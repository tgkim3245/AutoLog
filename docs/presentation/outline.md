# 실적 발표 구성 초안

발표를 새로 만들거나 개정할 때 아래 흐름을 사용한다. 실제 구현·검증 범위는 [현재 상태](../reference/implementation_status.md), 효과 수치는 [성과 기록](performance_notes.md)의 확인한 표본으로 설명한다.

| 장 | 전달할 내용 | 필요한 근거 |
| --- | --- | --- |
| 1. 업무 배경 | 자동차 VIL 검증에서 CAN·Ethernet 로그를 함께 취득하는 업무 | 실제 시험 연결도·업무 설명 |
| 2. 기존 문제 | 두 도구를 개별 조작하는 단계와 누락·발견 지연 사례 | 기존 작업 순서·실측 시간·사례 |
| 3. 개발 목표 | 통합 시작·정지, 취득 상태 확인, 이상 징후 표시 | 요구사항과 우선순위 |
| 4. 구현 구조 | 공통 패널, CANoe 연동, Ethernet 캡처, 감시·기록 모듈 | 최종 구조도·사용 버전 |
| 5. 동작 사례 | 정상 취득·부분 실패·이상 발생·복구가 화면에 나타나는 과정 | 구현 화면·로그·시연 |
| 6. 검증 결과 | 어떤 조건에서 확인했고 어떤 항목이 미지원·미검증인지 | 시나리오별 실제 검증 결과 |
| 7. 개선 효과 | 준비 시간·조작 수·유효 로그 쌍 확보·감지 지연의 변화 | 비교 가능한 실측 표본과 근거 |
| 8. 향후 과제 | 추가 장비·시험 프로필 지원, 배포·유지보수와 남은 제한 | 확인된 한계·후속 계획 |

프로젝트의 기여는 실제 구현·검증 범위로 설명한다. 원클릭 제어와 정확한 시각 동기화, 통신 이상 징후와 원인 확정, 가상 검증과 실제 장비 검증을 각각 구분한다.
