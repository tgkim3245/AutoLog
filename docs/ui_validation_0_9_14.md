# One Click Log 0.9.14 화면·유효성검사

2026-10-22 / 사용자 요청 반영.

- 메인의 통신 감시·기록 품질 버튼과 별도 창을 제거했다. 파일/수신 근거는 내부 진단과 버그리포트에 계속 남긴다.
- 기존 감시 기준은 설정의 네 번째 탭인 `zipy 유효성검사`에 넣었다. 규칙마다 최대 2,048자의 선택 팝업 안내를 저장하며 줄바꿈과 일반 텍스트를 지원한다. 빈 안내는 일반 오류 안내로 표시한다.
- 기본 규칙의 ID·수신 조건은 유지하고 이름을 `Zipy 활성화 실패`로 바꿨다. 기본 문구는 `Zipy 데이터 활성화에 실패하였습니다. Render 터미널에 아래의 커맨드를 입력하세요. |6 → e1`이다. 이전 기본 규칙은 새 필드가 없는 경우에만 안내를 추가해 사용자가 저장한 문구·기준·삭제 상태를 덮어쓰지 않는다.
- 위반 시 기존 전체 정상 정지·파일 검사/보관과 함께 구간별 한 번 팝업을 전달한다. 팝업은 HTML을 해석하지 않는 일반 텍스트이고 모달 대기를 하지 않는다. X 종료와 coordinator의 파일 정리가 계속 가능하다. 다른 Source도 계속 저장한다.
- 메인 상단 로깅 대상 줄에 로그 폴더를, 파일 영역의 같은 행에 작업 이력과 직전 로그 지우기를 붙였다. 버튼 아래 중복 단계 표시, 기본 이름 변경 설명, 하단 기능/종료 설명은 제거했다. 실제 파일 작업 결과와 오류 표시는 유지한다.
- 환경 확인 UI와 시작 전 팝업 가로채기를 제거했다. 설정에서 대상별 준비 오류를 확인한다. 내부 환경 기록/개발용 CLI 진단은 버그 분석을 위해 유지한다.
- 제품 이름과 EXE는 `One Click Log` / `One Click Log.exe`, 기본 prefix·개발자 로그·버그리포트의 파일 이름은 `One_Click_Log`를 사용한다. 기존 `AutoLog` 프로필은 새 프로필에 SQLite backup으로 한 번 복사한다. 기존 프로그램 실행 여부를 먼저 확인하고, 원래 DB/캡처와 사용자 지정 경로·이름·번호는 유지한다. 내부 Python 패키지·Git 저장소와 과거 파일의 식별 규약은 호환성을 유지한다.
- `assets/one_click_log.svg`와 16~256px 7개 크기의 ICO를 추가했다. ONE/CLICK/LOG 이름을 세 줄로 크게 배치하고 EXE 리소스와 실행 창에 함께 적용한다. `packaging/generate_icon.py`로 다시 생성한다.
- 공백이 포함된 새 배포 폴더에서 Wireshark MSI를 풀 때 속성값만 인용하도록 빌드 명령을 수정했다. 셸을 사용하지 않으며 드라이버/제품 설치 없이 관리 추출만 수행한다.

## 검증

소스 전체 619개 검사 통과(52.15초). 이후 EXE smoke가 실제 알림 큐로 팝업을 열어 문구·중복 방지·비모달·아이콘을 확인하고 팝업이 열린 상태에서 X 종료하도록 보강했으며 관련 21개 검사 통과. Ruff·의존성·diff 검사 통과. 메인 한·영·중 480/360px에서 가로 넘침 없음, 설정 탭·기본 안내·아이콘을 렌더링해 확인했다. 가이드는 데스크톱·모바일 14개 화면에서 검토했다.

실제 CANoe/차량/물리 케이블 분리는 이 변경에서 시험하지 않았다. 최종 배포 검증 결과는 이어서 기록한다.
