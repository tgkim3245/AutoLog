## 확인된 누락과 미해결 원인

A의 첫 CAN 프레임 기준 7.147042~7.185866초에 전체 프레임 공백 38.823ms가 있다. 같은 세션 CAN 파일과 대조하면 7.148221~7.185278초의 98개 ID·155프레임이 Diag 파일에 없다. 한 10ms 주기 메시지의 alive counter도 Diag에서는 181→186으로 건너뛰지만 CAN에는 중간 182·183·184·185가 연속으로 있다. 두 파일에서 관측된 수신/기록 경로의 차이는 확인됐으나, 물리 채널 매핑은 해당 세션의 XL 조회에서 확인하지 못했으므로 원인 층위는 확정하지 않는다.

비교는 CAN 1의 공통 ID와 겹치는 내부 구간(앞뒤 각 10ms 제외)을 사용했다. 동일 메시지로 두 파일 timestamp 차이 약 0.092745ms를 보정하고 ID·표준/확장·FD 형식·정확한 payload가 2ms 이내에 대응하는지 확인했다. 방향은 각 CANoe 관점이 달라 제외했다. A에서 기준 CAN 프레임 91,619개를 대조했고 미대응 155개가 위 한 구간에 모였다. B는 기준 63,652개를 대조해 미대응 0개다.

두 세션의 앱 이력은 completed이고 오류/정지 이벤트 없이 정상 보관했다. 원인이 CANoe/CAPL/DLL의 처리·드라이버·기록 경로 중 어디인지는 아직 확정하지 못했다. **미해결: 첫 표본의 Diag 수신/기록 누락 원인을 분리하고 재현해야 한다.** 이 분석만으로 One Click Log의 파일 복사나 버튼 제어가 원인이라고 단정하거나, 프로그램 수정 완료로 처리하지 않는다. 실제 진단 왕복 확인과 CAN 전체 무손실 검증을 구분한다.
