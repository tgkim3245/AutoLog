# 초기설정: 설치된 CANoe 버전 선택과 Npcap 설치

기준 SW 1.0.1 · 작성 2026-10-26

배포 EXE 옆 [Initial_Setup.bat](../../tools/Initial_Setup.bat)는 Windows 기본 PowerShell로 설치된 CANoe 버전을 검색하고 사용자 선택 후 기본 COM 등록과 Npcap 관리자 설치를 진행한다. CANoe 19나 최신 버전을 자동 선택하지 않는다. RBS 구성(.cfg)의 작성·검증 버전에 맞는 CANoe·라이선스·Vector 드라이버와 프로젝트 전체를 먼저 준비한다.

1. ZIP 전체를 로컬 폴더에 푼다. 저장할 기록은 정지·보관을 완료하고 앱과 모든 CANoe 작업을 저장·종료한다.
2. BAT를 더블클릭한다. Program Files와 Vector 설치 등록·설치 프로그램 등록 위치, 현재 COM 경로에서 64비트 CANoe 실행 파일을 검색한다. 버전·경로·현재 COM 대상·등록 도구 존재·서명 확인 결과를 표시한다. 알려진 설치 위치 밖의 미등록 복사본은 검색되지 않을 수 있다.
3. 사용할 설치본의 **목록 번호**를 입력한다. 하나만 발견돼도 입력을 받는다. 버전 숫자(예: 19)를 대신 넣으면 목록 범위를 확인하고 다시 묻는다. 빈 입력 또는 Q는 CANoe 등록 취소이며 Npcap 단계는 별도로 확인한다.
4. 선택한 실행 파일과 같은 폴더의 RegisterComponents.exe에 대한 Vector 서명, 선택 버전이 바뀌지 않았는지 확인한다. 도구가 없거나 서명/버전이 확인되지 않으면 다른 설치본으로 대체하지 않는다. 공식 도구의 관리자 권한 요청을 승인하고 완료 후 64비트 COM 대상의 경로·전체 버전이 선택한 설치본과 일치하는지 확인한다.
5. Npcap 드라이버와 두 DLL이 있으면 설치를 건너뛴다. 없으면 installers/Npcap/npcap-1.90.exe의 고정 크기·SHA256·Nmap 서명을 검사하고 관리자 실행한다. 공식 라이선스·옵션은 사용자가 확인한다. 재부팅 요청 시 먼저 재부팅하고 BAT를 다시 실행해 확인한다. 설치기는 확인된 회사 내부 PC 1대용 배포에만 동봉한다.
6. 사용할 기능의 결과(CAN·Diag: CANoe: 0, Zipy: Npcap: 0)를 확인하고 앱을 다시 실행해 RBS 구성(.cfg)·NIC·연결·F9/Trace·짧은 기록을 확인한다. 등록 성공은 RBS 호환·라이선스·측정·실차 취득 성공과 별개다.

## RBS 열기 실패 시 다시 설정

기본 COM 대상과 RBS 버전이 다르면 열기가 실패할 수 있다. 먼저 RBS 작성/검증 버전을 확인하고 위 순서를 다시 진행해 알맞은 설치본을 선택한다. 배포 가이드 하단 **초기설정 다시 하기**는 위 0단계 절차로 이동하는 링크다. 앱/CANoe 종료 후 EXE 옆 BAT를 더블클릭한다. 다른 COM 자동화에도 기본 대상 변경이 적용되며, CAN·Diag 두 구성은 선택한 버전과 모두 호환돼야 한다.

계속 실패하면 cfg 경로·참조 파일·컴파일·버스 옵션·라이선스를 확인하고 선택 버전/경로·기대 RBS 버전·시각·버그리포트를 남긴다. BAT는 원본 cfg/can.ini를 수정하거나 프로세스를 강제 종료하지 않는다.

## 검색 전용과 검증 범위

```powershell
.\Initial_Setup.bat --check
```

검색·검증만 수행하고 번호 입력·설치·등록은 실행하지 않는다. 로그는 `%TEMP%\OneClickLog-InitialSetup`에 두며 Git에 넣지 않는다. 개발 PC의 실제 읽기 전용 검색과 시스템 동작을 대체한 등록 검사, 생성 설치 폴더의 검색/중복/도구 누락·버전 선택·취소·실패 회귀 검사를 구분한다. 버전별 RBS·장비·실차 성공은 별도로 검증한다. [시험 PC 준비](test_pc_setup.md)를 따른다.
