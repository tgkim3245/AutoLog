# CAPL 컴파일의 CBF 쓰기 오류

기준 SW 0.9.22 · 검토 2026-10-25

CANoe가 `.can`을 컴파일한 `.cbf`를 프로젝트 폴더에 쓰지 못하는 오류는 앱의 BLF 시작 제어와 구분한다. [2026-10-20 사례](../analysis/capl_write_denial_2026_10_20.md)는 Defender 이벤트와 실제 오류 경로가 일치해 원인을 확인한 기록이며 모든 액세스 거부의 원인을 동일하게 단정하지 않는다.

## 확인과 조치

1. CANoe Write의 오류 원문·시각과 해당 출력 폴더를 확인한다. 존재·읽기 전용·쓰기 권한·사용 중 파일을 구분한다.
2. Windows 보안에서 차단된 앱이 실제 Vector `CAPLcompExec.exe`·`CANoe64.exe`와 해당 오류에 대응하는지 확인한다. 회사 정책으로 변경이 불가하면 관리자에게 정확한 앱·경로를 전달한다.
3. 실제 차단이 확인됐을 때 공식 사용자 가이드의 **제어된 폴더 액세스를 통해 앱 허용** 절차를 따른다. 보호 기능 전체를 끄지 않는다. 설치 버전의 실제 Vector 실행 파일을 지정한다.
4. 사용자 작업을 저장하고 CANoe를 다시 열어 재컴파일·라이선스·F9·Trace와 수동 기록을 확인한다. 이후 앱의 새 구간 기록을 수행한다.

CANoe 19 기본 설치 경로 예시는 `C:\Program Files\Vector CANoe 19\Exec64\CAPLcompExec.exe`와 같은 폴더의 `CANoe64.exe`다. 사용자 설치 위치가 다르면 실제 공식 파일을 사용한다. 업무 cfg/CBF·보안 이벤트 원본·개인 SID·전체 업무 경로는 Git에 넣지 않는다.

자동으로 보안 정책·원본 cfg·CAPL을 바꾸지 않는다. 오류가 계속되면 [진단 제출](diagnostics.md)에 따라 Write·시각·TC 결과와 ZIP을 보존한다. 라이선스 옵션 누락이나 COM 등록 문제는 [시험 PC 준비](test_pc_setup.md)의 해당 원인과 구분한다.
