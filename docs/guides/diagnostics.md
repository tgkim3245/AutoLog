# 버그리포트와 이력 보관

기준 SW 0.9.22 · 코드/기존 표본 검토 2026-10-25

진단 JSONL, 내보낸 ZIP, 캡처 원본, 설정/이력 DB는 다른 저장물이다. ZIP에 모든 시험 자료가 자동 포함되는 것으로 해석하지 않는다.

## 자동 진단과 재실행

배포 앱은 시작 때 진단을 켜고 EXE 옆 `developer_logs/One_Click_Log_developer.jsonl`에 추가한다. 회전 기준은 파일당 5 MiB, 현재 파일과 백업 .1~.4로 약 25 MiB다. .1이 가장 최근 백업이다. 레코드 단위 회전이라 엄격한 디스크 할당 상한은 아니다.

같은 실행 폴더에서 껐다 켜면 같은 파일 집합에 이어 쓰며 오래된 내용부터 교체한다. 날짜 기준 정리는 아니므로 보관 시간·일수는 보장하지 않는다. 새 EXE 폴더에서는 새 로그 집합을 사용하며 이전 폴더를 자동 합치지 않는다. 소스 실행 기본은 저장소 루트, 소스의 명시적 --data-dir/smoke는 시험 데이터 아래에 분리하며 배포 EXE는 EXE 위치가 우선이다.

정상 진단 close는 큐를 비우고 flush한다. X guard 강제 종료·앱 비정상 종료·전원 차단에서는 끝부분 기록이 빠질 수 있다. 진단 큐는 최대 4096건이며 큐/저장 실패를 진단 건강 상태와 화면에 알리려 하지만 누락된 내용을 복원하는 것은 아니다. 진단 오류만으로 실제 취득을 중단하지 않는다.

## 실사용 시간으로 보는 용량

10월 22~23일에 생성된 0.9.12·0.9.16의 짧은 실사용 리포트에서 기록 중 구간을 분리해 원본 JSONL 증가량을 계산했다. 활성 구간 합계는 각각 약 80초와 85초이며, 약 1.46 MiB/분·1.92 MiB/분 수준이다. 25 MiB를 같은 속도로 계속 쓰면 약 17분·13분에 해당한다.

따라서 이전 표본을 참고한 운영 추정은 연속 기록 약 10~20분, 시작·정지 처리를 매우 자주 반복하면 더 짧은 시간이다. 대기 시간을 포함한 실행시간으로 나누면 보관 시간을 과대평가한다. 이 값은 **현재 0.9.21의 장시간 실측이나 보장값이 아니다.** 대상 조합·상태/응답 크기·반복 조작·오류에 따라 달라진다. 원본 리포트와 개인 경로는 Git에 보관하지 않는다.

30분~1시간 시험의 전체 진단을 마지막 ZIP 하나로 보존한다고 기대하지 않는다. 오류 직후와 필요 구간 경계에서 내보내고 실제 버전의 장시간 시험으로 별도 측정한다.

## ZIP 생성과 전달

버그리포트 버튼은 Windows가 알려주는 바탕화면에 고유 이름의 ZIP을 만든다. OneDrive 등으로 바탕화면이 이동됐다면 그 위치를 따른다. 버튼은 이미 대기 중인 로그를 flush하고 회전을 잠시 고정해 현재 파일·존재하는 백업·manifest를 임시 ZIP에 복사한다. ZIP CRC와 각 파일의 크기/SHA256을 검증한 후 최종 이름을 확정한다.

이 ZIP은 생성 시점의 고정 사본이다. 이후 사건은 원본 JSONL에만 추가된다. 압축률 때문에 ZIP 크기로 보관량을 환산하지 않는다. 앱은 내보낸 ZIP을 자동 삭제하거나 수량/기간을 제한하지 않으며 자동 이메일 전송도 하지 않는다.

오류 직후 다음 자료를 함께 보존한다.

- TC 번호·회차·발생 시각과 시간대·선택 대상·prefix/번호·누른 순서·기대/실제 결과.
- 발생 직후 ZIP. 재실행이 필요하면 가능한 종료 전 ZIP과 재실행 직후 ZIP을 따로 남긴다.
- 해당 BLF·PCAP/PCAPNG와 CANoe Write/화면. 누락 분석에는 매핑·조작 시각·비교 기준도 필요하다.

[입력형 시험서](../testing/One_Click_Log_Vehicle_Test_Plan.html)는 결과 JSON으로 저장하고 ZIP/원본과 별도 전달한다. JSON에는 증빙 이름이 들어가며 증빙 파일이 자동 첨부되지는 않는다. 앱이 응답하지 않아 내보낼 수 없으면 해당 실행 폴더 developer_logs의 사본을 보존한다. 미완료 캡처를 살리려면 X 전에 현재 보관/재시도 상태를 확인한다.

ZIP에는 캡처·cfg 전체·DB·화면·Windows dump를 자동 첨부하지 않는다. UTC·버전·PID/스레드·명령·상태·경로·오류·traceback 같은 운영 정보를 남기고 지정 payload/바이트 필드를 가린다. 일반 문자열·경로를 완전히 익명화하지는 않으므로 승인된 자료 공유 범위에 맞춰 전달한다.

## 설정과 DB 아카이브

기본 DB는 `%LOCALAPPDATA%\One Click Log\state.sqlite3`다. 앱 시작 때 기본 90일·이벤트 10000건·완료 세션/완료 작업 각 1000건 기준으로 정리 후보를 고른다. 최근 이벤트 500건과 완료 이력 각 100건, 미완료·실패·진행 중·보호 파일 작업 관련 이력은 보존한다.

후보를 같은 프로필 `history_archive`의 jsonl.gz로 내보내고 재읽기/해시 검증 후 DB에서 정리한다. 내보내기 실패는 원본 DB를 유지한다. 이 과정은 캡처 파일·다음 번호를 삭제/초기화하지 않으며 진단 JSONL 순환과 별개다. DB와 이 아카이브도 ZIP에 자동 포함되지 않는다.
