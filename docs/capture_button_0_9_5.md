# AutoLog 0.9.5 — 메인 기록 버튼 상태 표시

2026-10-21. 고정 `logging` 문구를 현재 작업과 클릭 동작으로 바꿨다. 한·영·중 모두 적용하며 모의 실행은 명시한다.

| 상태 | 표시 / 색 | 클릭 |
| --- | --- | --- |
| 앱 초기화·환경 확인·CANoe 연결 확인 | 해당 작업명 + 회전 표시 / 회색·청회색 | 불가 |
| 대기 | 기록 시작 / 파랑 | 기존 준비 검사 후 시작 |
| 준비·시작 | 준비 중 · 취소 / 시작 중 · 취소 / 주황 | 취소 요청 1회 |
| 취소 접수 | 취소 처리 중 / 회전 표시 | 불가, 정리 완료 대기 |
| 기록·부분 실패 | 기록 중 · 정지 / 빨강, 일부 기록 중 · 정지 / 주황 | 현재 기록 정지 |
| 정지·검사·보관 | 단계·대상명 + 회전 표시 / 청회색 | 불가 |
| 완료 | 다음 기록 시작 / 초록 | 새 번호로 시작 |
| 실패 | 다시 시도 / 주황 | 기존 검사를 거쳐 시작 |
| 미완료 | 미완료 기록 확인 / 주황 | 복구 정보가 있으면 기존 복구 창 열기 |
| 파일 작업·종료 | 파일 처리 중 / 종료 준비 중 | 불가 |
| 대상 없음·초기화 실패 | 대상을 선택하세요 / 초기화 실패 | 불가 |

기록 중 정지는 백그라운드 진단보다 우선한다. 시작·정지 클릭은 UI에서 즉시 접수 상태를 표시하고 애플리케이션이 동기적으로 현재 phase를 반영해 중복 요청을 막는다. 취소 요청은 PREPARING→STARTING 중에도 한 번만 보낸다. 종료 중에는 후속 phase 알림이 와도 버튼을 다시 활성화하지 않는다.

실제 `_stop_real`의 검사·보관 시작 위치에서 `capture_step`을 발행한다. 시간으로 가짜 진행률을 만들지 않는다. 초기화가 실제로 완료된 뒤 `_ready`를 세우고 앱의 초기화 Future 완료를 확인해 로딩 표시를 끝낸다. 복구는 기존 수동 확인/정지 재시도 절차를 이용하며 미완료를 성공으로 승격하지 않는다.

회전 아이콘은 버튼이 보이고 처리 중일 때만 갱신한다. 작은 버튼은 글자 크기를 줄이고 색 외에 문구·툴팁·접근성 이름을 제공한다. 변경된 상태와 클릭 가능 여부는 개발자로그에 남긴다.

검사 범위: 단계별 문구·클릭 차단, 취소 중복/phase 경합, 백그라운드 진단 중 정지 우선, 파일 검사→저장 메시지, 종료 표시 유지, 복구 경로, 언어 변경·숨김 시 회전 중단. 실제 앱 버튼으로 모의 시작→취소→재시도→기록→정지→다음 기록→X 종료를 확인한다. CANoe 장비의 실제 기록 검증 범위는 0.9.4와 동일하게 현장 재시험 대기다.

소스 전체 검사 **515개(50.46초)**, Ruff·의존성·diff 검사를 통과했다. 실제 Qt 버튼의 14개 상태와 360px 폭 영어·중국어 화면을 렌더링해 글자·버튼 영역을 확인했다. 오프스크린 Qt에는 Windows 글꼴을 명시적으로 등록했으며 일반 앱의 글꼴 설정은 바꾸지 않았다. 가이드 개정 2026-10-21.2를 8개 뷰포트로 렌더링해 상태 표와 시작/정지 안내를 확인했다. 로컬 화면 근거는 빌드 저장소의 `ui-0.9.5/`와 `user-guide-2026-10-21.2/visual-qa/`에 보관한다.
