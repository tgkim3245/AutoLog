# 현재 요구사항

기준 SW 1.0.1 · 검토 2026-10-26

기존 요구사항 ID 55개를 유지하고 현재 구현과 미지원 항목을 명시한다. 구현됨은 실제 차량의 모든 장비 조합에서 통과했다는 뜻이 아니다. 시험 절차는 [48 TC](../testing/vehicle_test_plan.md), 실제 근거는 [환경별 검증표](../testing/canoe_support_matrix.md)를 따른다. 초기 요구/검토는 [과거 계획](../archive/README.md)에 보존한다.

## 화면과 연결

| ID | 현재 요구와 동작 | 확인 기준 |
| --- | --- | --- |
| UI-01 | 약 480px 폭의 작은 메인과 화면 높이에 맞는 스크롤을 제공한다. | 작은 화면·DPI에서 조작 접근과 문구 확인 |
| UI-02 | 현재·다음·직전 파일 제목과 보관 상태를 표시한다. | 선택 파일·확장자·실제 상태 대응 |
| UI-03 | 한국어·영어·중국어 간체를 순환 선택하고 기억한다. | 설정·알림·보조 창에 적용, 외부 원문은 보존 |
| UI-04 | CAN·Diag·Zipy의 참여 선택과 연결 상태를 카드에 표시한다. | 선택과 연결 준비를 구분 |
| UI-05 | 톱니바퀴에서 저장·CAN/Diag·Ethernet·Zipy 규칙을 설정한다. | 기록 처리 중 관련 설정 잠금 |
| UI-06 | 작업 이력·로그 폴더를 제공한다. 패킷 보기·별도 기록 품질 창·환경 확인 창은 제공하지 않는다. | 이력은 읽기 전용, 폴더는 지정 캡처 위치 |
| CFG-01 | 역할별 cfg 경로와 BLF 블록을 선택·검증한다. | 실제 cfg·블록과 의존 오류 확인 |
| CFG-02 | 선택 cfg를 앱 전용 CANoe로 열고 그 대상만 제어한다. | 임의의 기존 사용자 CANoe에 접속하지 않음 |
| CFG-03 | 사용자는 CANoe 화면에서 설정을 직접 편집·저장할 수 있다. | CANoe의 권한·측정 제한을 따름 |
| CFG-04 | 실제 cfg·블록·측정·기록 상태를 재조회한다. | 구조/출력 외부 변경과 확인 불가 구분 |
| CFG-05 | 이번 구간의 출력 경로·이름만 관리하고 복구를 시도한다. | 원본 cfg 자동 저장/재로드 없음, 복구 보류와 보관 실패 구분 |
| CFG-06 | 동일 카드 재연결 중복 실행과 서로 같은 cfg의 동시 취득을 막는다. | 다른 구성으로 교체 전 측정/기록 정지 |
| CFG-07 | 원본 cfg·CAPL·시스템 변수 정의를 자동 수정하지 않는다. | 사용자 편집·저장은 별도, 독립 COM can.ini 준비는 별도 안내 |
| CONN-01 | Zipy 연결 확인은 도구 버전·NIC 목록·선택 식별자 준비를 확인한다. | 실제 NIC 열기·취득 성공은 시작 시 별도 확인 |
| CONN-02 | NIC 하나를 안정 식별자로 선택·기억한다. | 사라진 NIC를 다른 항목으로 자동 대체하지 않음 |

## 기록과 이상 처리

| ID | 현재 요구와 동작 | 확인 기준 |
| --- | --- | --- |
| CAP-01 | 공통 버튼은 상태별 기록 시작·정지·취소·확인 문구로 동작한다. | 준비 부족 시 회색 설정 안내, F9 대기는 주황색, 준비 후 녹색 |
| CAP-02 | CAN·Diag 한 개 또는 두 개와 선택 Zipy를 같은 세션으로 제어한다. | 7가지 비어 있지 않은 조합, 정확한 동시 시각 보장은 아님 |
| CAP-03 | Zipy는 선택했을 때만 캡처한다. | 선택하지 않은 대상에 기록 명령·파일 생성 없음 |
| CAP-04 | 선택 대상의 준비·저장 검사를 모두 통과한 뒤 시작한다. | 기존 파일·다른 블록·진행 중 수동 기록 보호 |
| CAP-05 | 메인 정지는 구간 기록만 끝내며 CANoe 측정·다른 블록을 유지한다. | BLF 완결·안정된 완전 복사본과 핸들 보유 구분 |
| CAP-06 | 시작 단계 실패·취소는 이번에 시작한 구간만 정리한다. | 예약 번호 유지, 정지·보관 미확인은 성공 처리 금지 |
| CAP-07 | 기록 중 한 대상 오류가 확인되면 선택한 전체 기록을 정지한다. | 실패 원인 유지·닫힌 파일별 보관·같은 세션 자동 재시작 없음 |
| FORMAT-01 | Zipy pcap 기본·pcapng 선택을 지원한다. | 실제 형식과 확장자 일치, 기존 파일 형식 유지 |
| STATE-01 | 역할별 연결·측정·기록·관측 상태를 구분해 표시한다. | 프로세스 생존을 수신 정상으로 대체하지 않음 |
| STATE-02 | 세션 결과와 개별 파일 결과를 따로 보존한다. | 전체 완료로 개별 누락/실패를 가리지 않음 |
| ALERT-01 | CAN·Diag 신호 미수신 감시는 요구로 남아 있으나 현재 미지원이다. | Trace·원본과 별도 기준 필요, 자동 경고 없음이 정상 수신 증거는 아님 |
| ALERT-02 | Zipy의 지정 흐름 미수신·지속 저수신을 검사한다. | 저장된 유예·미수신·최소 pps 기준, 기본 2초/2초/100pps |
| ALERT-03 | 규칙의 Source IP/MAC·접두사 등 조건으로 필요한 수신 흐름을 확인한다. | 선택 조건과 기대 Source 비교 지원 조건을 실제 규칙으로 확인 |
| ALERT-04 | 수신 위반·관측 불가·미지원·미설정을 구분한다. | Zipy 관측 확인 불가 5초 지속 시 전체 정지 |
| ALERT-05 | 조회 가능한 로컬 장비 채널 기준을 저장·대조한다. | 불일치 또는 저장한 기준 확인 불가 시 시작 차단, 기준 없을 때 미확인을 정상 매핑으로 단정하지 않음 |
| ALERT-06 | 최근 활동 500건과 오류/경고 필터·상세를 제공한다. | 고정 높이와 내부 스크롤, 복사/건수 버튼은 없음 |
| ALERT-07 | 수신 감시는 선택한 대상의 실제 로깅 중에만 적용한다. | 전후·미선택은 미감시, 도구/파일 오류 감시는 별도 |
| ALERT-08 | Zipy 규칙은 원본 저장 범위를 제한하지 않는다. | 다른 Source도 저장, 한 번 확인한 위반은 복구돼도 해당 구간 정지 사유로 유지 |

## 번호와 파일

| ID | 현재 요구와 동작 | 확인 기준 |
| --- | --- | --- |
| NAME-01 | prefix와 다음 인덱스를 명시 적용한다. | 기본 One_Click_Log, 정확한 십진 정수·이름 길이 검증 |
| NAME-02 | 세션 예약 때 번호와 다음 번호를 영구 보관한다. | 모든 선택 파일은 같은 번호, 실패 예약 번호 재사용 없음 |
| NAME-03 | 설정 적용과 시작 직전 최종 이름 충돌을 검사한다. | 기존 파일 덮어쓰기 없음 |
| NAME-04 | 정지 상태에서 다음 인덱스를 수정할 수 있다. | 기존 파일/이력 충돌을 허용하는 우회는 아님 |
| PATH-01 | 사용자가 지정한 공통 로컬 저장 폴더를 기억한다. | 쓰기·경로·남은 공간 확인, 고유 작업 폴더와 최종본 구분 |
| FILE-01 | 직전 완료 로그 삭제를 확인받고 수행한다. | 기록/확인 불가 중 차단, 파일별 결과 유지 |
| FILE-02 | 직전 완료 세션의 제목을 버튼 또는 Enter로 바꾼다. | 확장자·Diag 구분 유지, 임의 재번호화 없음 |
| FILE-03 | 이름 변경·삭제로 다음 번호를 바꾸지 않는다. | 전후 설정·DB 확인 |
| FILE-04 | 파일 제목·작업 이력·직전 로그 지우기를 메인 같은 행에 둔다. | 작업 이력은 읽기 전용, 과거 전체 파일 관리 UI와 구분 |
| FILE-05 | 파일 작업 의도·부분 결과·실제 경로를 보존한다. | 충돌/외부 변경/잠금에서 강제 해제·다른 앱 종료 없음 |
| STORE-01 | 외부 시작 전에 세션·대상·출력 경로·예약 번호를 트랜잭션으로 저장한다. | 영구 저장 실패 시 시작 금지, 사용자 세션 중복 앱 제한 |
| STORE-02 | 작업 파일과 보관본을 나누고 정상 정지 후 검사·보관한다. | 현재 실행 재시도 가능, X/재실행 중단 구간은 폐기 |
| APP-01 | 메인 X는 이번 실행의 앱·전용 도구·전용 CANoe를 종료한다. | 약 1초 guard·반복 X, 원본 cfg 무저장·무관한 프로그램 유지 |
| APP-02 | 재실행은 이전 미완료 소유 구간을 정리하고 새 기록을 허용한다. | 완료/외부 파일·설정·다음 번호 유지, 잠김 소유 파일 정리 재시도 |

## 실행과 배포

| ID | 현재 요구와 동작 | 확인 기준 |
| --- | --- | --- |
| ENV-01 | Windows 11 x64 데스크톱을 지원 기준으로 한다. | 새 PC·실제 장비/도구 조합은 별도 확인 |
| NET-01 | 앱 기록·설정·가이드는 인터넷 없이 사용한다. | 실행 중 다운로드·로그인·텔레메트리 없음, CANoe 라이선스 준비는 별도 |
| DEPLOY-01 | 앱 런타임·Wireshark CLI·문서·라이선스를 포함한 폴더로 배포한다. | EXE만 복사하지 않음. Npcap은 초기설정 BAT가 설치/기설치 확인, 사용자 권한 승인·동의 필요 |
| DEPLOY-02 | 버전·소스·도구·해시·문서 개정을 대응시킨다. | build_info와 ZIP 대조, 가이드 불일치 빌드 차단 |
| PERF-01 | 대표 부하·60분·1 GiB 초과를 별도 실증한다. | localhost 결과와 차량 성능 분리, 현재 실차 미검증 범위 명시 |
| CONF-01 | 공통 배포물과 PC별 설정·번호·캡처·진단을 분리한다. | 사용자 프로필 DB와 EXE별 진단 위치 구분 |
| MAINT-01 | 프로필 이행·업데이트에서 완료 원본·번호를 보존한다. | 원본 백업과 검증, 과거 번호 되살리기/미완료 성공 승격 금지 |
| DEV-01 | 진단을 상시 순환 기록하고 버튼으로 ZIP 스냅샷을 내보낸다. | 약 5 MiB×5, 같은 위치 재실행 이어 쓰기, 수량 제한 없는 별도 ZIP·무전송·실제 원본 자동 미첨부 |

기본 Zipy 기준과 제어 제한, 경로 복구·완결 순서는 [제어 정책](control_policy.md), 사용자 흐름은 [공식 가이드](../../user_guide/README.md)를 기준으로 함께 유지한다.
