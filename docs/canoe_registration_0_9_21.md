# CANoe 등록 복구 진단 — 0.9.21

다른 CANoe 버전을 설치·제거한 뒤 연결 확인이 즉시 실패한 보고를 분석했다. 실패 위치는 cfg 열기 전 `CANoe.Application\CLSID` 조회이며 Windows 오류 2가 발생했다. 당시 앱은 이를 `setup_failed`로 묶어 빈 설정 파일 경로를 표시했다. 채널 매핑·라이선스·로깅 블록 검사는 아직 실행되지 않은 상태였다.

해당 PC에서 CANoe 15와 19 설치가 남아 있었지만 CANoe.Application 등록은 32/64비트 조회 모두 없었다. CANoe 17 제거가 등록을 해제했을 가능성은 사용자 설명 및 관측과 부합하지만 제거 과정을 직접 추적한 것은 아니다. Vector 서명이 유효한 CANoe 19 `Exec64/RegisterComponents.exe`를 관리자 권한으로 실행해 등록을 복구했다. 사용한 절차는 CANoe 19 설치 폴더의 Vector 공식 문서 `Doc/AN-AND-1-117_CANalyzer_CANoe_as_a_COM_server.pdf` 1.4절에 따른다.

복구 후 등록 대상과 can.ini가 CANoe 19로 일치했고 SingleCOMClient=1을 확인했다. 실제 앱의 생성 경로로 CANoe 19 SP3 /pro COM 창 두 개를 각각 독립 프로세스로 실행하고, 이번 시험에서 만든 창만 Quit으로 닫았다. 사용자 cfg를 열거나 측정·차량 기록을 시작하지 않았다. 실제 라이선스 장비를 이용한 기록 성공과 구분한다.

변경 내용:

- COM ProgID/클래스/서버 명령/실행 파일 누락·손상을 `com_registration_missing` 또는 `com_registration_invalid`로 구분한다. 레지스트리 권한 오류는 기존 설정 접근 오류와 구분해 잘못된 누락 판정을 피한다.
- 사용자 오류 카드에 세 언어로 공식 등록 도구 관리자 실행·버전 선택·재연결 절차를 안내하고 발견한 공식 도구 경로를 표시한다. COM 등록을 앱이 자동 변경하거나 다른 버전으로 임의 연결하지 않는다.
- 레지스트리 키·등록 명령·제거된 실행 파일·복구 도구 후보를 개발자로그/워커 결과에 남긴다. CANoe 인스턴스가 생기기 전 실패한 경우 불필요한 NoneType 관찰 오류를 남기지 않는다.
- 세 언어 사용자 가이드와 배포 안내에 등록 복구를 추가했다. 기존 독립 창 확인·원본 cfg 무저장·측정 수동 제어 정책은 유지한다.

실제 보고서·업무 cfg·개인 경로는 저장소에 포함하지 않는다. 도구 후보 탐색은 기존 환경 진단의 알려진 설치 경로 범위를 사용하며, 사용자 지정 설치 위치에서는 가이드에 따라 실제 설치 폴더를 확인한다.

## 자동 검증

소스 전체 711개 검사 통과(75.22초). 누락/빈/손상 CLSID, 서버 키 누락, 제거된 실행 파일, 잘못된 명령, 권한 오류와 미생성 인스턴스 오류 증거를 확인했다. 새 Runtime 안내는 한국어·영어·중국어 필드와 실제 복구 도구 경로를 보존한다. Ruff, pip check, git diff --check 통과. 오프라인 가이드의 언어 전환·확대·기억·등록 복구 상세 링크 자동 펼침을 1100/360px 38개 화면으로 검사했다. 실제 보고서나 cfg는 저장소에 넣지 않았다.

배포 ID `One Click Log-0.9.21_20261023_195933`, 소스 `85040279512a518f9935ae88182b5811474eb148`(변경 없음)으로 EXE/ZIP 빌드를 완료했다. ZIP CRC/SHA256·EXE 버전/의존 모듈·문서 폴더/ZIP/추출본 해시가 일치했다. ZIP 추출 EXE의 실제 앱 바이트코드를 사용한 관련 366개 검사 통과(18.55초), 별도 실제 EXE 모의 시작/정지/팝업·사용법·X 종료 검사 통과. 세 언어 등록 오류 카드도 가로 넘침 없이 렌더링했다. 실제 CANoe COM 실행 시험과 이 모의 취득 검증은 구분하며 새 차량 측정은 하지 않았다.
