# 6단계 — 미완료 기록 수동 복구 (0.6.0)

2026-10-18 · CANoe 측정 라이선스를 기다리는 동안 구현 계획 IMP-10의 장비 없는 복구 작업을 진행했다. 0.5.1의 독립 연결·출력 옵션 복구는 유지한다. 실제 CAN/Diag 구간 기록과 통신 감시의 완료를 뜻하지 않는다.

## 사용자 동작

1. 비정상 종료한 기록이 있으면 메인에 **미완료 확인 N건**이 표시된다. **파일 관리 → 미완료 기록 복구**에서도 열 수 있다.
2. 번호·대상·파일별 상태, 임시/최종 전체 경로, 존재·크기와 이전 오류를 확인한다. **파일 상태 다시 확인**은 중단된 이름 변경·보관 작업의 경로와 파일 식별 정보를 대조한다. 파일을 다시 이동하거나 삭제하지 않는다.
3. 관련 CANoe 기록블록과 TShark 기록이 끝났는지 사용자가 직접 확인하고 체크한다. CANoe 측정 자체는 유지할 수 있다. AutoLog가 이전 CANoe 창에 재접속하거나 측정을 제어하지 않는다.
4. **검사 후 보관**은 등록된 작업 파일만 전체 구조 검사한 뒤 예약된 최종 경로에 보관한다. BLF는 기존 스트리밍 판독기, PCAP/PCAPNG는 Wireshark의 capinfos를 사용한다. 0패킷도 구조가 유효하면 보관할 수 있다. 기존 목적지는 교체하지 않는다.
5. 필요한 파일을 보관한 뒤 **파일 유지하고 미완료 정리**를 누른다. 해당 세션을 실패 이력으로 남기고 파일·소비한 번호를 유지한다. 다른 미완료 세션이 남아 있으면 새 기록은 계속 차단한다. 사용 중인 파일은 정리하지 않는다.
6. 삭제 등 중단된 파일 작업의 결과를 입증할 수 없으면 **결과 미확인으로 정리**한다. 현재 경로의 파일을 보존하고 미확인 상태를 남기며, 삭제 성공이나 관리 가능한 캡처로 승격하지 않는다.

현재 앱이 시작한 기록의 정지가 미확인이면 **현재 기록 정지 재시도**만 허용한다. 사용자의 체크만으로 살아 있는 worker의 기록 상태를 덮어쓰지 않는다. 복구 작업 중에는 새 기록과 다른 파일 작업을 막으며 UI는 응답을 유지한다.

## 데이터 보호와 진단

- 복구 화면이 확인한 세션·작업·파일 식별 정보가 바뀌면 요청을 거부하고 새로 확인하게 한다. 링크·정션·다중 하드링크, 배타 접근 실패, 검사 도중 변경, 형식 불일치와 손상은 보관하지 않는다.
- 이동 전 의도를 DB에 저장하고, 검사한 파일과 같은 식별 정보의 Windows 배타 핸들로 교체 없는 이동을 수행한다. 이동 후 결과 저장이 중단되면 기존 작업 저널이 정확한 파일 식별 정보로 회수한다. 기존 정상 보관 직후 DB 갱신이 끊긴 경우에도 저장했던 검사 정보와 일치할 때만 경로를 회수한다.
- 남은 파일은 자동 삭제하지 않는다. 보관을 마쳐 비어 있는 `.vil_work/<세션>/`와 `.vil_work/`만 제거한다. 미완료 정리는 원래 예약 경로와 확인 근거를 DB에 남긴다. DB 스키마는 기존 2를 유지한다.
- 복구 요청·검사 시작·구조 검사 결과·실제 경로·작업 ID·사용자 확인·실패 traceback을 기존 상시 개발자로그와 버그리포트에 남긴다. 차량 payload는 추가로 저장하지 않는다.
- 구조 검사와 사용자 종료 확인은 취득의 무손실·기대 채널/데이터 수신·정상 종료를 증명하지 않는다. 복구 세션은 보관 파일이 있어도 실패 이력으로 유지한다.

## 검증

- 장비 없는 기본 검사 **296개**, Ruff 정적 검사를 통과했다. 새 복구 검사 24개에는 손상·열린 파일·늦은 목적지 충돌·확인 후 파일 변경·DB 의도/결과 실패·재실행 경로 회수·100개 이전 이력·복수 미완료와 동시 시작 차단·현재 기록 보호·체크 기본 해제·한/영 UI가 포함된다.
- 소스의 `--verify-recovery`에서 생성한 0객체 BLF, 0패킷 PCAP/PCAPNG의 DB 재실행·배타 접근 보호·전체 읽기·보관·빈 폴더 정리·번호 유지 3건을 통과했다. CANoe와 실제 NIC는 열지 않았다.
- 한국어·영어 복구 화면, 최소 780×580 화면과 메인 알림 배치를 확인했다. offscreen 이미지 확인에는 Windows 설치 글꼴을 명시적으로 로드했다.
- 빌드·배포본 검증 결과와 경로는 이 문서에 추가한다. 실제 차량 장애 복구와 라이선스 활성화 후 CAN/Diag 취득 시험은 남아 있다.

배포본의 장비 없는 복구 검사는 새 폴더를 지정하여 실행한다. PCAP 판독에는 설치된 Wireshark의 capinfos가 필요하다.

```powershell
.\AutoLog.exe --verify-recovery --data-dir "C:\Temp\AutoLog-recovery-new"
```
