# 7단계 — Ethernet 통신 감시와 관측 유효성 (0.7.0)

2026-10-18 · IMP-12의 Ethernet 감시, 설정·상태 화면, 경고 병합·복귀와 관측 지연 보호를 구현했다. CAN·Diag 실제 수신 이벤트와 하드웨어 채널 관측은 현재 어댑터에서 지원하지 않는다. CANoe 기록 제어와 수신 감시의 지원 여부는 구분한다.

## 사용 순서

메인 **통신 감시 → 감시 기준**에서 **새 규칙**을 선택한다. 최대 16개의 Zipy 규칙을 저장할 수 있다. 규칙은 다음 기록부터 적용되며 기록 중에는 변경할 수 없다. 상태 화면은 기록 중에도 열 수 있다.

- 이름과 **미수신 판정 시간**, **시작 유예 시간**, **허용 해석 지연**, **복귀 확인 연속 수신 횟수**를 직접 입력한다. 초기값은 모두 비어 있다. 시작 유예에는 0을 명시할 수 있으며, 허용 지연은 0보다 크고 미수신 시간 이하여야 한다. 시험 기준이 없으면 규칙을 만들지 않는다.
- 흐름은 목적지 IP/MAC과 패킷 목록의 프로토콜 표기로 고른다. 조건은 AND로 적용한다. 출처 확인은 해당 흐름 안에서만 수행하며, 기대 출처 IP/MAC을 지정하려면 독립적인 목적지 조건이 필요하다. 기대 출처를 비우면 미수신만 확인한다. 모든 흐름 조건을 비우면 선택 NIC의 전체 수신을 관측한다. 포트별 조건은 이번 범위에 없다.
- 감시 기준은 원본 캡처 필터로 전달하지 않는다. 기존 파일 기록 범위를 유지한다. 규칙이 없으면 **감시 미설정**, CAN·Diag 기록 중에는 **감시 미지원**, 기록 전후에는 **감시 안 함**으로 표시한다.
- **수신 상태** 탭과 메인 대상 카드에서 상태를 확인한다. 미수신, 선택 흐름의 다른 출처, 수신 복귀, 관측/응답 지연과 처리 오류를 구분한다. 같은 경고는 횟수·마지막 수신·출처 근거를 갱신하고 발생/복귀를 이력으로 남긴다. 경고만으로 기록을 정지하지 않는다.

## 구현과 보호

- `monitors/rules.py`: 버전 1 JSON 검증·주소 정규화·16개 상한. 기준은 기존 SQLite 설정 문서에 저장한다. 스키마는 2를 유지하며 이전 설정은 빈 감시 기준으로 읽는다.
- `monitors/engine.py`: 실제 패킷 시각·흐름·출처를 기록별로 누적한다. 미수신에는 단조 시계를 사용한다. 값 변화 여부를 수신 근거로 사용하지 않으며, 프레임 payload는 보유하지 않는다.
- Ethernet worker의 stdout 해석 직후, 표시 큐에 넣기 전에 감시한다. 화면 큐가 차거나 사용자가 패킷 창을 닫고 필터/일시 정지를 사용해도 감시 입력은 유지한다. `summary_drops`는 화면 누락이며 원본 캡처 손실이나 감시 누락으로 단정하지 않는다.
- 파서 오류 이후에는 설정한 미수신 시간만큼 깨끗한 관측 범위를 다시 확보한다. 늦거나 미래인 패킷은 새 수신 근거로 쓰지 않는다. 정상 시각의 패킷이 다시 올 때까지 판정을 보류한다. PC 벽시계가 허용 범위 이상 바뀌면 해당 구간의 시각 판정은 확인 불가로 유지한다.
- `monitors/observation.py`: 패킷 처리 지연뿐 아니라 worker 응답의 생성 시각도 검사한다. IPC/다른 CANoe 응답 때문에 오래된 정상 응답이 뒤늦게 도착하면 확인 불가로 표시한다. UI의 독립 검사도 마지막 정상 표시가 무기한 남는 것을 방지한다. 매우 짧은 허용 지연을 설정하면 UI 갱신/질의 지연에도 확인 불가가 표시될 수 있다.
- 감시 처리 예외는 진단에 남기고 원본 stdout 소비를 계속한다. 이전 세션 응답은 현재 수신 근거로 채택하지 않는다. 도구 오류는 통신 미수신과 구분하며 기존 부분 실패 정책을 따른다.
- 발생·복귀 이벤트는 SQLite와 상시 개발자로그에 남긴다. 현재 횟수·시각·출처 요약은 약 5초 간격과 종료 시 세션 이력에 저장한다. 이 간격은 DB 갱신 설정이며 차량 판정 기준이 아니다. worker 명령 로그에는 중간 관측 근거와 예외 원문을 남긴다.

## 검증

- 신규 감시 검사 37개와 전체 자동 검사 **333개**, Ruff 정적 검사를 통과했다. 미설정·유예·미수신·복귀·출처 비교·관계없는 트래픽·비IP MAC·다중 규칙·오래된 패킷/응답·시계 변경·파서/감시 오류·표시 큐 포화·기록 유지·설정 영구 보존·한/영 UI·UI 응답 유효시간을 확인했다.
- 소스 `--verify-monitoring`의 localhost 시험 5항목을 통과했다. 규칙은 이 시험 프로필에만 만든 합성 기준이다. 최초 미수신, 화면 큐 누락 200건 중 감시 입력 1,200건 보존, 재미수신·복귀, 의도한 기대 출처 불일치, 파일 검사·이력 저장을 확인했다. 생성한 1,220개 패킷과 최종 PCAP의 전체 읽기 건수가 일치했다. 실제 NIC나 CANoe 창을 열지 않았다.
- 초기 시험 도구는 상태 전환만 확인하고 stdout/캡처 버퍼의 나머지 패킷이 반영되기 전에 정지를 요청했다. 전송 완료와 관측 완료를 구분해 생성한 모든 패킷의 관측을 기다린 뒤 정지·전체 파일 건수를 대조하도록 고쳤다. 이 시험은 임의 시점 정지나 모든 실제 부하에서의 무손실 취득을 보장하지 않는다.
- 한국어·영어 상태/기준 화면, 최소 720×520 기준 입력 스크롤과 메인 3개 대상의 감시 표시를 확인했다. offscreen 확인은 Windows 설치 글꼴을 명시적으로 사용한다.
