# 1.0.1 CANoe 로깅 블록 Name 미지원 연결 수정

2026-10-26 · 사용자 가이드 2026-10-26.1

다른 실차 PC의 1.0.0 제공 로그에서 CANoe 19.2.76 실행/RBS 열기와 블록 수 조회는 성공했으나 Logging Block.Name의 E_NOTIMPL로 연결 8회가 실패했다. [비식별 원인 분석](../analysis/canoe_connection_failure_2026_10_26.md)을 따른다. 차량 데이터 수신이나 RBS 전체 호환성 문제로 단정하지 않는다.

Name의 알려진 미지원 오류와 빈 이름은 번호 표시로 대체한다. 블록 목록에 name_available을 남기고 내부 선택에는 실제 알 수 없는 이름을 None으로 보존한다. 진단은 block_name_fallbacks 및 canoe.block_name_unavailable을 기록한다. 조회 미지원은 연결마다 확인하고 검증 중 반복 호출은 캐시한다.

출력 경로·블록 수/순서·선택한 출력의 고유성·소유한 정확한 파일·Trigger/측정 상태 검사를 유지한다. 같은 경로의 알 수 없는 이름은 모호한 선택으로 차단하고, RPC/권한/기타 COM 오류와 필수 FullName 오류는 숨기지 않는다. 다중 블록의 수동 파일명 변경은 이름이 확인되지 않으면 명시적 재연결을 요구한다. 소유한 정지 후 출력 복구/trigger 번호 정규화는 기존 원본/작업 경로 범위 안에서 검증한다.

세 언어 가이드에 번호 표시와 수동 파일명 변경 후 재연결을 설명하고 새 버전 Qt 사진을 갱신한다. TC-03에 해당 PC의 재확인 절차를 반영하되 48개 제목/ID 및 이전 회차 JSON 불러오기를 유지한다. 설치 CANoe 버전 선택·Npcap BAT·ZIP 보관 기능은 유지한다.

실제 버그리포트의 예외를 사용한 COM 대역 회귀 검사와 해당 PC의 실제 연결/장비 취득 성공은 구분한다. 후자는 새 배포본으로 현장 재확인이 필요하다.

검증: 제공 예외 모양으로 수정 전 동일 Name 조회 실패를 재현했다. 수정 후 CANoe 제어 검사 111개와 전체 자동 검사 805개가 통과했다(전체 79.56초). Ruff/pip check/438개 문서 링크/48 TC HTML 최신성 검사와 세 언어 데스크톱/390px 가이드·1.0.1 Qt 사진 42장을 확인했다. 제공 실차 PC에서의 수정판 성공은 이 검사 결과에 포함하지 않는다.
