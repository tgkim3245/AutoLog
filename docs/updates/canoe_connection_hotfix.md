# CAN·Diag 연결 수정 — 0.8.1

> 과거 기록: 이 문서는 작성 당시의 변경·검증 근거를 보존합니다. 현재 동작과 남은 확인 사항은 [현재 구현 상태](../reference/implementation_status.md)를 따릅니다.

후속 변경: [0.8.4 자동 독립 연결](canoe_independent_connection.md)에서 별도 모드 선택창을 제거했다. 현재 사용법은 각 카드의 연결 확인이며 필요한 COM 모드는 자동 준비한다. 아래는 0.8.1 당시의 진단과 수동 설정 이력이다.

2026-10-18. 사용자가 CAN과 Diag 연결 확인을 연달아 누른 뒤 한쪽 오류와 다른 쪽의 설정 변경 안내를 보고했다.

## 확인한 원인

- 현재 설치본 `can.ini`의 `SingleCOMClient=0`을 확인했다. CANoe 프로세스는 한 개였고, Diag 연결 응답에 기존 CAN 구성이 반환된 진단이 남아 있었다. 두 버튼을 동시에 눌렀기 때문만은 아니며, 이 모드에서는 순차 연결도 기존 창을 재사용한다.
- 0.5.1에서 두 인스턴스 연결을 실증할 때는 독립 연결 모드를 적용했고, 검사 후 원래 값 0으로 복구했다. 실제 PC에서 독립 연결을 적용해야 한다는 안내가 연결 실패 이후에 나와 사용자 흐름이 불충분했다.
- 연결 버튼은 수정하지 않은 값까지 모든 연결 설정을 다시 저장했다. CAN의 기록 블록을 실행부에서 자동 선택한 직후 UI 반영이 늦으면, Diag 클릭이 CAN 블록의 이전 빈 값을 다시 저장할 수 있었다. 실제 로그에서 CAN 블록 선택 직후 재저장이 보였고, 반영 응답을 지연한 재현으로 이 경로를 확인했다.

## 수정

- 연결 전 저장은 사용자가 실제 수정한 항목만 보낸다. 응답 대기 중인 동일 값은 두 번째 연결에서 재전송하지 않는다. 다른 대상의 자동 선택 결과를 이전 UI 값으로 덮어쓰지 않는다.
- 실제 COM 생성 전에 현재 설정과 CANoe 프로세스를 읽는다. 독립 연결이 꺼져 있고 CANoe가 실행 중이면 생성 요청 전에 조치를 안내한다. 설치 설정을 읽지 못한 경우에는 기존 구성/객체 일치 보호를 계속 사용한다.
- 예상한 독립 연결 문제는 긴 Traceback 대신 원인·조치와 **독립 연결 설정…** 버튼을 해당 카드에 표시한다. 전체 오류는 개발자로그와 상세 툴팁에 유지한다. worker는 이번 명령에서 발생한 문제만 구조화해 보고하므로 과거 진단이 새 오류의 분류를 덮어쓰지 않는다.
- 설정 창에서 CANoe가 실행 중이면 변경 버튼을 잠그고, 창 수와 닫기 안내를 표시한다. 닫은 뒤 **상태 다시 확인 → 다중 연결 적용 → 닫기**를 사용한다. 적용 후 저장된 CAN/Diag 구성을 다시 연결 확인한다. 비활성 적용 버튼의 색도 구분한다.

현재 열려 있는 사용자 CANoe 창과 설치 설정을 이번 수정 작업에서 변경하지 않았다. 다중 연결은 사용자가 모든 CANoe 작업을 저장하고 창을 닫은 뒤 설정 화면에서 적용한다. `.cfg`를 저장하거나 측정을 시작하는 동작은 추가하지 않았다.

## 검증

- 전체 자동 검사 **376개**를 통과했다. 후속 worker 오류 분류/표시 변경 후 관련 검사 **47개**, 저장 응답 대기 중 동일 값 재전송을 막는 추가 회귀 검사를 포함한 관련 검사 **42개**와 Ruff를 통과했다. 다른 블록의 늦은 설정 응답, 실제 편집의 저장, 생성 전 차단/허용 조건, 설정 재확인·양쪽 재연결, 과거 오류의 잘못된 재분류를 포함한다.
- 현재 PC의 설정 0·실행 중 CANoe를 유지한 채 실제 source worker의 Diag 연결 요청을 실행했다. COM 생성 전 안내가 반환됐고 기존 CANoe 프로세스 목록과 원본 Diag `.cfg` 해시는 유지됐다. 측정/Trigger는 호출하지 않았다.
- 한/영 연결 안내와 실행 중 설정 변경 잠금 화면을 확인했다. 근거는 로컬 `Downloads/AutoLog_Builds/hotfix-0.8.1-review/`에 보관했다.

독립 모드를 실제 적용한 뒤 두 구성의 측정/BLF 기록을 수행하는 검증은 현장 작업으로 남긴다. 0.5.1의 독립 연결 실증과 0.8.0의 Ethernet 부하 결과는 각각 해당 문서를 따른다.
