# 0.9.23 CANoe 버전 선택과 RBS 열기 실패 재설정

2026-10-25 · 가이드 2026-10-25.6

초기설정 BAT의 19 버전 고정을 해제했다. Program Files·Vector 설치 등록·설치 프로그램 등록·현재 COM 경로에서 64비트 CANoe를 찾고 버전·경로·현재 COM 대상과 등록 도구 존재/서명 상태를 표시한다. 사용자는 RBS 구성(.cfg)에 맞는 설치본의 목록 번호를 입력한다. 하나만 발견돼도 자동 선택하지 않으며 빈 입력/Q는 CANoe 등록 취소, 잘못된 번호는 재입력이다.

선택한 실행 파일과 같은 폴더의 공식 RegisterComponents.exe를 사용한다. 두 파일의 Vector 서명과 선택 당시 전체 버전을 실행 전 다시 확인한다. 서명 없는 설치본은 경로/SHA256을 보여주고 공식 설치본임을 확인한 사용자의 REGISTER 추가 입력 후 서명 상태/해시를 재확인해 실행한다. 잘못된/확인 불가 서명은 이 예외로 실행하지 않는다. 관리자 요청과 공식 도구 조작 후 실제 64비트 COM 경로/전체 버전이 선택과 일치해야 성공이다. 도구 누락·파일/서명/해시/버전 변경·관리자 취소·공식 도구 실패·다른 COM 대상은 성공으로 처리하지 않는다. Npcap 설치/건너뛰기와 고정 해시·서명 검증, 내부 PC 배포 범위는 유지한다. 실제 COM 등록·설치는 빌드/자동 검사에서 실행하지 않는다.

세 언어 가이드의 CANoe 19 필수 조건을 RBS에 맞는 버전 선택으로 바꿨다. 하단에 RBS 열기 실패 시 정지·보관 → 앱/모든 CANoe 저장·종료 → BAT 재실행·목록 번호 선택 → 관리자 승인·COM 결과 확인 → 앱 재실행·cfg 재연결·F9/Trace 확인 절차와 초기설정 다시 하기 링크를 넣었다. 링크는 위 0단계 절차로 이동하며 BAT 실행/관리자 승인은 사용자가 한다. COM 등록 확인은 RBS 호환·라이선스·실차 성공과 구분한다.

이전 0.9.22 문서의 CANoe 19 필수/고정 등록 안내는 당시 배포 범위이며 이 버전부터 위 선택 절차를 따른다. 48 TC의 제목/ID를 유지하고 TC-01/03에 버전 선택·취소·RBS 실패 후 재설정을 반영했으며 이전 결과 JSON도 계속 불러온다. 배포/설치 절차는 [초기설정 안내](../guides/canoe_registration_helper.md)를 따른다.

검증: 전체 자동 검사 784개 통과(79.67초), Ruff·432개 문서 링크·48 TC HTML 최신성 확인. 생성 설치 폴더의 15/19 검색·중복 제거·도구 누락, 단일/복수 선택·재입력/취소·선택과 다른 COM 경로·서명 없는 설치본의 추가 확인/해시 변경 차단을 검사했다. 개발 PC 읽기 전용 검색은 실제 15.7.5/19.3.118과 현재 COM 대상을 발견했고 설치/등록을 실행하지 않았다. 세 언어 데스크톱/390px에서 하단 재설정 안내와 0단계로 이동하는 버튼을 확인했다.
