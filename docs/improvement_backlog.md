# 개선 제안 — 이번에는 적용하지 않음

2026-10-19 · 사용자 요청에 따라 선택적 개선은 구현하지 않고 아래에 정리했다. 확인된 버그 수정은 [전체 검토](project_audit_0_8_6.md)에 별도로 기록한다.

| 우선순위 | 제안 | 사용자에게 생기는 이점 | 범위·결정할 점 |
| --- | --- | --- | --- |
| 높음 | CAN 연결 상태를 `cfg 열림 → 측정 대기 → 기록 준비`로 구분 | 연결 확인이 성공했는데 logging이 안 되는 이유를 더 쉽게 이해 | 기존 카드 안의 상태 문구/다음 동작을 정돈. 설치 버튼 추가 없이 처리 |
| 높음 | 하드웨어 채널 확인 결과를 준비 카드에 표시 | cfg만 맞고 실제 VN/채널은 다른 상황을 구분 | 실제 API 조사와 기대 채널 설정 필요. 기존 미구현 ALERT-05와 연결하며 정보 없으면 확인 불가 표시 |
| 높음 | CAN 라이선스 시험 결과를 버전별 지원표로 관리 | 어떤 CANoe/cfg/장비 조합에서 실제 기록을 확인했는지 명확 | 제품 버전뿐 아니라 CANoe 빌드, 라이선스 유형, VN/드라이버, 시험 조건 기록 |
| 중간 | 작은 해상도·125~200% DPI에서 창 높이/스크롤 조정 | 버튼이 화면 밖으로 밀리거나 잘리는 문제 예방 | 480px 폭 선호를 유지하면서 화면 높이에 맞추는 범위 검토. 현재 코드 변경 없음 |
| 중간 | 최근 활동에 오류/경고 필터와 상세 복사 | 긴 traceback에서 사용자가 조치할 내용과 개발자 전달 내용을 쉽게 찾음 | 최근 500줄 상한 유지. 기존 버그리포트 버튼과 중복 기능 최소화 |
| 중간 | 오래된 DB 이력 보관·정리 정책 | 장기 사용 시 DB 크기와 시작/목록 조회 시간 제한 | 기간/건수·내보내기·미완료 기록 예외를 먼저 결정. 캡처 파일 자동 삭제는 포함하지 않음 |
| 조건부 | 취득(dumpcap)과 실시간 해석 경로 분리 | 대표 고부하에서 해석 정체가 취득에 주는 영향 완화 가능 | 우선 CPU·메모리·드롭·지연 실측. 파일 후행 읽기/관측 지연과 복구 복잡성이 늘므로 자동 변경하지 않음 |
| 낮음 | 파일 관리 전체 이력 검색/페이지 이동 | 현재 최근 100개 세션 밖의 파일도 앱에서 찾기 쉬움 | 오래된 파일은 디스크에 유지되고 미완료 복구는 전체 세션을 조회함. 검색 범위·로딩 성능 고려 |
| 낮음 | 버그리포트에 익명화 가능한 환경 요약 추가 | 사용자가 버전·설정·재현 조건을 따로 설명할 부담 감소 | 현재 ZIP은 개발자로그와 manifest. cfg·캡처 내용은 넣지 않고 포함 항목/경로 마스킹을 결정 |

권장 순서는 **라이선스 CAN 기록 실증 → 필요한 CAN/채널 감시 구현 → 차량 대표 부하 검증 → 화면/운영 편의 개선**이다. 미검증 기록 기능의 성공 여부를 UI 정리만으로 대신 판단하지 않는다.
