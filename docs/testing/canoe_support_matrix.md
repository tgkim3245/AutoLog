이전 버전의 시작/정지·파일 잠금·자동 번호 문제와 수정은 [업데이트 목록](../updates/README.md)에 있다. 오래된 “실제 BLF 미검증” 문장은 해당 버전/시점의 사실이며 위 후속 관측과 구분한다.

## 현재 버전에서 남은 실차 확인

CAN·Diag 단독/동시·Zipy 포함 7조합, 측정 유지 10회 반복, 물리 장비 재연결, X의 실제 전용 CANoe 종료, 누락 원인 분리, 대표 부하·60분·1 GiB 초과를 [48 TC](vehicle_test_plan.md)로 확인한다. 수행하지 않은 결과는 미실행·Blocked로 남긴다. 새 증빙 없이 표의 상태를 통과로 바꾸지 않는다.

## 새 결과 기록

아래 정보를 회차별 결과 JSON/양식에 남기고 공유 가능한 요약만 이 표에 추가한다.

- 실제 앱 버전·소스/빌드 ID·배포 해시, Windows·CANoe 전체 빌드·옵션 라이선스.
- 장비 별칭·드라이버·cfg 별칭·BLF 블록·논리 CAN 번호와 물리 포트, DBC·ECU 버전.
- TC/조합·반복/기록 시간·시각과 시간대·번호·실제 프레임/시간 범위.
- 측정 유지·출력 복구/보류·파일별 보관·다음 구간·종료/재실행 결과.
- 오류·누락·비교 기준·버그리포트 및 원본 증빙 이름.

업무 cfg 전체·장치 시리얼·원본 캡처·진단·개인 경로는 Git 밖에 보관한다. 연결만 확인, 실제 기록, 사후 파일 분석, 미실행을 구분해 적는다.
