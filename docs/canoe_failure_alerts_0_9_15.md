# CAN·Diag 기록 중단 알림 — 0.9.15

2026-10-23. 이전 버전은 CANoe query의 측정/기록/응답 이상을 확인하면 전체 정지는 했지만 팝업 전달은 Zipy 유효성검사 경로에만 있었다.

CAN·Diag의 측정 중지, 선택 기록 블록 중지, 상태 확인 불가에도 중단 팝업을 전달한다. 각 대상의 확인된 원인을 표시하고 물리 연결선이 빠졌다고 단정하지 않는다. USB/전원/케이블과 CANoe F9·Trace 확인 후 재시작을 안내한다. 원문 오류는 개발자 로그와 대상별 이벤트에 남긴다.

한 query에서 동시에 확인한 CAN·Diag·Zipy 이상은 한 알림으로 합친다. 실제 실패한 Zipy 규칙의 사용자 문구도 함께 유지한다. 기존 Zipy 단독 실패의 기본/사용자 안내와 설정 탭은 유지한다. 알림은 구간당 한 번이며 한국어·영어·중국어를 지원한다. 일반 텍스트·비모달 표시를 유지해 정상 정지/파일 검사·보관이 버튼 확인을 기다리지 않는다. 팝업이 열린 상태의 메인 X도 기존 즉시 종료 정책을 따른다. 저장할 수 없는 파일은 저장 완료로 안내하지 않는다.

감지는 기존 CANoe worker query의 측정·trigger·출력 소유권/파일/응답 상태를 사용한다. 새 XL 포트나 CAN 수신 채널을 열지 않고 원본 cfg·CAPL·하드웨어 매핑을 변경하지 않는다. CAN 통신선만 빠져도 CANoe 측정과 trigger가 계속 정상으로 보고되면 감지하지 못한다. CAN·Diag 실제 수신 감시는 아직 미지원이므로 팝업 부재는 정상 수신의 증거가 아니다.

## 검증

장비 없는 회귀 검사에서 CAN 측정 중지, Diag trigger 중지, 응답 실패, 3대상 동시 실패, 정지 실패의 알림 전달, 전체 정지/보관·다음 구간 재시작을 확인했다. CANoe query 성공 응답 안에 중단 상태가 담긴 경우와 query 자체가 실패한 경우를 각각 검사했다. UI는 세 언어의 대상/원인·단발 알림·Zipy 문구 보존·X를 확인했으며, 앱 smoke는 실제 알림 큐로 CAN·Diag 실패를 중복 전달해 한 팝업과 열린 상태 종료를 검증했다.

소스 전체 631개 검사 통과(55.30초), CANoe 응답 상태 대역 보강 후 해당 Runtime 검사 21개 통과(3.88초). Ruff·의존성·diff 검사도 통과했다. 한국어·영어·중국어 팝업을 렌더링해 문구/줄바꿈을 검토했고, 배포 가이드는 데스크톱·모바일 16개 화면에서 가로 넘침과 미치환 항목이 없었다. 문서 파일 링크 304개에 누락이 없다.
