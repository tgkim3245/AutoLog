## 새 시험 결과 추가 규칙

- 아래 항목을 회차별 기록하고 위 표에 결과를 추가한다. 업무 cfg 이름·경로·장치 시리얼은 로컬 근거에 두고 Git에서는 별칭을 쓴다.
- AutoLog 버전/소스 커밋, Windows 빌드, CANoe 전체 빌드, 측정 가능한 라이선스 종류와 확인 시각, VN 모델/드라이버, cfg별 논리 CAN 번호→장치 별칭/물리 포트, 블록 이름·출력 형식을 기록한다.
- `연결만`, `실제 기록 통과`, `실패`, `미실행`을 구분한다. 실제 기록 통과에는 시작/정지 3회 이상, BLF 실제 프레임·시간 구간, 측정 유지와 원래 출력 옵션 복구 근거가 필요하다.
- 0패킷 구조 검사 통과나 COM 대역 검사는 실제 CAN 통신 성공으로 등록하지 않는다. 실패는 오류·조작 순서·버그리포트 근거와 함께 남긴다.
- CAN 단독, Diag 단독, 동시 기록의 결과를 각각 기록한다. 하드웨어 기준 일치도 케이블·차량 데이터 수신을 인증하지 않는다.

## 현장 기록 양식

```text
시험 일시 / 담당자:
AutoLog 버전 / 소스 커밋:
Windows / CANoe 빌드 / 라이선스:
VN 별칭 / 모델 / 드라이버:
CAN cfg 별칭 / 블록 / 논리 채널→장치 별칭·포트:
Diag cfg 별칭 / 블록 / 논리 채널→장치 별칭·포트:
조합 / 반복 횟수 / 기록 시간:
결과: 연결만 | 실제 기록 통과 | 실패 | 미실행
BLF 프레임·시간 구간 확인:
측정 유지 / 경로·옵션 복구:
오류 및 로컬 근거 경로:
```

Vector의 [채널 매핑 안내](https://support.vector.com/kb?id=kb_article_view&sysparm_article=KB0011315)처럼 논리 채널과 물리 장치 채널을 구분한다. 로컬 XL 조회로 원격 VTP 장치의 매핑을 대신 판정하지 않는다. [원격 장치 매핑 안내](https://support.vector.com/kb?id=kb_article_view&sysparm_article=KB0014055)를 따른다.
