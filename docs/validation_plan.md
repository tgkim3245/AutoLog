# 검증 계획

상태: 요구사항 55개에 대응하는 시나리오 66개(T-01~T-66). 최신 자동 검사·복구·배포본 검증은 [6단계 0.6.0 결과](development_stage_6.md), CANoe 독립 연결은 [0.5.1 결과](canoe_fix_plan.md)를 따른다. 자동 검사 296개와 아래 시나리오 전체의 현장 통과는 구분한다. 실제 CANoe 측정·구간 기록, 차량 NIC의 대표 부하와 팀 배포 검증은 남아 있다. 임계값과 시험 조건이 미확정인 항목에는 실측 결과를 입력하지 않는다.

## 1. 검증 단계

1. **장비 없는 검증:** 가상 연동 모듈로 시작·정지·부분 실패·타임아웃·이벤트 상태 전이를 검사한다.
2. **파일 검증:** 식별 정보가 없는 샘플로 저장·파일명 충돌 방지·형식 읽기·요약 생성을 검사한다.
3. **시험 PC 연동 검증:** 실제 CANoe 19 설정과 Ethernet 인터페이스에서 각각 취득·정지를 확인한다.
4. **통합 검증:** 공통 패널에서 두 로그 취득과 이상 발생·복구를 확인한다.

실제 장치 분리·통신 차단·Bus-off 유발은 시험 절차에 따라 별도 수행한다. 일반 자동 검사에서 차량 통신이나 기존 측정을 바꾸지 않는다.

## 5. 결과 기록 양식

각 검증에는 아래 항목을 남긴다.

- 검증 ID와 일시, 프로그램 버전 또는 변경 식별자.
- 시험 PC·CANoe/Wireshark·드라이버·장비·설정 프로필.
- 조건, 재현 순서, 기대 결과, 실제 결과, 통과/실패/미실행/미지원.
- 관측 근거: 로그·화면·파일 검증 결과와 해당 세션 경로.
- 이상 발생 시각의 기준, 패널 최초 경고 시각, 측정 불확실성.
- 결함과 재검증 결과.

가상 연동 검사 통과와 실제 장비 연동 통과를 구분한다. 파일 존재 검사와 파일을 실제로 열어 취득 내용을 확인한 결과도 구분한다.
