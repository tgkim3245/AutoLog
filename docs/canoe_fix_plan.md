# 대표 구성 호환성 수정 계획 · 0.5.1

2026-10-18. 실제 구성에서 발견한 문제를 다음 순서로 처리한다.

1. 연결 소유권: 기존 창을 반환하는 COM 설정에서는 구성을 덮어쓰지 않고 현재/요청 구성과 조치 방법을 표시한다. 시작 직후 COM 준비 지연을 기다린다. 전역 can.ini를 앱이 자동 변경하지 않는다. 독립 연결은 실제 두 구성으로 별도 검증한다.
2. 블록 선택: 실제 블록 이름·형식·출력 경로를 조회한다. BLF 블록이 하나면 그 블록을 선택하고 PCAPNG 블록의 잘못된 선택을 차단한다. 삭제된 선택은 목록을 다시 보여준다.
3. 구간 출력: 선택 블록의 출력 경로와 자동 번호/분할 옵션을 메모리에 보관하고 구간 동안만 적용한다. 정상 정지, 시작 전 취소/오류에서 복구한다. 외부 편집을 발견하면 덮어쓰지 않고 진단에 남긴다. 원본 cfg는 저장하지 않는다.
4. 환경 안내: View Only를 측정 대기와 구분하고 라이선스 조치를 표시한다. 기존 CAPL 로깅 버튼과 동시 조작 시 외부 상태 변경을 감지한다.
5. 검증: 블록 선택, 세 구간 반복, 설정 복구, 부분 적용 오류, 외부 변경, 예약 전 취소와 복수 대상 실패를 검사한다. 소스 검사 후 버전별 EXE/ZIP을 빌드한다. 실제 기록 검증과 읽기 전용 연결 검증은 구분한다.

원본 구성/CAPL/데이터베이스는 수정하지 않는다. 측정은 사용자가 시작하며 AutoLog는 선택한 Logging Block의 구간만 제어한다.

## 구현 결과

- **독립 연결:** `SingleCOMClient=0`에서는 별도 worker의 DispatchEx도 기존 창을 반환한다. Vector의 `SingleCOMClient=1` 모드에서는 새 객체가 Open 이전에 Configuration 조회를 E_FAIL로 거부한다. 등록된 COM 실행 파일과 일치하는 Vector SettingsFolder의 설정을 확인한 경우에만 이 미구성 상태를 처리한다. 읽을 수 있는 기존 구성이 반환되면 계속 교체를 거부한다. 활성 객체 표에서 임의 창을 가져오지 않는다.
- **명시적 설정:** 설정 → CAN·Diag 구성 → **CANoe 독립 연결 설정…**에서 설명과 현재 상태를 확인하고 다중 연결을 적용하거나 기본 모드로 복구한다. 해당 설치본 전체의 설정임과 다른 COM 도구/ActiveX/.NET 패널의 영향을 표시한다. 모든 CANoe 프로세스가 닫혀 있어야 하며 설정 파일 배타 열기·표시 당시 내용 대조·원본 백업 후 값 한 바이트만 바꾸고 읽어 확인한다. 연결 확인 자체는 전역 설정을 바꾸지 않는다.
- **블록 선택:** Name·확장자·원래 출력 경로를 조회한다. 유일한 BLF 후보를 자동 선택하고 PCAPNG 블록은 선택을 막는다. 오래된/부적합한 선택은 목록과 조치 메시지를 다시 표시한다. 경로는 툴팁에서 확인한다.
- **출력 관리:** 원래 FullName과 측정 시작/트리거/용량/시간별 증가 옵션을 보관한다. 구간 출력에는 증가·분할을 끄고 정지 후 복구한다. 예약 전 실패/취소, 예약 이후 미시작 대상도 복구한다. 외부 설정 변경은 덮어쓰지 않으며 실패 시 스냅샷을 유지해 다음 연결에서 재확인한다. 파일 닫힘과 설정 복구 실패는 별개로 기록한다.
- **구성 전환:** 정지·미수정 상태의 소유 창에서는 COM 참조를 유지한 채 새 구성을 연다. 미저장 편집이나 무관한 수동 구성 교체를 감지하면 보존하고 조치 요청을 표시한다.
- **라이선스/공존:** View Only는 라이선스 조치를 표시하고 시작을 차단한다. CANoe 기존 로깅 버튼과의 동시 조작을 피하도록 안내하고, 트리거·경로·측정·파일명 옵션 변경을 감지한다. 기존 CAPL은 유지한다.

## 검증 결과와 범위

- 정적 검사 통과, 기본 자동 검사 **272개 통과**. 세 구간 반복·출력 옵션 복구·부분 적용 실패·외부 편집 보존·미저장/제목 없는 구성 보존·예약 오류/취소 복구·View Only 안내·기존 CAPL에 해당하는 외부 정지 등을 포함한다.
- **실제 연결:** 수정된 0.5.1 어댑터로 CANoe 19.3.118에서 대표 CAN/Diag 두 구성을 동시에 열었다. 서로 다른 COM identity와 두 프로세스, 구성별 정확한 경로, CAN_Logging/Logging의 BLF 자동 선택을 확인했다. CAN의 ETH_Logging은 PCAPNG 비호환 후보로 구분됐다.
- 실제 연결 시험 중 Measurement/Trigger의 Start·Stop은 호출하지 않았다. 두 측정은 정지였으며 View Only를 정확히 보고했다. 두 원본 .cfg의 전후 SHA-256은 일치한다. 검증이 만든 미수정 창만 종료한 후 다중 COM 설정을 원래 값 0으로 복구했다. 원시 경로/해시는 로컬 `Downloads/AutoLog_Builds/cfg-review-20261018/autolog-0.5.1-dual-connection.json`에 보관하고 Git에는 넣지 않는다.
- 설정·블록 드롭다운·독립 연결 설정 창을 한국어로 렌더링해 배치를 확인했다.
- **남은 실제 기록 시험:** View Only를 해제할 CANoe/VN 라이선스·장비 준비 후 CAN 단독 3회, Diag 단독 3회, CAN+Diag 및 Zipy 조합에서 출력 옵션의 측정 중 적용·복구, BLF 완결·기대 채널·측정 유지·CAPL 공존을 확인한다. 연결과 모의 검사만으로 실제 취득 성공/고부하 무손실을 보증하지 않는다.

근거는 설치된 Vector can.ini의 SingleCOMClient 설명, CANoe.tlb와 실제 두 구성의 COM 관찰이다. 처음의 Configuration E_FAIL은 라이선스 오류로 단정하지 않고 미구성 객체와 구분해 재검증했다. 배포본 검증은 빌드 후 별도 기록한다.
