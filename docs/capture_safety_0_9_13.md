# 0.9.13 연결·수신 이상 정지와 종료 수정

2026-10-22 / 사용자 보고에 따른 변경.

## 확인한 원인

- 0.9.12 보고서에서 Ethernet 파일 증가량·해석 PPS가 0인 상태가 10초 이상 이어져도 dumpcap은 살아 있었다. 기존 코드는 프로세스 생존만으로 기록 중을 표시하고 감시 규칙도 비어 있었다.
- 전용 CANoe PID 수신 직후 `win32process.GetProcessTimes`가 지연 로드하는 `win32timezone`이 배포본에 없어 소유 핸들 등록이 예외로 끊겼다. 연결 재시도는 가능했지만 종료 대상이 등록되지 않았다. 보고서는 X 이전에 만들어졌으므로 해당 X의 완료 여부 자체는 보고서에 없다.

## 구현

- 선택한 NIC GUID의 Windows `GetIfTable2` 운영 상태를 조회한다. Down/NotPresent/LowerLayerDown 또는 어댑터 소실을 단절로 취급하고 인터넷 유무·다른 NIC의 트래픽으로 판단하지 않는다. 조회 오류/알 수 없는 상태를 단절로 지어내지 않는다.
- 기본 규칙은 `02:00:00` Source MAC 접두사, 5초 시작 유예, 3초 미수신 제한, 2초 평균 100pps 하한이다. 저속이 3초 지속돼도 실패한다. 트래픽 속도는 100ms 버킷 최대 21개로 계산해 고속 수신에서도 패킷별 이력을 쌓지 않는다. 전체 MAC/특정 EtherType/목적지를 임의로 고정하지 않는다. 다른 Source도 허용하고 저장한다.
- 기존 사용자 지정 규칙은 유지한다. 종전 빈 문자열 설정에만 기본 규칙을 추가하고 명시적으로 저장한 빈 규칙 목록은 유지한다. 기준은 통신 감시에서 수정/삭제 가능하다.
- 기록 중 단절·수신 기준 위반·대상 오류/응답 확인 불가가 발생하면 모든 선택 대상에 정상 정지를 보내 닫힌 파일을 보관한다. 관측 불가 지속은 5초 후 정지한다. 시작 유예/복귀 샘플 대기는 관측 고장으로 보지 않는다. 확인된 수신 위반은 화면 갱신 전에 수신이 복구돼도 해당 구간에 유지해 정지 판단을 놓치지 않는다. 표시용 큐 누락은 원본 단절로 오인하지 않는다. 실패 이력은 남기고 새 구간을 시작할 수 있다.
- 처음·다음·실패 후 새 기록 시작 버튼은 초록색. 기록 중 빨간 정지, 준비/정리 중 문구·잠금은 유지한다.
- 메인 패킷 보기/환경 확인을 제거했다. 작업 이력은 이름 변경·삭제의 기존 이력을 읽기 전용으로 표시한다. 옆의 로그 폴더는 설정한 캡처 폴더를 연다. 직전 파일 이름 변경/삭제는 유지한다. 일반 캡처의 화면 패킷 전송도 꺼서 불필요한 IPC를 줄였다.
- 소유 CANoe의 생성 시간 확인을 native FILETIME으로 바꾸고 `win32timezone`도 명시적으로 동봉한다. X는 coordinator가 바빠도 보관한 핸들로 즉시 종료 요청을 보낸다. 종료 완료 대기·COM 호출·프로세스명 일괄 종료는 하지 않는다. 늦게 등록된 소유 핸들도 종료 요청하며 관련 없는 프로세스는 유지한다.

## 검증

소스 전체 614개 검사 통과(61.47초), 표시 보완 뒤 관련 20개 검사 통과. Ruff·의존성·diff 검사 통과. 세 언어 메인 창 480/360px에서 가로 넘침 없음, 기본 감시 편집 값 표시 확인. 가이드는 데스크톱/모바일 14개 화면으로 렌더링해 검토했다. native 테스트 전용 자식 프로세스로 생성 시각 검증·보관 핸들 종료·늦은 등록·다른 프로세스 유지와 coordinator 대기 중 즉시 종료 신호를 검사했다. 최종 빌드의 검증 수치와 해시는 후술한다.

실제 EXE 재현에서 출처 위반이 확인되자 정지해 이후 시험 패킷 일부가 기록되지 않는 정상 동작을 확인했다. 검증 명령은 위반 패킷 하나로 정지를 검사하도록 바꿔 정지 이후 패킷 수를 요구하지 않는다. 완성 파일 수와 실제 읽힌 패킷 수 확인은 유지한다.

실제 VN 및 물리 Ethernet 케이블 분리와 실제 CANoe 종료는 현장 재시험이 필요하다. 모의 성공을 실제 차량 시험 성공으로 표시하지 않는다.
