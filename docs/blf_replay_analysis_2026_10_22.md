# BLF 리플레이에서 시그널이 안 보이는 사례 분석

2026-10-22. 사용자가 제공한 완료 BLF 한 개를 읽기 전용으로 분석했다. 다른 PC에서 취득 때와 같은 cfg/DBC로 재생했다고 설명했으며 PCA 상태 시그널을 예로 들었다. 실제 재생 PC의 cfg·DBC·재생 방식은 아직 직접 확인하지 않았다. 원본 캡처·업무 cfg·개인 경로·프레임 및 시그널 원문은 Git에 보관하지 않는다.

## 확인된 사실

- 파일 크기 8,209,282바이트, SHA256 `0d8aec59a678ebb7d5a601b8b5b72ecb34d2fe53a65feb9fb0600373ee856780`이다. 압축 컨테이너 213개와 내부 객체 264,770개를 구조 검사했다. 헤더 개수보다 실제 객체가 6개 많으며 메타데이터가 존재한다. 이 차이를 프레임 누락으로 판단하지 않는다.
- 실제 CAN FD 객체 264,513개를 독립 CAN reader로 전부 읽었다. 논리 CAN 1은 59,942개, CAN 2는 204,571개다. 읽힌 오류 프레임·역행 타임스탬프·프레임 데이터 길이와 DLC 불일치는 없었다. python-can이 지원하지 않는 버전 3 객체 두 개는 CAN FD 객체가 아닌 별도 메타데이터이며, CAN FD 객체 수와 읽힌 프레임 수는 일치한다. 이 결과는 차량 취득 전체의 무손실을 증명하지 않는다.
- 프레임은 측정 기준 355.277232~416.747262초에 존재하며 실제 기록 구간은 약 61.470초다. 측정을 유지하고 구간 trigger만 켜고 끄는 원래 시간축이 남아 있다. 이 앞의 시간이나 고정된 짧은 그래프 구간만 보면 기록이 없는 것처럼 보일 수 있다. 재생 PC가 그 시간을 어떻게 처리했는지는 확인 전이다.
- BLF 자체의 채널 메타데이터에는 메인 DBC가 CAN 1, Debug DBC가 CAN 2에 연결돼 있다. 현재 PC의 취득 cfg도 같은 DBC 연결이다. 그러나 해당 Debug 메시지 여섯 개는 실제 CAN 1에서 발견되고, 메인 DBC에 맞는 다수의 메시지는 CAN 2에서 발견된다. 파일 자체의 메시지 채널과 연결된 DBC 정보가 엇갈린다.
- 사용자가 언급한 이름에 대응하는 현재 DBC의 PCA 상태 필드를 읽었다. 같은 메시지가 CAN 1에 2,459개 있으며 값 변화도 있다. 따라서 그 필드의 원시 데이터가 전혀 저장되지 않았다는 설명과는 맞지 않는다.
- 현재 Debug DBC의 해당 메시지 길이/값 범위와 실제 기록 길이/값 범위에도 차이가 있다. CAN FD 패딩 가능성이 있으므로 길이 차이만으로 오류를 확정하지 않으며, 기록 당시 ECU 소프트웨어에 맞는 Debug DBC/열거값을 확인해야 한다. 현재 DBC로 특정 비트를 읽을 수 있다는 사실과 올바른 업무적 의미 해석을 구분한다.

## 코드 확인과 결론

AutoLog는 CANoe의 선택 BLF 블록에 출력 이름/분할 옵션과 trigger를 적용하고, 완성된 파일을 그대로 이동하거나 동일 내용의 봉인본으로 보관한다. CAN 프레임의 채널 번호·ID·payload·timestamp나 DBC 연결 정보를 변환하지 않는다. 로컬 채널 기준 기능도 매핑을 조회/비교하며 장비 매핑을 자동 변경하지 않는다.

이번 파일은 완료 이력의 파일 크기·개수·ID와 일치했다. 현재 증거에서 AutoLog의 저장 처리로 해당 시그널 데이터가 삭제됐다는 결함은 재현하지 못했다. 우선 확인 대상은 **취득 파일의 채널과 DBC 연결 불일치**, 추가로 DBC/ECU 버전 및 재생 시간 범위다. 사용자가 전달한 앱 버전만으로 당시 정확한 실행 바이너리를 단정하거나, 다른 PC의 재생 환경 전체가 잘못됐다고 판단하지 않는다.

재생용 cfg 복사본에서 Trace의 숫자 ID·CAN 번호를 먼저 확인하고, 해당 메시지가 있는 논리 CAN에 맞는 Debug DBC/시그널을 연결한다. 실제 데이터가 존재하는 측정 시간 구간을 선택한다. 다음 현장 취득에서는 물리 포트·논리 CAN·DBC 연결이 일치하고 기대한 메시지 이름/시그널이 Trace에 나타나는지 확인한 뒤 해당 구성을 저장한다. 실제 배선 확인 없이 물리 매핑이나 원본 파일 채널을 자동 교환하지 않는다.

공식 사용자 가이드 개정 2026-10-22.4와 배포 안내문에 이 점검 절차를 추가했다. 앱 실행 코드나 기존 배포 EXE는 바꾸지 않았다. 원본 파일/프로젝트는 수정하지 않았다. 원본 SHA256 재대조, 문서 생성·치환 확인, 291개 로컬 문서 링크와 12개 뷰포트의 가로 넘침/미치환 검사를 통과하고 수정한 문제 해결 표의 렌더링을 확인했다. 실제 재생 PC에서의 시각적 재현은 남아 있다.

로컬 빌드 저장소의 `blf-replay-analysis-2026-10-22/`에 구조 통계, DBC별 대조 결과, 상태 값 변화와 CSV를 보관한다. 분석용 cantools 45.1.0을 개발 환경에 설치했으며 앱의 실행 의존성으로 추가하지 않았다. 원본 DBC의 한 확장 ID 표기를 분석 도구용 메모리 사본에서만 정규화했고 원본은 변경하지 않았다. 여러 DBC에 같은 메시지가 있어 DBC별 대조 횟수/시그널 수를 고유 개수로 합산하지 않는다.
