## 바뀐 동작

- 메인은 네이비·블루, 대상별 카드, 상태 배지, 간결한 활동 목록으로 개편했다. 설정은 저장 / CAN·Diag / Ethernet 탭으로 나눈다. 상단 작은 **개발자로그**는 매 실행 기본 OFF다.
- .cfg·TShark 실행 파일·저장 폴더는 선택 직후 자동 저장한다. 직접 입력한 경로는 입력을 마칠 때 저장한다. 네트워크·pcap/pcapng·표시 언어도 기억한다. prefix·다음 번호 변경은 **적용**을 사용한다.
- TShark를 PATH·일반 Wireshark 설치 경로·준비한 사용자 도구 경로에서 찾는다. 저장된 경로가 잘못되면 그대로 알려주며, 사용자가 **다시 찾기**를 눌렀을 때 새로 발견한 도구로 바꿀 수 있다.
- NIC 식별자 수동 입력을 없앴다. Windows의 이더넷/Wi-Fi 이름, 어댑터 설명과 연결 상태를 표시하며 실제 GUID는 내부 저장과 상세 도움말에 사용한다. 첫 네트워크를 임의 선택하지 않는다. 지난 네트워크가 사라지면 이전 선택을 보존하고 재선택을 안내한다.
- **연결 확인**은 클릭 직후 진행 상태를 표시한다. 누락/읽기 불가 구성 파일·도구 오류·미선택 네트워크·Npcap 확인 필요 등을 같은 카드에 표시하고 다음 조치를 안내한다. 결과 카드가 커지면 화면 안으로 스크롤한다.
- 환경 확인은 CANoe / 캡처 도구 / 네트워크 / Npcap의 읽을 수 있는 상태 카드와 설정 이동 버튼을 제공한다. 기술 JSON은 접힌 상세 보기에 둔다.
- OS/도구 검색은 제어·SQLite 처리와 별도 실행한다. 늦은 결과는 변경된 설정을 준비 완료로 만들지 않는다. 자동 경로 저장도 prefix/번호 편집을 덮어쓰지 않는다.
- 개발자로그에는 탐색 경로·버전·네트워크 목록·드라이버 확인 범위·오류 원문·연결 확인 요청/결과·저장 내역·예외를 남긴다. 캡처 payload는 저장하지 않는다.

## 현재 PC 준비와 확인 범위

공식 winget 배포 MSI의 Authenticode와 SHA256을 확인하고 Wireshark 4.6.9 도구 파일을 사용자 폴더에 준비했다. MSI의 관리자용 이미지 추출을 사용했으며 시스템 드라이버나 기존 CANoe 구성은 변경하지 않았다.

TShark 경로: `%LOCALAPPDATA%\VILLogging\tools\Wireshark\tshark.exe`.

로컬 확인에서 TShark 버전 실행 성공, 네트워크 6개 조회, CANoe 19.3.118.0 실행 파일 발견, 알려진 경로에서 Npcap 미발견을 확인했다. NIC 목록은 Windows 조회와 `tshark -D`를 병합하며 실제 인터페이스를 열거나 패킷을 기록하지 않는다.

TShark는 앱 배포 폴더에 포함하지 않는다. 다른 PC에서는 해당 PC의 Wireshark/TShark를 자동 탐색한다. 외부 드라이버·도구 라이선스와 준비 조건은 기존 설치 안내를 따른다.

실제 CANoe/TShark 취득 어댑터·파일 보관/이름 변경/삭제는 아직 제공하지 않는다. CANoe 파일과 설치 확인, TShark 버전 및 NIC 목록 조회는 실제 연결·라이선스·캡처 성공 판정과 구분한다. CAN/Diag .cfg와 실제 연동은 사용자의 답변대로 시험 PC에서 나중에 확인한다.

## 검증

자동 검사 134개, Ruff, 의존성 검사 통과. 기존 제어·저장·개발자로그 검사에 경로 즉시 저장, 재실행 보존, 오래된 저장 응답, 저장 내용이 같을 때의 완료 처리, 친숙한 NIC 이름, 누락된 이전 장치, 연결 확인 진행/결과, 검색 중 정지, 늦은 연결 결과 무효화, 명시적 TShark 재탐색을 추가했다.

실제 앱의 signal 연결로 경로·NIC·형식·prefix/번호를 변경하고 오류 결과를 표시한 뒤 종료하고, 별도 프로세스로 다시 실행해 복원하는 검사도 통과했다. 한국어/영어 메인·설정·환경 화면을 렌더링해 배치를 확인했다. [메인](../../../outputs/stage2/preview/main.png), [Ethernet 설정](../../../outputs/stage2/preview/ethernet.png), [환경 확인](../../../outputs/stage2/preview/environment.png)을 볼 수 있다.

최종 EXE를 Python 관련 환경 변수와 경로를 제거한 조건에서 실행했다. 기본 OFF 실행은 개발자로그 파일 0개, 체크박스 ON/OFF 실행은 JSONL 1개와 명령 결과·모의 종료·로그 종료 근거를 확인했고 모두 종료 코드 0이었다. 결과는 [EXE 자체 검사](../../../outputs/stage2/exe_smoke_results.json), 버전과 해시는 배포 폴더의 build_info.json에 기록한다. 실제 시험 PC·실제 취득은 미검증이다.
