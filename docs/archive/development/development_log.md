## 2026-10-22 — Wireshark CLI 동봉 배포 (0.9.12)

- 사용자 정상 동작 확인 이후의 요청에 따라 공식 4.6.9 x64 MSI에서 TShark·dumpcap·capinfos와 의존 DLL·자료를 동봉한다. 출처/버전/해시 고정·캐시 검증·MSI 관리 추출·CLI 버전 검증·라이선스/소스 제공을 빌드에 연결했다. Npcap 드라이버는 별도 설치다.
- 실행 파일 상대 기본 경로·이동 가능한 저장값·직접 선택 유지·이전 관리 경로 전환을 적용하고 한·영·중 UI와 사용자 가이드를 갱신했다. [동봉 구조·검증 범위](../../updates/bundled_tshark_0_9_12.md)를 따른다.
- 전체 자동 검사 596개(52.68초), Ruff·의존성·diff·문서 링크 293개를 통과했다. 공식 가이드 개정 2026-10-22.5의 생성·12개 뷰포트 가로 넘침/치환 검사를 통과하고 변경 안내의 실제 렌더링을 검토했다.
- 공통 설정 API에서도 동봉 도구의 절대 경로를 빈 기본값으로 저장하도록 보강한 뒤 전체 596개를 53.52초에 재통과했다. 소스 `7b82666`으로 `AutoLog-0.9.12_20261022_162422`을 빌드했다. ZIP CRC·버전·해시·중국어 모의 버튼/X·동봉 도구 NIC 조회, 동일 EXE 추출 코드 154개와 문서 일치 검사를 통과했다.
- 압축 해제한 실제 EXE에서 기본 도구로 PCAP/PCAPNG 각 3구간(0패킷·5패킷·재기록)을 보관했다. 실제 UDP 패킷 수와 원본/화면 수가 일치했고 물리 NIC는 열지 않았다. 폴더를 실제 이동한 실행과 별도 이전 관리 경로 프로필의 자동 전환도 통과했다. 861개 runtime/resource와 39개 소스 아카이브를 ZIP/압축 해제본 해시로 대조했다. 최종 ZIP은 267,756,615바이트다. 가이드 14개 뷰포트와 한·영·중 설정 화면을 검토했다.

## 2026-10-22 — 완료 BLF의 시그널 리플레이 분석

- 제공된 BLF에서 CAN FD 프레임 264,513개와 PCA 상태 필드의 값 변화를 확인했다. 파일 안의 DBC 채널 정보와 실제 메시지 채널이 엇갈렸고, 측정 기준 첫 프레임이 355.277초인 점 및 Debug DBC 정의 차이도 구분했다. 취득 무손실이나 실제 재생 화면의 원인은 이 결과만으로 확정하지 않는다.
- [분석 근거·확인 절차](../../analysis/blf_replay_analysis_2026_10_22.md)를 기록하고 공식 가이드 개정 2026-10-22.4와 배포 안내문을 갱신했다. 원본 파일·cfg·앱 코드는 변경하지 않았다. 실제 재생 PC의 채널/DBC 대조는 남아 있다.

## 2026-10-22 — X 완전 종료·중단 구간 폐기 (0.9.11)

- 새 리포트 1,731건에서 네 구간 정상 보관, 1,000건 패킷 보기 직후 AppHang, 재실행 5회의 같은 미완료 이력 차단을 확인했다. 폴더 삭제만으로 DB 차단이 풀리지 않는 원인을 구분했다.
- 사용자의 새 결정에 따라 X는 AutoLog와 이번 실행의 전용 CANoe까지 종료하고 중단 작업 파일을 버린다. 이력은 실패/폐기로 정리하며 다음 실행은 대기 상태로 시작한다. 생성 시 검증한 프로세스 핸들·소유 경로만 처리하고 완료 파일·다음 번호·다른 프로그램은 유지한다. 트레이를 제거하고 패킷 표를 모델 방식으로 바꿨다.
- 현재 PC는 DB 사전 백업 후 파일이 이미 없는 13번 이력만 정리했고 다음 번호 14를 유지했다. [정책·근거·검증 범위](../../updates/shutdown_policy_0_9_11.md)를 따른다. 공식 가이드 개정 2026-10-22.3을 반영한다.

- 소스 `bce968c`에서 `AutoLog-0.9.11_20261022_132118`을 빌드했다. ZIP CRC·해시·버전, 압축 해제 EXE의 중국어 모의 시작/정지/완료/X·NIC 조회와 같은 EXE 추출 코드 142개, 가이드 포함·개정·해시 대조를 통과했다. 실제 EXE의 별도 프로필 두 개에서 이전 작업 폴더가 있거나 없어도 중단 이력 폐기 후 새 모의 기록을 완료했다. 전용 CANoe 실제 종료/재연결은 현장 재시험으로 남아 있다.

## 2026-10-22 — 종료·재실행과 Enter 이름 변경 (0.9.10)

- 0.9.9 현장 리포트에서 9구간 정상 보관과 마지막 새 구간의 Windows AppHang/미완료 복원을 확인했다. 정상 종료 요청과 멈춘 위치의 스택이 없어 특정 함수의 현장 원인으로 확정하지 않는다.
- 화면의 직접 IPC 수신을 bounded 메모리 큐/전용 daemon으로 분리하고, pool의 종료 검증도 adapter의 정지 소유 출력 복구 보류를 허용하도록 맞췄다. 외부 변경 보호·X 제한·원본 취득 분리는 유지한다. 5초 이상 UI 지연 시 스택 진단과 Enter 이름 변경을 추가했다.
- 마지막 완전 BLF 두 개를 DB 사전 백업/해시 대조 후 복구했다. 잘린 PCAP은 원본 유지 정리하고 다음 번호 9·이전 기록·외부 CANoe를 보존했다. [원인·검증·복구 근거](../../updates/capture_fixes_0_9_10.md)를 따른다. 공식 가이드 2026-10-22.2를 함께 갱신한다.
- 전체 자동 검사 577개(61.45초), Ruff·의존성·diff·문서 링크 283개를 통과했다. 종료 전 worker 응답을 소비·확인하고 가이드 12개 뷰포트를 검토했다.
- 소스 `f0976e0`으로 `AutoLog-0.9.10_20261022_110539`을 빌드했다. ZIP CRC·해시·버전, 압축 해제 EXE의 중국어 모의 기록/종료·NIC 조회, 같은 EXE의 추출 코드 대역 136개와 문서 포함·개정·해시 대조를 통과했다. 실제 새 버전 CANoe 종료/재실행 시험은 남아 있다.
