## 목표

컴팩트한 다이얼로그 팝업에서 CANoe의 CAN 로그(`.blf`)와 Wireshark의 패킷 캡처(`.pcap` 또는 `.pcapng`)를 함께 시작·정지하고, 취득 중 확인된 문제와 캡처 파일을 간단히 관리한다.

## 기능 요구사항

| ID | 요구사항 | 완료 기준 |
| --- | --- | --- |
| UI-01 | 화면은 핵심 제어를 담은 컴팩트한 다이얼로그 팝업으로 제공한다. | 폭을 약 480px로 제한하고 CAN·Diag·Zipy 선택 카드를 가로로 배치한다. 알림·로그와 큰 공통 로깅 버튼도 같은 메인 창에 둔다. 좁은 화면에서는 카드가 읽기 좋게 재배치된다. |
| UI-02 | 현재·다음·직전 기록 파일명을 메인 팝업에서 확인하고 직전 로그 이름을 변경한다. | 기록 중에는 선택한 모든 파일의 실제 기본 이름과 확장자를 표시한다. 최초 대기에는 다음 파일명, 세션 종료 후에는 직전 파일명과 결과를 표시한다. 직전 로그 이름 변경은 메인 파일명 영역의 고정 텍스트박스와 버튼으로 실행하며 클릭해도 창 높이가 늘어나지 않는다. 다음 예정 이름은 설정에서 확인한다. 파일별 저장 중·보관 완료·미완료를 구분하고 임시 기록 중에는 실제 경로도 확인할 수 있다. |
| UI-04 | CAN·Diag·Zipy는 메인 창에 가로 카드로 배치한다. | 각 카드에는 로깅 체크박스·대상·현재 상태를 표시한다. .cfg 선택과 Zipy 연결 조작은 설정 창에서 수행한다. CAN/Diag 체크박스는 .cfg 선택 전에도 사용할 수 있으며 연결 설정과 독립적으로 로깅 참여만 정한다. |
| UI-05 | 파일 규칙·저장 경로와 1회성 연결 준비는 톱니바퀴 설정창에서 관리한다. | 설정창은 prefix·다음 인덱스·공통 저장 폴더, CAN/Diag의 .cfg 선택, Zipy 연결, Ethernet 저장 확장자 선택을 제공한다. 현재 연결 상태는 설정창과 메인 카드에 표시한다. 직전 로그 이름 변경은 메인 파일명 영역의 상시 노출 텍스트박스와 버튼으로 실행하며, 조작에 따라 창이 확장되지 않는다. |
| UI-03 | 사용자는 통합 `한 / EN / 中` 버튼으로 한국어·영어·중국어 간체 표시를 순환 선택한다. | 선택 언어를 기억하고 메인·설정·보조 창의 라벨·상태·알림·버튼에 적용한다. 외부 도구 오류 원문·경로·프로젝트명은 보존한다. |
| CAP-01 | 공통 버튼 하나로 체크한 CANoe 및 Ethernet 로그를 함께 시작·정지한다. | 버튼 이름은 언어와 상태에 관계없이 소문자 `logging`으로 표시한다. 한 번 누르면 시작, 다시 누르면 정지하며 활성 상태는 버튼 색·표시와 대상별 로깅 상태로 구분한다. 체크된 대상만 제어한다. CAN 단독·Ethernet 단독·동시 로깅을 지원하며, 아무것도 선택하지 않으면 시작하지 않고 알린다. |
| CFG-01 | 설정창의 CAN·Diag 카드의 .cfg 찾기 버튼으로 .cfg 파일을 찾아 연다. | 확장자·존재·읽기 가능 여부를 검사하고 전체 경로를 보관한다. 취소·잘못된 파일 선택은 기존 구성과 연결을 바꾸지 않는다. CANoe가 실제로 읽은 구성과 의존 파일 오류를 확인하며 파일명만으로 성공 처리하지 않는다. |
| CFG-02 | 통합 프로그램이 선택한 .cfg로 CANoe를 실행하고 해당 대상만 제어한다. | 이미 사용자가 열어 둔 CANoe 창을 찾아 연결하는 기능은 지원 범위에서 제외한다. 실행한 대상과 실제 연결된 구성의 일치를 확인한다. |
| CFG-03 | 통합 프로그램으로 실행한 CANoe의 일반 화면을 사용자가 직접 조작할 수 있다. | 현재 제품·권한·측정 상태에서 허용되는 설정 수정과 저장을 CANoe에서 수행할 수 있다. |
| CFG-04 | 사용자의 설정 변경과 실제 측정·기록 상태를 통합 패널이 다시 확인한다. | 기록 명령 직전 재조회하고 기록 도중에도 상태 이벤트·조회를 반영한다. 프로젝트 교체·창 종료·대상 모호성은 기존 제어 참조를 무효화한다. 경로·블록 변경은 CFG-05를 따르며 단순 화면 배치 변경은 연결을 무효화하지 않는다. |
| CAP-02 | 시험에 따라 CANoe 로그 1개 또는 2개를 동시에 취득한다. | 사용자가 서로 다른 두 .cfg 구성 중 취득 대상을 선택하고, 각 CANoe의 독립된 BLF를 한 세션으로 기록한다. Ethernet도 선택하면 해당 PCAP/PCAPNG를 같은 세션에 포함한다. 어느 대상의 시작 실패·중단인지 구분한다. |
| CAP-03 | Ethernet 로깅을 체크박스로 선택한다. | 체크한 경우에만 Ethernet 캡처를 수행한다. CAN 단독·Ethernet 단독·동시 기록을 지원한다. 시작 처리부터 모든 기록 종료·미완료 상태 정리까지 대상 선택·형식·이름·폴더를 바꾸지 않는다. |
| FORMAT-01 | 설정창에서 Zipy의 .pcap/.pcapng 확장자를 선택한다. | 메인 카드에는 선택된 확장자만 표시한다. 기본값은 .pcap이며 실제 캡처 도구의 출력 형식을 지정한다. 확장자·내용이 일치해야 하고 다음 세션부터 적용한다. 최초 지원 범위는 선택한 NIC 한 개이며 지원하지 않는 조합은 시작 전에 차단한다. 직전 로그의 형식은 유지한다. |
| CONN-01 | 설정창의 Zipy 연결 버튼으로 Ethernet 캡처 준비 상태를 확인한다. | 캡처 도구의 실행 가능 여부·버전·드라이버를 통한 인터페이스 조회·선택한 NIC 존재를 확인한다. 확인 범위를 표시하며 실제 NIC 열기와 기록 시작 성공은 로깅 시작 시 별도 확인한다. 연결만으로 패킷 취득이나 파일 기록을 시작하지 않고 패킷 미수신을 연결 실패로 단정하지 않는다. |
| STATE-01 | CAN·Diag·Zipy의 실제 상태를 각각 표시한다. | 미연결·연결 중·연결 완료·시작 중·로깅 중·종료 중·오류·확인 불가를 글자와 색으로 구분한다. 선택 해제는 연결 상태를 덮지 않는다. 정지 후에는 실제 연결·측정 상태를 다시 표시하며 오류를 정상으로 되돌리지 않는다. |
| CAP-04 | 선택한 모든 대상의 기록 준비가 완료되어야 공통 로깅을 시작한다. | 대상·구성·기록 블록·측정 실행·도구/NIC·출력 경로·이름 충돌을 확인한다. 준비 미완료나 사전 충돌이면 시작과 번호 예약을 보류하고 원인을 알린다. CANoe 측정은 사용자가 시작하며 연결과 로깅 선택은 별도 동작이다. |
| ALERT-01 | 설정된 CAN 신호가 기준 시간 동안 수신되지 않으면 사용자에게 신호 미수신을 알린다. | 대상 신호와 마지막 수신 시각 등 확인 가능한 근거를 보여준다. |
| ALERT-02 | Ethernet 패킷 또는 설정된 대상 흐름이 수신되지 않으면 사용자에게 알린다. | 패킷 미수신을 캡처 도구 중단이나 네트워크 단선으로 단정하지 않고 관측 사실을 구분해 표시한다. |
| ALERT-03 | 설정한 감시 흐름에서 기대한 패킷 출처를 확인한다. | 대상 흐름과 기대 IP/MAC 등을 비교하고 근거를 표시한다. 관계없는 정상 트래픽의 존재만으로 출처 불일치 경고를 만들지 않는다. 기대 흐름 미수신과 같은 흐름의 다른 출처 관측을 구분한다. |
| ALERT-04 | 관측 사실과 확인 불가 상태를 구분한다. | 미수신·출처 불일치·캡처 도구 오류를 구분하고 시각·대상·근거를 표시한다. 기준 미설정·기능 미지원·관측 지연/중단·미감시를 각각 표시한다. 감시 경고만으로 로깅을 자동 정지하지 않는다. |
| ALERT-06 | 메인 팝업에 실제 오류와 동작 이력을 누적한다. | 시각·대상·등급·이벤트 코드·파라미터·원문 근거를 보존한다. 메인에는 최근 500건을 내부 스크롤로 표시하고 동작 이력은 앱 저장소에 남긴다. 기존 이력의 앱 설명은 선택 언어로 전환하고 외부 오류 원문·경로·프로젝트명은 보존한다. 설정 입력 오류·적용 결과는 해당 입력 옆에 표시하며 외부 토스트로 대체하지 않는다. |
| ALERT-05 | 시작 전에 CANoe의 기대 하드웨어 채널 매핑과 확인된 장비·채널을 비교한다. | 명확한 불일치는 시작 전에 차단하고 근거를 표시한다. 실제 정보에 접근할 수 없으면 확인 불가 경고를 유지하며 이 사실만으로 매핑 정상 또는 단선을 단정하지 않는다. 확인 불가 자체는 제어 대상·측정·기록 준비가 확인된 로그 취득을 막지 않는다. |
| NAME-01 | 사용자가 파일 prefix와 다음 저장 인덱스를 지정한다. | 새 기록 파일은 입력 prefix 뒤에 `_`를 한 번 보정한 다음 인덱스를 붙인다. CANoe 1은 `<prefix>_<인덱스>.blf`, CANoe 2는 `<prefix>_Diag_<인덱스>.blf`, Ethernet은 `<prefix>_<인덱스>.pcap` 또는 `.pcapng`로 저장한다. 입력이 이미 `_`로 끝나면 중복 구분자를 붙이지 않는다. CANoe 2만 선택해도 Diag를 유지하며 선택하지 않은 대상 파일은 생성하지 않는다. |
| NAME-02 | 새 캡처 세션마다 일련번호를 자동으로 증가시킨다. | 다음 캡처에 지정한 인덱스를 쓰고 세션마다 자동 증가하며, 앱을 다시 실행해도 이어진다. 파일 이름 변경·삭제는 인덱스에 영향을 주지 않으며, 설정에서 사용자가 직접 바꾸면 변경한 값부터 이어간다. |

| DEV-01 | 개발자로그는 항상 저장하고 상단 `버그리포트` 버튼으로 내보낸다. | 배포판 EXE 옆 `developer_logs/`에 JSONL을 저장하며 체크박스는 없다. 기본 5 MiB 파일과 최대 4개 백업, 유한 큐를 사용한다. 명령/응답·식별자·상태 전이·시간·오류 원문/traceback·버전을 기록하고 종료 시 큐를 비운다. ZIP을 바탕화면에 복사하고 파일명과 팝업으로 Taegon.Kim에게 이메일로 보내도록 안내하되 이메일 주소는 넣지 않는다. 원본별 크기·SHA256을 manifest에 기록하고 ZIP을 검증한다. 자동 전송하지 않는다. 진단 저장 실패를 화면에 알리며 실제 취득을 중단하지 않는다. |

## 파일명과 번호 규칙

새 설치에서 prefix는 `AutoLog`이며 다음 저장 인덱스를 `7`로 정하면 `AutoLog_7.blf`와 `AutoLog_7.pcap`을 만든다. 다음 캡처는 `AutoLog_8`을 사용한다. prefix가 이미 `_`로 끝나면 구분자를 중복하지 않는다. 일련번호는 앞자리 0을 채우지 않은 십진수로 표시한다. 입력값과 증가 계산에서 큰 정수를 소수로 반올림하지 않는다.

번호는 파일명과 별도로 저장한다. prefix·다음 인덱스를 적용할 때 선택 대상의 예상 파일명을 공통 저장 폴더의 파일과 대조한다. 충돌 시 설정은 적용되지 않고 오류와 충돌 파일명/경로를 표시한다. 캡처 시작 직전에도 실제 저장 폴더를 재검사하며 충돌이 확인되면 덮어쓰지 않고 시작을 보류한다. 세션 번호를 예약한 뒤 부분 실패가 발생해도 그 번호를 다시 사용하지 않는다. prefix만 바꾸면 번호는 이어진다. 설정창의 다음 저장 인덱스는 기록 종료 후에도 사용자가 명시적으로 변경할 수 있으며, 적용한 값은 다음 캡처부터 사용한다. 변경한 번호가 기존 파일과 충돌하면 덮어쓰지 않고 시작을 보류한다.

CANoe 2개를 취득하는 예: `AutoLog_7.blf`, `AutoLog_Diag_7.blf`, `AutoLog_7.pcap`. 이 세 파일은 인덱스 7을 공유하며 다음 저장 인덱스는 8이다. CANoe 1에는 CAN1을 붙이지 않고 CANoe 2에는 인덱스 앞에 Diag를 붙인다. 직전 로그 이름을 `주행 기록`으로 바꾸면 `주행 기록.blf`, `주행 기록_Diag.blf`, `주행 기록.pcap`이 된다. 직전 이름 변경은 인덱스를 붙이지 않으며 다음 저장 번호를 바꾸지 않는다.

선택한 BLF와 PCAP/PCAPNG는 지정한 공통 폴더 안의 같은 세션 임시 폴더에 기록하고, 종료 확인 후 공통 폴더의 최종 이름으로 보관한다. 폴더 경로는 입력하거나 폴더 선택 기능으로 지정하며, 메인 팝업에서 현재 경로를 확인한다. 선택한 경로는 앱 재실행 후에도 유지한다. 폴더에 접근할 수 없거나 경로가 비어 있으면 캡처 시작 전에 알린다.

Ethernet 기본 형식은 `.pcap`이다. 확장자 드롭다운에서 `.pcapng`를 선택하면 예를 들어 `AutoLog_7.pcapng`로 저장한다. 이후 형식을 바꾸어도 이미 기록한 파일의 확장자와 내용은 유지하며, 직전 세션 이름 변경 시에도 원래 형식을 유지한다. Ethernet 체크를 해제하면 해당 세션에는 Ethernet 파일을 만들지 않는다.

## 기준값과 범위

CAN 감시 대상 신호 및 미수신 판정 시간, Ethernet 기대 출처(IP/MAC) 및 패킷 미수신 판정 시간은 시험 조건에 따라 정해야 한다. CANoe 19에서 실제 설정 매핑과 연결 장비·채널 정보를 읽는 방법도 시험 PC에서 확인해야 한다. 정보 접근이 지원되지 않으면 매핑 정상으로 단정하지 않는다. 아직 기준값과 확인 방법은 확정하지 않았다.

화면 표기는 CAN=CANoe 1, Diag=CANoe 2, Zipy=Wireshark 캡처 대상을 뜻한다. 현재 시안은 세 대상을 약 480px 폭의 메인 창에 가로 카드로 표시하고, .cfg 선택·Zipy 연결·Ethernet 확장자 선택은 설정창에서 조작한다. 연결 상태는 메인 카드와 설정창에 함께 표시한다. 브라우저 시안에서는 CANoe와 Wireshark를 실제 실행하지 않는다. 연결 준비 조작 후 연결 중→연결 완료 전이를 시뮬레이션하며, 실제 구현은 외부 프로그램의 응답으로 상태를 결정해야 한다.

`docs/design/wireframe.html`은 과거 시안이다. 실제 앱은 `src/vil_logging/ui/`의 Qt 구현이며 저장 폴더·이름 충돌 검사, SQLite 설정/번호 보존, 실제 Ethernet 기록, 파일 보관·이름 변경·삭제·수동 복구를 제공한다. 모의 실행은 실제 BLF/PCAP를 만들지 않는다. 첫 선택은 CAN·Zipy이며 Diag는 해제다. 메인의 큰 제목/상태 행과 설정의 프로그램 종료 버튼은 제거했으며 메인 X로 기록 정리 후 종료한다.

## 개발자 진단 파일

최신 사용자 요청은 DEV-01의 상시 기록·버그리포트 방식이다. 초기 체크박스 방식은 폐기했다. `로그 폴더`는 사용자 지정 캡처 저장 폴더를 연다. 캡처 원본/패킷 payload는 개발자로그에 저장하지 않으며 파일명·경로·오류 원문 등 운영 정보를 남긴다. ZIP 크기는 압축 때문에 원본보다 작고 내보낸 이후 원본 로그는 계속 증가한다. 검증은 [T-66](validation_plan.md), 구현 연결은 [DEV-01 대응](implementation_plan.md)을 따른다.





## CANoe 실행과 사용자 설정 수정

2026-10-17 확정: 이미 열린 CANoe 두 창에 임의로 연결하는 기능은 제외한다. 사용자가 .cfg 경로를 지정하고 통합 프로그램이 해당 구성으로 CANoe를 실행한다. 시험에 따라 실행한 대상 중 한쪽 또는 양쪽의 로깅을 선택한다.

사용 흐름은 '.cfg 선택 → CANoe 실행 → 필요 시 CANoe에서 설정 수정·저장 → 측정 유지 → 통합 패널에서 구간 로깅 시작·정지'를 기준으로 한다. 실행 직후 전체 측정까지 자동 시작하는 요구는 이번 결정에 포함하지 않는다.

사용자는 CANoe 화면에서 현재 제품·편집 권한·측정 상태가 허용하는 설정을 수정할 수 있다. 실행만으로 설정 편집 권한이 추가되거나 제한되지 않는다. 측정 정지가 필요한 변경은 CANoe의 기존 절차를 따른다.

통합 프로그램은 이번 구간의 출력 경로·이름만 CFG-05에 따라 적용한다. 그 외 사용자 변경을 이전 값으로 자동 덮어쓰거나 .cfg를 다시 불러오지 않는다. 필요 시 사용자가 CANoe의 저장 기능으로 변경을 보관한다. 기록 대상·저장 경로·프로젝트 등 제어에 영향을 주는 변경은 다음 취득 전에 다시 읽고 검증한다. 단순 화면 배치 변경까지 일괄적으로 재연결 사유로 취급하지 않는다.

직접 실행하는 범위로 좁혀도 복수 CANoe의 COM 연결이 자동 보장되는 것은 아니다. 실제 실행 대상과 연결 객체의 대응은 별도로 검증한다.

## 이번 보완의 적용 기준

2026-10-17 사용자 답변: 기록 도중 한 대상이 중단되면 나머지는 계속 기록한다. 사람의 실시간 확인은 출처·목적지·프로토콜·수신 시각과 최근 패킷 목록이면 충분하다. 통신 이상 감시는 선택한 대상의 로깅 중에만 동작한다.

이번 세션의 출력 이름·폴더는 통합 패널이 관리한다. CANoe의 나머지 설정은 사용자가 직접 편집하고 저장한다. 시작 단계 일부 실패는 이번 시작만 정리하고, 모두 시작된 이후 일부 중단은 다른 기록을 유지한다. 감시 경고 자체는 자동 정지 사유가 아니다.

공통 저장 폴더 아래 고유 임시 경로에 취득한 뒤 파일 닫힘과 읽기를 확인하고 최종 이름으로 보관한다. 최종 이름 충돌·보관 실패·부분 파일 작업 실패는 파일별 실제 경로와 결과를 남긴다. 번호는 외부 기록 시작 전에 영구 예약하며 이름 변경·삭제로 자동 되돌리지 않는다.

구체적인 명령·시간 제한 초기값·상태·복구·패킷 목록 처리 방식은 [제어 정책](control_policy.md)을 따른다. 기존 시안에는 새 NIC 설정·패킷 보기·영구 저장·복구 기능이 아직 구현되지 않았다.

복수 CANoe 독립 제어, 측정 유지 중 구간별 파일 완결, 시험 PC TShark 버전의 기록+필드 출력·정상 정지·부하는 실제 실증 전이다. CAN 수신 관측 방법·실제 장비/채널 정보·필요한 경우 CAPL 추가 허용 여부도 확인해야 한다. 소스·주기·통신 임계값은 추후 제공 상태를 유지한다.

## 개발·팀 배포 환경

2026-10-17 사용자 답변: 실제 시험 PC는 Windows 11 64비트이며 팀 여러 PC에서 사용할 예정이다. 설치 권한은 별도 차단 조건으로 삼지 않고, 보안 예외 등록은 필요하지 않을 것으로 설명받았다. 로컬 디스크에 저장하며 평소 약 1분, 길게는 30분 초과이고 Wireshark 로그가 1GB를 넘을 수 있다.

앱의 취득·표시·저장에는 인터넷을 요구하지 않는다. CANoe는 VN 장비를 연결해 인증하는 기존 환경을 사용한다. 원본 .cfg는 되도록 유지하며 CAPL/시스템 변수 추가 허용 여부는 아직 확인 필요다. 로깅 제어는 COM과 기존 설정을 먼저 검증한다.

[착수 전 종합 검토](development_readiness_review.md), [설치 프로그램 목록](installation_matrix.md), [개발·배포 계획](development_delivery_plan.md)에 개발 환경·실증·패키징·장시간/대용량·버전/복구·팀 배포 조건을 정리했다. 설치·실행 코드·실제 시험 PC 검증은 이번 문서 작업으로 수행된 것이 아니다.
