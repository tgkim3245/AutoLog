# AutoLog 0.9.8 — 마지막 버퍼와 BLF 완성

2026-10-21. 사용자가 현재 실제 시험은 불가능하다고 확인했다. 새 버전의 실장 시험을 통과했다고 표시하지 않는다. 실제 캡처·cfg·개인 경로·DB는 Git에 포함하지 않는다.

## 현장 원인

리포트 825건, 1,036,667바이트. ZIP CRC와 manifest SHA256 `16ae696d4e331f04db2e62d6a8b46792e34add15b2f5632cda5becf91d98095f`가 일치한다.

세 구간 모두 측정 실행 중에 trigger가 정지했지만 BLF의 선언 최종 크기와 object 수가 0이었다. 안정된 복사본도 미완결이어서 검사에 실패했다. 다음 기록을 시작한 시점에 앞 BLF가 완성된 근거가 있다. 669번은 검사 실패 때 1,773,568바이트였고 이후 1,805,022바이트가 됐다. 헤더만 고치면 마지막 31,454바이트를 놓칠 수 있다. 670/671번도 검사 실패 이후 파일 크기가 늘었다. 폴더 변경이나 검사 생략으로 해결할 문제가 아니며 0.9.7의 핸들 보유 대응으로 충분하지 않았다.

버튼은 세 번 모두 준비→시작→기록 중→정지로 바뀌었다. 이후 CAN 보관 실패로 FAILED가 되어 ‘다시 시도’로 돌아갔다. 새 클릭은 새 인덱스의 구간을 시작하므로 ‘새 기록 시작’으로 바꿨다. 기록 중에는 정지가 우선한다.

## 구현

- 선택 trigger 정지 뒤 BLF가 미완결이면 같은 블록을 고유한 `.AutoLog_finalize_<UUID>.blf`로 전환하고 짧게 trigger를 시작·정지한다. 다음 trigger가 앞 파일을 완성하는 동작으로 이번 구간의 마지막 버퍼·헤더를 마무리한다. 이미 완성된 파일에는 추가 trigger를 사용하지 않는다.
- 내부 구간은 사용자 로그로 보관하거나 번호를 소비하지 않는다. 측정·다른 블록·다른 CANoe와 원본 cfg를 유지한다. 전체 BLF 검사·교체 없는 최종 보관은 유지하며 헤더를 인위적으로 완성하거나 마지막 데이터를 버리지 않는다.
- 내부 출력도 cfg·논리 블록·고유 경로·분할 옵션과 Start 발행 의도로 검증한다. Start 적용 후 응답 실패·Stop 실패는 보존하고 재시도에서 자기 내부 구간만 정지한다. 외부 경로/기록은 정지하지 않는다. 내부 시작/정지 확인은 각각 최대 4초이며 X 종료 제한은 유지한다.
- 내부 파일 의도·물리 ID를 stop/inspection 근거에 기록한다. 최종 보관본 ID와 내부 파일의 고유 이름·부모·물리 ID가 맞고 핸들이 풀린 자기 파일만 삭제한다. 바뀌거나 잠긴 파일은 유지하고 다음 구간/다음 실행에서 재시도한다. 마지막 내부 파일은 CANoe가 놓아줄 때까지 남을 수 있다.
- `.vil_work`는 진행 중/미완결 파일과 완료 파일을 분리하는 작업 폴더다. 사용자 최종 BLF와 내부 전환 파일은 별개다. 완료 여부를 숨기거나 이름만 옮기는 방식으로 처리하지 않는다.
- 번개 뒤 연결 확인을 또 누르라는 안내를 한·영·중과 공식 가이드에서 제거했다. cfg·블록 선택 후 F9·Trace 수신을 확인하면 바로 기록 시작을 누른다. 시작 시 측정 상태를 재조회하며 cfg/블록 변경의 재연결 정책은 유지한다.

## 재현과 남은 검증

기존 대역은 Stop 때 완성된 BLF를 쓰거나 파일명 변경 때 writer를 닫아 실제 현장 동작과 달랐다. 새 대역은 Stop 뒤 최종 크기/개수가 0이고 마지막 객체가 메모리에 남으며, 다음 Start에서 앞 파일의 마지막 객체·헤더를 쓰고 닫는다.

같은 측정의 3회 구간과 실제 Runtime의 CAN+Zipy 3회에서 즉시 COMPLETED·최종 파일·마지막 데이터·다음 번호를 검사한다. 내부 trigger는 사용자 번호를 소비하지 않는다. 내부 Start 응답/Stop 실패 재시도·외부 출력 보호, 잠금·다른 이름/폴더·교체 ID·사라진 보관본의 삭제 금지와 기존 손상/충돌/복사 변경/복구/X/버튼 검사도 유지한다.

실제 CANoe 새 버전은 현장 재시험이 남아 있다. `canoe.finalization_handoff_requested`·`canoe.finalization_trigger_stopped`·`BLF_PUBLISHED`, 최종 BLF의 마지막 프레임/시각, 측정 유지와 원래 경로/옵션 복구를 3구간 이상 확인한다.

전체 자동 검사 556개(58.83초), Ruff·의존성·diff와 문서 로컬 링크 274개를 통과했다. 공식 가이드 2026-10-21.5를 PC/작은 폭 8개 뷰포트로 렌더링하고 수정된 기록·연결 절차와 버튼 표를 확인했다.

## 이전 파일 복구

0.9.7 DB에 활성 기록이 없고 세 BLF 모두 독점 접근·전체 구조 검사가 가능한 것을 확인했다. 정확한 경로/부모가 일치하는 AutoLog 본체와 worker만 종료했으며 외부 CANoe는 유지했다. SQLite 사전 백업 후 기존 RecoveryService로 669~671번을 최종 저장 폴더에 보관했다. 실패 이력·PCAP·다음 번호 672와 원문 해시를 보존했다.

| 669 | 1,805,022 | 55,593 | `17459ecb816726a56de02e0917d7c8a050419ae47fbf2910fb0b7fa73de37be7` |
| 670 | 1,199,398 | 36,790 | `18abe3d8d6207ff30e0b45c189176d7d1073f6eab0556acb581d8524d187b1c0` |

각 파일의 비-CAN header version 경고 2개와 선언/물리 object 수 차이 3개는 별도로 구분한다. CAN 프레임 읽기와 모든 객체 해석/취득 무손실을 동일시하지 않는다. 사전 DB 백업과 복구 근거는 로컬 빌드 저장소 `field-recovery-0.9.8/`에만 보관한다.
