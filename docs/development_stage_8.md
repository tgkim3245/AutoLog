# 8단계 — Ethernet 기록 품질과 부하 검사 (0.8.0)

2026-10-18 · IMP-04/09/14의 성능·운용 검증에 필요한 계측과 반복 시험 도구를 추가했다. 실제 CAN/Diag 측정과 차량 NIC의 지원 성능 확정은 별도 현장 시험으로 남긴다.

## 사용 방법

메인의 **기록 품질** 버튼을 누르면 Ethernet 파일 크기·증가 속도, 기록 시간, 요약 해석 속도, 현재/최대 해석 지연, 화면 큐 누락, 해석/읽기 오류와 디스크 여유를 확인할 수 있다. 종료 후에는 파일 전체 읽기 패킷 수와 해석 수, 파일에 제공된 드라이버/OS 누락 통계를 함께 표시한다. 재실행 시 이전 기록은 **이전 실행의 종료 기록**으로 표시한다. 기록 중 갱신이 6초 이상 지연되면 마지막 관측값이라는 안내를 표시한다.

**설정 → Ethernet 연결 → 캡처 버퍼**의 기본값은 64 MiB이며 16/32/64/128/256 MiB 중 선택한다. 이전 설정 파일에도 기본값 64 MiB를 적용하며 사용자의 선택을 기억한다. 설정 파일/API로는 정수 1~1024 MiB를 검증한다. 기록 중 설정 변경은 잠긴다. 실제 TShark에는 `-B`로 전달한다. 이는 드라이버에 요청하는 크기로 실제 할당량과 무손실을 보장하는 수치가 아니다. 저장 형식 기본값은 기존대로 pcap이다. [TShark 공식 설명](https://www.wireshark.org/docs/man-pages/tshark.html)을 따른다.

- 파일 증가·해석 속도는 주기 샘플 간 차이이며 종료 시 마지막 관측 속도를 유지한다. 회선 전송률/평균 성능과 구분한다. 지연은 패킷 시각부터 요약 해석까지로, PC 시계 오차도 포함한다.
- 화면 큐 누락은 표시용 요약 누락이다. 저장 파일의 원본 누락으로 계산하지 않는다. 파일 건수와 해석 건수가 같아도 취득 전에 유실된 프레임은 찾을 수 없다.
- 기본 pcap에는 인터페이스 누락 통계가 없어 **확인 불가**를 표시한다. pcapng에서도 선택 통계가 빠진 항목은 확인 불가다. 0이 제공돼도 해당 카운터 범위만 의미하며 전체 경로의 무손실 증명이 아니다.
- 저장 공간이 1 GiB 이하이면 경고와 로그를 남기고, 1.25 GiB 초과 회복 시 복귀를 남긴다. 운용 안내 기준이며 이 경고만으로 기록을 자동 정지하지 않는다. 실제 도구/쓰기 실패는 기존 실패 처리와 파일 보존 정책을 따른다.
- 품질 요약은 약 5초 간격과 최종 보관 시 SQLite 세션 이력·상시 개발자로그에 남긴다. **버그리포트**에 관련 로그가 포함된다. 개발자로그의 위치·회전 크기와 전송 안내는 기존 정책을 유지한다.

## 구현

`diagnostics/capture_quality.py`는 파일/디스크 계측을 수신 잠금 밖에서 수행한다. 파일/디스크 계측 실패는 진단으로 남기고 수신 처리를 계속한다. 정상 정지 때 최종 값을 고정해 이후 파일 이동 때문에 잘못된 경로 오류를 만들지 않는다. TShark 시작 때 이전 수신 스레드가 끝나지 않았으면 새 세션을 거절한다.

`storage/pcapng_stats.py`는 capinfos 전체 파일 검증 이후 블록 위치만 순차 검사한다. 프레임 본문은 읽지 않고 섹션별 바이트 순서/인터페이스, ISB의 선택 `ifdrop`/`osdrop` 64비트 누적 값을 읽는다. 동일 인터페이스의 반복 통계는 최신 값을 쓰며 합산하지 않는다. 인터페이스별 값이 모두 있을 때만 전체 합계를 제시한다. 알려진 양수 근거는 뒤의 통계 생략으로 지우지 않는다. 깨진 길이·시각 역전·감소한 누적 값·검사 시간 초과는 확인 불가 사유로 남기며 캡처 성공으로 추정하지 않는다. [PCAPNG 형식 초안](https://www.ietf.org/archive/id/draft-tuexen-opsawg-pcapng-05.html)의 선택 통계 정의를 사용한다. 전체 파일 읽기와 실제 형식 검사는 계속 [capinfos](https://www.wireshark.org/docs/man-pages/capinfos.html)가 담당한다.

**보관 완료**는 정상 닫힘·구조 검사·파일 보관을 뜻한다. 원본 누락 통계나 해석 수 차이가 있으면 별도 경고를 남긴다. 정상 종료/검사/보관 확인에 실패하면 품질 상태도 확인 필요로 바꾸고 작업 파일을 유지한다.

## 반복 가능한 시험

설치된 Wireshark/Npcap을 사용하며 localhost NIC만 연다. 별도의 새 프로필과 해당 시험용 UDP 목적지 포트만 사용한다. 사용자 설정이나 실제 NIC 필터를 바꾸지 않는다.

```powershell
.\AutoLog.exe --verify-load --load-duration 60 --load-pps 5000 --load-payload 512 --data-dir "C:\Temp\AutoLog-load-new"
```

기본 시험은 10초·초당 1,000개·512바이트 payload다. 시간 1~7200초, 초당 1~100000개, payload 64~60000바이트, 총 1천만 개 이내로 제한한다. 예상 파일 크기 외 1 GiB 여유를 확인하고 시작한다. 이는 입력 제한이며 지원 성능 보장 범위가 아니다. 다른 검증/모의 실행 옵션과 함께 실행할 수 없다.

고유 시험 토큰·연속 번호·고정 내용을 넣어 UDP를 전송한다. 송신 완료 후 해석 잔여분을 기다려 정상 종료/전체 읽기/보관을 마친 다음 PCAP를 스트리밍으로 읽고 누락·중복·내용 손상·다른 시험 토큰·범위 밖 번호를 대조한다. 번호 확인 메모리는 예상 패킷당 1바이트이며 누락 예시는 20개만 보관한다. 목표 송신 시간이 10% 이상 늘어나도 통과하지 않는다. `result.json`에 실제 송신률·파일 검사·품질 샘플·번호 대조 결과를 저장한다. 정상 보관 파일은 이후에도 유지한다.

## 현재 검증 결과

- 자동 검사 **364개**와 Ruff를 통과했다. 설정 기억/오래된 ACK 보호, 구버전 기본값, 샘플 속도/정지 고정, 통계의 0/미제공·다중 인터페이스/섹션·바이트 순서·오류·시간 제한, 순번 대조, 저장 공간 경고 병합/복귀, 경고 중 기록 유지, 세션 혼입 방지·정지 실패/파일 보존·재실행 표시와 한/영 UI를 포함한다.
- 소스 localhost 시험에서 60초간 512바이트 payload를 초당 약 4,999.92개, 총 **300,000개** 전송했다. payload 기준 약 20.48 Mbit/s이며 회선 속도가 아니다. PCAP **168,000,024바이트**의 전 패킷을 재읽어 누락/중복/내용 손상/다른 시험 패킷/범위 밖 번호 모두 0건을 확인했다.
- 표시 큐를 의도적으로 비우지 않아 요약 **299,000건**이 누락됐지만, 저장 파일 번호 300,000개와 해석 건수는 모두 일치했다. 관측한 최대 해석 지연은 약 **508.55ms**였다. pcap의 원본 드라이버/OS 누락 카운터는 확인 불가로 유지했다. 이 결과는 이 로컬 조건에만 해당한다.
- 소스 시험 근거: `Downloads/AutoLog_Builds/stage8-load-63746c3ab7964381a108585e2e7356da/result.json`. 한/영 메인·품질 창과 Ethernet 설정 화면은 `Downloads/AutoLog_Builds/stage8-ui-review/`에서 확인했다. 실제 로그/화면/캡처는 Git에 포함하지 않는다.
