# AutoLog 0.9.3 — 수동 기록 후 파일명 변경 차단 수정

2026-10-20. 사용자가 CAN·Diag 각각 수동 기록 성공을 확인한 뒤 받은 새 리포트를 분석했다. 이 버전의 실제 CAN/Diag 자동 구간 기록 성공은 아직 확인하지 않았다.

## 리포트 근거

ZIP CRC와 manifest의 크기/SHA256이 일치한다. JSONL은 582개 레코드, 853,588바이트, SHA256 `49e6e3516fcd383e20982c708ef300b2595d0a89f66e7d6752192414a3a9adb8`이다. 원본 로그·cfg·개인 경로는 저장소에 넣지 않는다.

- 실행 버전은 0.9.2이며 가이드 포함 배포판이다. CAN/Diag는 서로 다른 PID와 각각 올바른 cfg/BLF 블록에 연결됐다. CAN의 선택은 1번 `CAN_Logging`이며 2번 `ETH_Logging` PCAPNG가 아니다.
- CAN은 처음 연결 당시 원래 출력 파일명을 기억했다. 이후 수동 기록 시험에서 선택 BLF 파일명을 바꾸고 번호가 증가했다. 블록 개수/이름/순서·다른 ETH 블록 경로는 그대로였고 CAN 측정은 실행 중이었다.
- AutoLog prepare 25회 모두 `_validate()`의 `block_layout_or_output_changed`로 실패했다. configure/Start는 한 번도 호출되지 않았다. 수동 trigger 정지가 관측된 시도에서도 파일명 차이로 거부했다. 따라서 이번 리포트의 직접 원인은 라이선스·채널 매핑이 아니라 AutoLog의 대기 상태 경로 검사다.
- Diag는 연결 확인까지만 있다. 사용자 확인으로 수동 기록 성공은 알 수 있지만 이 리포트로 Diag 자동 시작 실패를 관측했다고 쓰지 않는다. 두 역할이 같은 어댑터를 사용하므로 해당 결함은 공통으로 수정했다.

## 수정과 제한

0.9.2는 COM 객체 주소 비교를 제거했지만 대기 중 FullName까지 고정해 정상적인 수동 시험과 번호 증가를 구별하지 못했다. 0.9.3은 출력 소유권을 얻기 전 prepare/configure에 한해 다음 조건을 모두 확인하고 최신 파일명을 받아들인다.

1. 같은 cfg, 선택 인덱스, 전체 블록 개수/이름/순서를 유지한다.
2. 선택 이름이 목록에서 유일하고 출력 확장자가 BLF다. 다른 블록 출력은 바뀌지 않았다.
3. AutoLog 출력 복구가 남아 있지 않고 미확인 시작도 없다. 수동 trigger가 정지 상태다.

진행 중인 수동 기록은 Stop·출력 변경 없이 정지를 안내한다. 정지 후 다시 logging을 누르면 재연결 없이 진행한다. 시작 직전 실제 파일명·자동 증가/분할 옵션을 스냅샷에 보관하고 구간 정리 후 그 값으로 복구한다. 기존 수동 파일은 덮어쓰지 않는다. configure 이후의 소유 출력 경로·세션·자동 분할·닫힘/복구 검사는 유지한다.

수락한 변경은 `canoe.idle_output_refreshed`에 이전/현재 경로와 블록을 남긴다. 수동 기록 진행 중 거부는 `canoe.preparation_blocked`의 `manual_recording_active`로 남는다. 전체 조회마다 동일 로그를 반복하지 않는다.

COM에서 영구 블록 ID를 제공하지 않는 현재 경로로는 같은 cfg/순서/유일한 이름을 유지한 블록 재생성과 정상적인 모델 갱신을 완전히 구별할 수 없다. 대기 상태의 선택은 위 논리 기준을 사용하고, 출력 소유 이후 외부 변경을 허용하지 않는다. 중복 이름으로 파일명만 변경한 경우에는 자동 갱신하지 않고 명시적 연결 확인을 요구한다.

## 검증

- 동일한 새 회귀 검사를 기존 0.9.2 코드에 적용해 CAN·Diag 모두 같은 prepare 오류를 재현했다. 수정 후 안정 프록시/매 조회 새 프록시, CAN(ETH 형제 블록 포함)/Diag 각각 수동 파일명 변경 후 3회 기록·조회·정지·BLF 구조 검사·최신 출력/옵션 복구를 확인했다.
- prepare/configure 사이 파일명 증가와 시작 전 취소 복구, 수동 기록 중 거부 후 수동 정지·재시도, 형식/이름/순서/개수/모호한 선택·다른 블록 출력 변경, AutoLog 출력 소유 중 외부 변경 차단을 검사했다.
- 실제 CANoe 측정 시작·버스 송신·장비 연결·보안 정책 변경은 수행하지 않았다. 현장 재시험은 [절차](licensed_canoe_validation.md)에 따라 CAN 단독 → Diag 단독 → 동시 기록 순서로 남긴다.
