# 4단계 — 완료 파일 관리

2026-10-18 · VIL Logging 0.4.0

[실행 파일](../outputs/stage4/VILLogging/VILLogging.exe). 기존 앱은 **설정 → 프로그램 종료**로 닫고 새 EXE를 실행한다. EXE와 `_internal`을 포함한 폴더 전체를 유지한다. X는 트레이 숨김이다.

## 제공 기능

- 메인의 고정 입력란에서 직전 세션의 공통 prefix를 변경한다. Diag 구분자·세션 번호·확장자·저장 폴더는 유지한다. 입력/실행 때문에 메인 창을 확장하지 않는다.
- **직전 로그 지우기**는 직전 세션의 보관 완료 파일 전체, **파일 관리**는 최근 100개 실제 세션에서 체크한 파일을 대상으로 한다. 전체 경로를 확인한 뒤 영구 삭제한다. 기본 선택은 취소이며 휴지통을 거치지 않는다.
- 기록/시작/정지/닫힘 미확인 중에는 파일 변경을 막는다. 파일 처리 중에도 새 기록·설정 변경을 잠근다. 모의 실행의 파일 작업은 비활성화한다.
- 이름 변경·삭제는 다음 저장 번호와 다음 캡처의 prefix 설정을 바꾸지 않는다. 파일별 실제 경로·결과·오류는 작업 이력과 개발자로그에 남는다. 개발자로그는 매 실행 기본 OFF다.
- 재실행 후 직전 파일과 변경된 경로, 삭제 결과를 다시 표시한다. 파일 없음·내용/식별 정보 변경·접근 불가·중단 작업은 따로 표시한다.

예를 들어 `Run_123.pcapng`의 prefix를 `Road_`로 바꾸면 `Road_123.pcapng`가 된다. 다음 번호가 124였다면 그대로 124다. 파일 관리 모듈의 CAN/Diag 이름 규칙은 생성한 시험 파일로 검사했으며 실제 CANoe BLF 취득을 지원한다는 의미는 아니다. 실제 취득은 여전히 Zipy만 지원한다.

## 파일 보호와 중단 회수

변경은 DB에 등록된 보관 완료 파일에만 수행한다. 임의의 폴더 파일을 검색해 삭제하지 않는다. 파일의 식별자·장치·크기·수정 시각을 확인하고 Windows 배타 핸들로 같은 파일을 잡은 상태에서 이름 변경 또는 삭제한다. 사용 중 접근이 실패하면 해당 파일을 보존한다. 잠금 강제 해제·다른 프로그램 종료·읽기 전용 속성 해제는 하지 않는다. 파일 링크·디렉터리 연결·다중 하드링크는 관리 대상에서 제외한다. 다른 앱이 파일을 닫은 뒤 내부 메모리에 보관하는 모든 사용 상태까지 탐지한다는 의미는 아니다.

그룹 이름 변경은 모든 기대 파일의 준비와 배타 접근을 확인한 뒤 시작한다. 목적지가 나중에 생겨도 교체하지 않는 Windows 핸들 연산을 사용한다. 실행 중 한 파일이 실패하면 나머지 결과와 실제 경로를 별도로 기록한다. 여러 파일의 원자 변경이나 자동 원복을 보장하지 않는다.

작업 의도를 먼저 커밋하고 파일별 실행 결과와 경로를 함께 커밋한다. 결과 커밋이 실패하면 나머지 파일을 더 변경하지 않고 새 기록을 차단한다. 재실행 시에는 저장한 원본/목적지의 식별 정보를 대조할 뿐 이름 변경·삭제를 자동 재실행하지 않는다. 변경 경로가 같은 파일로 확인되면 메타데이터를 회수한다. 삭제 예정 경로가 사라졌더라도 삭제 성공으로 추정하지 않는다. 확인 불가 항목은 작업 이력의 두 경로와 원인을 남기고 해당 파일 관리·해당 경로의 재사용을 차단한다. 그 밖의 충돌하지 않는 새 번호 기록은 가능하다. 확인 불가 항목을 수동 승인해 해제하는 기능은 아직 제공하지 않는다.

이번 버전은 SQLite 스키마를 1에서 2로 이행한다. 기존 DB가 있으면 SQLite 백업 API로 `state.sqlite3.before-v2-<고유값>.bak`을 만들고 무결성을 확인한 다음 트랜잭션으로 이행한다. 번호·설정·세션 계획은 유지한다. 실패 시 이행 트랜잭션은 취소한다. 0.3.x는 스키마 2를 읽지 못하므로 새 버전에서 사용을 계속하며, 새 기록 뒤 과거 백업을 덮어써 번호를 되돌리지 않는다.

## 검증

- 기본 자동 검사 193개. 새 검사는 실제 Windows 임시 시험 파일로 그룹 이름 변경, Diag/확장자/번호 유지, 선택 삭제, 잠금·누락·외부 변경·늦은 목적지 충돌, 의도/결과 DB 실패, 중단 시점 회수, DB 이행·실패 시 원본 보존, UI 확인/취소·조작 잠금을 포함한다. 기본 검사에서 실제 NIC는 열지 않는다.
- `tests/hardware/verify_ethernet_ui.py`는 생성한 localhost 패킷 8개를 실제 캡처한 뒤 메인에서 이름 변경, 파일 관리의 확인창 취소와 확정 삭제, 창 높이·다음 번호 유지, 정상 앱 종료를 확인한다. 물리 NIC나 차량 트래픽은 사용하지 않는다.
- 명시적 `--verify-file-management`는 새 프로필 안에 유효한 PCAP 시험 파일을 생성한다. Windows 이름 변경, 재시작 경로, 사용 중 파일 보존, 삭제, 재시작 삭제 이력의 5항목을 검사한다. 외부 NIC·CANoe를 열지 않는다.
- 최종 폴더 EXE에서 Python 환경 변수와 경로를 제거하고 기본 OFF, 개발자로그 ON/OFF와 검색 UI 전달, 실제 파일 관리, 실제 localhost 6세션의 4종 검사를 모두 종료 코드 0으로 통과했다.
