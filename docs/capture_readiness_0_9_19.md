# 초기 기록 버튼과 준비 상태 — 0.9.19

2026-10-23. 처음 실행한 실제 앱은 선택한 cfg·NIC와 연결 상태가 없어도 초록색 기록 시작을 표시했다. 기존 클릭은 런타임의 준비 검사를 실행했지만 실제로 시작할 수 있는 상태와 구분되지 않았다.

- 저장 위치 또는 선택한 대상의 cfg/NIC가 없으면 회색 **환경 설정 필요**. 클릭하면 빠진 설정의 저장/CAN·Diag/Ethernet 탭을 연다.
- 저장된 경로만 있고 연결 확인을 하지 않았거나 cfg·기록 블록·채널 기준·NIC·TShark가 바뀌면 회색 **연결 확인 필요**. 클릭은 연결 탭만 열고 기록 요청을 보내지 않는다.
- 선택한 대상의 설정과 연결 확인이 끝나면 초록색 **기록 시작**. 사용하지 않는 대상은 요구하지 않는다. 시작 때 기존 런타임의 실제 파일/도구/측정 검사는 계속 수행한다.
- CANoe 창과 선택 블록이 확인되고 F9만 기다리는 경우는 주황색 **CANoe 측정 확인 후 시작**. 사용자가 외부 CANoe에서 번개를 켠 뒤 바로 시작할 수 있도록 현재 측정을 재검사하는 시작 요청을 허용한다. cfg/블록이 다르거나 라이선스·하드웨어 불일치·기존 기록 중 등은 이 경로로 우회하지 않는다.
- 다음/새 기록도 선택한 연결이 준비된 경우 초록색이다. 기록·취소·정지·파일 처리·복구·X의 우선순위와 정지 클릭은 유지한다. 모의 실행은 실제 설정을 요구하지 않는다.

UI에서 디스크·COM을 조회하지 않고 저장된 설정과 현재 실행의 확인 결과만 사용한다. 설정 변경 시 UI와 런타임의 이전 연결 확인을 무효화한다. 기록 시작 때 성공해 READY가 된 뒤에는 오래된 측정 대기 표시를 카드에 다시 덮어쓰지 않는다. 결과 안내와 상세 오류 메시지는 유지하며 설정 필요 안내는 버튼의 툴팁에도 표시한다.

사용법 첫 화면과 버튼 표·CANoe 측정 대기 설명을 갱신하고 현재 Qt 화면 사진 13장을 다시 촬영했다. 공식 가이드 개정은 `2026-10-23.6`이다. 실제 VN/차량 취득과 기존 Diag 누락 원인 분리 시험은 이 변경의 검증 범위가 아니다.

소스 전체 683개 검사 통과(57.93초). 초기 버튼 클릭이 시작 요청 없이 필요한 탭을 여는 실제 앱 실행, 저장된 설정만으로 시작하지 않음, 선택 대상만 확인, 설정 변경 후 확인 무효화, cfg/블록이 같은 F9 대기 경로와 차단 사례, 준비 상태에서 반복 시작·정지 우선순위를 검사했다. 한국어·영어·중국어의 360px 화면에서 네 상태의 12개 배치와 문구·가로 넘침을 확인했다. 가이드 19개 렌더 화면에서 사진·접힌 설명·확대/닫기·Esc를 확인했다. Ruff·의존성·diff 검사 통과.
