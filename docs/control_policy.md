## 2. 구현 구성

    작은 메인 팝업
        ├─ 설정: .cfg 슬롯, NIC, 공통 폴더, prefix/다음 번호, 도구 경로
        ├─ 대상별 실제 상태와 공통 logging 버튼
        ├─ 구조화 알림·동작 이력
        └─ 작업 이력 / 로그 폴더: 파일 처리 결과 / 캡처 저장 위치
                │
    세션 제어기 + 영구 저장소
        ├─ CANoe 1 전용 실행부 → 검증된 CANoe 참조·Logging Block
        ├─ CANoe 2 전용 실행부 → 검증된 CANoe 참조·Logging Block
        └─ Ethernet 실행부 → Wireshark 계열 도구·선택 NIC
                ├─ 원본 PCAP/PCAPNG
                ├─ 패킷 요약 → 통신 감시
                └─ NIC 링크 상태 → 공통 정지 판단

화면의 logging은 사용자 토글이다. 실행부에는 Start와 Stop을 명시적으로 전달해 재시도·중복 클릭이 반대 동작으로 뒤집히지 않게 한다.

각 대상 명령에는 세션 ID·명령 ID·대상 세대 번호를 넣는다. 실행부의 명령 수신, 적용 응답, 실제 기록 증거, 파일 완결을 구분한다. 이 필드와 명령 이름은 우리가 정의할 계약이며 CANoe 내장 API 이름이 아니다.

CANoe COM 작업은 해당 객체가 속한 실행 문맥에서 직렬 처리한다. Windows UI 스레드에서 COM이나 파일 종료를 기다리지 않는다. 호출 정체가 다른 대상 정지를 막지 않도록 대상별 실행부를 분리한다. 실행부의 시간 초과는 CANoe 기록 종료의 증거가 아니며 자동 COM 재접속으로 처리하지 않는다.

## 3. CANoe 실행·직접 편집·측정

- .cfg 전체 경로와 실제로 로드한 Configuration 경로를 확인한다. 서로 다른 폴더의 같은 기본 이름도 구분한다.
- 통합 프로그램이 생성한 대상과 제어 객체의 대응을 검증한다. 이미 열린 무관한 CANoe에는 연결하거나 새 구성을 덮어 열지 않는다.
- 동일 .cfg를 두 슬롯에서 사용하는 기능은 추가 식별 검증 전 차단한다. 같은 슬롯의 같은 구성을 다시 선택하면 기존 관리 창을 재사용하고 중복 실행하지 않는다.
- 다른 .cfg로 바꾸려면 해당 대상의 측정과 기록이 정지돼 있어야 한다. 측정 정지를 대신 수행하지 않는다. 미저장 변경에 관한 CANoe 확인 창이 나타나면 사용자가 처리하고 패널은 대기 상태를 알린다.
- 사용자가 CANoe 화면에서 프로젝트를 바꾸거나 창을 닫으면 기존 세대를 무효화한다. 다음 명령은 재검증된 참조만 사용한다.
- 사용자가 CANoe에서 측정을 시작해 유지한다. 패널은 기록 시작 직전에 측정 실행 여부와 정확한 Logging Block을 확인한다.
- 세션 출력 경로는 기록이 꺼진 대상 블록에만 적용하고 결과를 다시 읽는다. 다른 기록이 진행 중이거나 적용 결과가 다르면 시작을 보류한다.
- 사용자 편집 전체를 원복하지 않는다. 원본 .cfg 자동 저장·재로드를 하지 않는다. 사용자가 CANoe에서 직접 저장하는 동작은 CANoe의 일반 저장 범위를 따른다.
- 구간 종료는 대상 기록만 끝낸다. 측정·다른 블록·다른 CANoe를 정지하지 않는다. 기록 정지와 파일 완결을 확인한다. CANoe가 핸들을 보유해도 정지한 BLF의 변경 없는 완전 복사본을 보관하면 다음 기록을 허용한다. 파일 관리의 이름 변경·삭제에는 독점 핸들 정책을 유지한다.

COM Logging/Trigger를 우선 사용한다. CAPL은 기존 제어 연결이나 필요한 수신 관측을 COM에서 얻지 못하는 경우의 보조 경로다. 프로젝트 수정이 허용됐다고 가정하지 않는다.

## 4. Ethernet 기록과 수신 감시

### 4.1 우선 구현안

Wireshark에 포함된 TShark가 원본 캡처와 패킷 필드 출력을 담당하는 구성을 우선 실증한다. 공식 매뉴얼에는 파일 기록과 함께 패킷 출력을 사용하는 -w/-P, 필드 선택 -T fields/-e, 출력 반영 -l, 형식 지정 -F가 설명돼 있다. 실제 설치 버전의 조합·수행 부하는 별도 확인한다. [W1]

이 방식이면 원본 저장과 패킷 요약을 같은 캡처에서 얻을 수 있다. 별도의 GUI 버튼 조작·named pipe 연결·기록 파일 전체 반복 읽기를 필수로 두지 않는다. 높은 부하에서 요구를 충족하지 못하면 캡처와 해석 분리 구조를 다시 검토하며 미검증 상태로 배포하지 않는다.

도구 호출은 인자 배열로 구성한다. 사용자 경로를 셸 명령 문자열에 붙이지 않는다. 표준출력과 오류출력을 계속 읽고 외부 창을 띄우지 않는 실행부에서 관리한다.

라이브 기록과 표시 필터의 조합 제한을 고려해 원본 캡처에 -Y를 추가하지 않는다. 감시·표시 조건은 요약 출력 이후 적용한다. 캡처 필터를 나중에 추가하는 경우에도 별도 설정으로 명시하며 표시 필터와 혼동하지 않는다. [W1]

### 4.2 연결과 시작 확인

- 설정에서 도구 경로·버전과 NIC 식별자를 확인한다. 인터페이스 설명·식별자를 함께 표시하고, 지원되는 경우 MAC·링크 상태를 보조 표시한다.
- 연결 버튼에서는 도구 실행 가능 여부와 해당 NIC의 목록 조회만 확인한다. 취득을 시작하지 않으며 차량 통신 정상으로 표시하지 않는다.
- 실제 세션 시작 때 NIC 열기·파일 기록 준비·프로세스 오류를 확인한다. 단일 시작 문구나 파일 존재만으로 준비 성공을 확정하지 않는다. 패킷 0개인 상황에서도 기록 준비와 통신 미수신을 구분하는 방법을 실증한다.
- 처음에는 단일 NIC를 지원한다. 요청한 pcap/pcapng 형식을 명시하고 완성 파일의 실제 형식을 검사한다. 지원하지 않는 조합을 조용히 다른 형식으로 저장하지 않는다. [W2]
- 정상 정지는 숨김 실행부의 콘솔/프로세스 그룹 등 설치 버전에서 검증한 수단으로 요청한다. 대상 프로세스명 일괄 종료나 강제 종료를 정상 정지로 쓰지 않는다. 콘솔 이벤트에는 공유 콘솔·그룹 제약이 있다. [W3]

### 4.3 수신 감시 (0.9.13)

- 메인의 패킷 보기와 환경 확인을 제거했다. 완성된 원본 파일은 외부 Wireshark로 분석한다.
- dumpcap이 원본 파일을 쓰고 별도 TShark가 growing file을 읽어 감시한다. 일반 실행은 화면 패킷 IPC 전송을 하지 않는다. 명시적 localhost 검증에서만 요약 전송을 켠다.
- 기본 Zipy 규칙은 Source MAC 접두사 `02:00:00`, 시작 유예 5초, 미수신 3초, 2초 평균 100pps 미만 3초 지속이다. 다른 출처도 모두 저장한다. 확인한 기준 위반은 수신이 복구돼도 이번 구간의 정지 사유로 유지한다. 규칙 수정·삭제는 다음 구간부터 적용하며 캡처 필터를 추가하지 않는다.
- 선택한 NIC의 운영 상태를 읽는다. 단절과 필수 Source 미수신을 구분하고 인터넷 접속 유무는 판단하지 않는다. 관측 확인 불가는 5초 지속 시 정지한다. 정상 시작 유예/복귀 샘플 대기는 고장으로 오인하지 않는다.

## 5. 기록 상태와 예외 처리

### 5.1 시작

1. 선택 대상이 없으면 시작하지 않는다.
2. 연결 대상·측정·블록·도구/NIC·이름·폴더·쓰기 가능 여부를 확인한다. 명확한 채널 매핑 불일치는 차단한다. 실제 매핑 정보를 읽을 수 없으면 경고와 확인 불가를 유지하되 다른 기록 준비가 확인됐을 때 취득은 허용한다.
3. 세션 계획과 고유 임시 경로를 준비한다. 출력 경로 적용 및 읽기 확인까지 실패하면 번호를 예약하지 않는다.
4. 세션 ID·대상별 임시/최종 파일·적용 설정·예약 번호·다음 번호를 영구 저장한다. 실패하면 Start를 보내지 않는다.
5. Ethernet을 선택했으면 기록 준비를 먼저 확인하고 CANoe 구간 기록을 요청한다. Ethernet 미선택이면 CANoe 대상만 요청한다. 도구별 요청/확인 시각을 남긴다.
6. 선택 대상 모두의 시작이 확인되면 기록 중으로 전환한다. 이 전까지의 실패는 이번 요청이 시작한 구간만 정지하고 부분 파일을 보존한다.
7. 시작 중 logging을 다시 누르면 시작 취소/정지 요청으로 받아 새 세션을 만들지 않는다. 늦게 도착한 시작 응답도 세션/명령/세대 번호를 확인해 정리한다.

| 상황 | 동작 |
| --- | --- |
| 감시 기준 미설정 | 미설정 표시. NIC 단절·기록 도구 상태는 별도 감시 |
| CANoe 하나의 기록 중단·창 종료 | 모든 선택 대상 정지·닫힌 파일 보관, 실패 원인 유지 |
| Ethernet 단절·캡처 중단·필수 수신 규칙 위반 | 모든 선택 대상 정상 정지·닫힌 파일 보관, 실패 원인 유지 |
| 관측부만 오류, 파일 취득은 계속됨 | 확인 불가 표시. 5초 지속 시 모든 선택 대상 정지 |
| 대상 응답이 없어 기록 중단 여부도 모름 | 모든 선택 대상에 정지를 시도. 닫힘 미확인은 성공으로 보관하지 않고 확인 필요로 표시 |
| logging으로 정지 요청 | 이번 세션의 남은 모든 기록에 정상 정지 요청. 이미 실패한 대상도 실제 종료 여부 확인 |
| 모든 기록 종료 확인 | 파일별 검사·보관으로 전환. 실패가 있었던 세션을 전체 성공으로 바꾸지 않음 |

기록 도중 실패한 대상을 자동으로 같은 파일에 재시작하지 않는다. 시간 축에 설명 없는 공백이나 파일 교체를 만들지 않는다. 원클릭은 정확한 동시 취득·시간 동기화 보장이 아니다.

### 5.3 시간 제한

실행/구성 로드는 120초, 기록 시작 확인은 15초, 정상 정지는 30초를 초기 작업 제한으로 제안하고 PC 설정에서 조정한다. CANoe 후행 기록 시간은 정지 제한에 추가한다. 이는 도구 제어 제한이며 통신 미수신 판정 시간이 아니다. 시험 PC의 정상 소요 시간을 측정해 확정한다.

시간 초과는 자동 성공·자동 강제 종료로 처리하지 않는다. UI는 살아 있어야 하고 다른 대상의 정지 요청을 처리할 수 있어야 한다.

## 6. 파일 보관·번호·이름 변경·삭제

### 6.1 저장 위치

    지정한 공통 폴더/
    ├─ .vil_work/
    │   └─ 고유 세션 ID/
    │       ├─ VIL_7.blf
    │       ├─ VIL_Diag_7.blf
    │       └─ VIL_7.pcap
    ├─ VIL_6.blf
    └─ VIL_6.pcap

기록 중 실제 기본 이름은 최종 이름과 같다. 폴더만 임시 위치다. 메인에서는 지정한 보관 폴더를 표시하고 파일 상태와 실제 기록 경로를 확인할 수 있게 한다.

닫힘·읽기를 확인한 파일은 같은 파일명으로 공통 폴더 루트에 이동한다. 목적지가 있으면 교체하지 않고 임시 파일을 보존한다. 형식상 유효한 0패킷 파일도 '파일 보관 완료'와 '기대 데이터 수신 성공'을 구분한다.

### 6.2 영구 상태와 복구

- Windows 사용자별 로컬 앱 데이터에 SQLite 저장소를 둔다. 실제 위치는 설치/실행 환경에서 결정하며 프로그램 설치 폴더나 개발 PC 경로를 사용하지 않는다.
- 세션 예약·다음 번호 증가·출력 파일 계획을 한 트랜잭션으로 보관한다. 기록 전에 저장 결과를 확인한다.
- 제어 앱은 사용자 세션당 한 개만 실행하고 두 번째 실행은 기존 패널을 보여준다. 임시 파일의 UUID 세션 ID는 사용자 변경 가능한 파일 일련번호와 다르다.
- 명시적 번호 재지정은 허용한다. 이름 변경·삭제만으로 번호를 자동 되돌리지는 않는다. 번호는 정확한 십진 정수로 저장·계산하고 최종 이름의 길이도 검사한다.
- 비정상 종료 후 예약된 세션은 실패/폐기로 정리한다. 소유 작업 경로의 임시 파일만 삭제하고 완료 파일·다음 번호는 유지한다. 중단 파일을 성공으로 승격하지 않는다.
- 이전 CANoe 창으로 자동 접속하지 않는다. CANoe 기록이 남아 있을 수 있으면 사용자가 해당 창에서 확인하도록 안내한다. 소유·닫힘이 불명확한 대상의 새 기록을 차단한다.

### 6.3 파일 관리

각 파일에 예정/기록 중/종료 중/닫힘 확인/보관 완료/보관 실패/손상/확인 불가/삭제 결과를 보관한다. 세션 전체 상태만으로 개별 파일 성공을 추정하지 않는다.

직전 이름 변경은 입력 문자열을 기본 파일명으로 사용하고 인덱스를 생략하며 확장자를 유지한다. Diag 파일은 `_Diag`를 붙여 CAN 파일과의 이름 충돌을 막는다. 이름을 다시 파싱하지 않으며 원본/목적지 목록을 검사하고 작업 의도를 저장한 뒤 수행한다. 일부 성공이면 파일별 현재 경로를 갱신하고 부분 실패로 표시한다. 원복도 실패할 수 있으므로 '전부 한 번에 변경'을 보장하지 않는다.

삭제는 사용자에게 전체 경로·이름을 확인받고 파일별 결과를 기록한다. 자체 기록·닫힘 미확인·알려진 관찰 도구 사용은 차단하고 가능하면 배타적 파일 접근을 확인한다. OS 공유 조건상 외부 사용 중에도 삭제가 허용될 수 있어 모든 앱의 사용 여부 탐지는 보장하지 않는다. 강제 잠금 해제나 다른 앱 종료는 하지 않는다. [W4]

부분 삭제 후 남은 파일은 직전 로그 전체 삭제 대상으로 명확히 표시할 수 있다. 예상 파일이 누락된 세션의 이름 변경은 보류한다. 어느 파일을 처리하더라도 다음 번호는 자동 변경하지 않는다.

## 7. 감시와 이벤트 표시

감시는 선택 대상의 기록 시작 확인 후부터 기록 종료까지다. 전후에는 미감시, 기준이 없으면 설정 필요, 수신 정보가 없거나 지연되면 확인 불가다. 기록 도중 정상 수신 기준은 추후 제공 조건으로만 판정한다.

CAN 감시는 값 변경이 아니라 실제 수신 시각/이벤트를 사용한다. Ethernet은 감시 흐름에 속한 출처만 비교한다. 정상적인 다른 트래픽이 섞였다는 이유로 출처 불일치 경고를 만들지 않는다.

동일한 경고가 계속되면 발생/마지막 관측/횟수를 갱신하고 상태 전환·복구를 이벤트로 남긴다. 외부 오류는 앱의 한국어·영어·중국어 설명과 원문을 함께 보존한다. 사용자 후속 요청에 따라 화면은 최근 500건을 보여주며 세션의 중요 동작·오류 이력은 저장소에 남긴다. 0.7.0의 Ethernet 규칙과 관측 유효성, CAN/Diag 미지원 범위는 [7단계 결과](development_stage_7.md)를 따른다.

## 개발자로그 저장

사용자 후속 요청에 따라 개발자로그는 앱 시작부터 항상 저장한다. 배포 실행은 EXE 옆 `developer_logs/`, 소스 실행은 프로젝트의 같은 폴더에 저장하며 5MB 파일 하나와 최대 4개 순환 백업으로 제한한다. 명령·응답 식별자, 상태·처리 시간, 파일 작업과 감시 근거, 원문·예외 traceback과 실행환경을 기록한다. 상단 **버그리포트**로 최근 로그 ZIP을 바탕화면에 복사하고 Taegon.Kim에게 전달하도록 안내한다. 진단 실패·유실은 표시하되 그 이유만으로 취득 제어를 중단하지 않는다. 원본 패킷 payload나 파일을 자동 전송하지 않는다.

## 8. 창 종료

0.9.11부터 메인 X는 AutoLog와 이번 실행에서 생성한 전용 CANoe를 모두 종료한다. COM 복구나 파일 보관을 기다리지 않고 worker/job·검증된 CANoe 프로세스 핸들을 종료하며 약 1초의 독립 종료 제한을 둔다. 반복 X는 즉시 종료한다. 원래 cfg를 자동 저장하지 않으며 다른 CANoe는 종료하지 않는다.

중단 구간은 버리고 작업 파일을 삭제한다. DB에 폐기 의도를 먼저 기록하고 완료 파일·다음 번호는 유지한다. 파일이 잠겼거나 경로 검증에 실패하면 삭제를 보류하고 재시도하며 재실행을 차단하지 않는다. 임시 폴더가 이미 없어도 DB 이력을 정리한다.

트레이 아이콘/백그라운드 모드는 제거한다. 설정창·패킷 창의 닫기는 해당 창만 닫는다. 운영체제 강제 종료/전원 장애도 정상 완료로 간주하지 않으며 다음 실행에서 동일한 중단 폐기 정책을 적용한다.

## 개발 착수·운영 환경 보완

현재 사용자 확인 환경은 Windows 11 64비트, 팀 여러 PC, 로컬 디스크, 약 1분의 일반 구간과 30분 초과/1GB 초과 가능 로그다. 사용자는 VN 장비를 연결해 CANoe 라이선스를 인증한다.

앱은 오프라인으로 실행하며 외부 API·로그인·자동 전송·자동 업데이트·실행 중 다운로드를 사용하지 않는다. TShark 이름 해석을 끄고 설치 때 준비한 로컬 도구를 사용한다. 차량용 NIC와 VN 장비는 해당 취득에 필요하다.

기존 .cfg는 되도록 유지한다. CAPL·시스템 변수 정의를 자동 추가하지 않고 원본 .cfg/관련 소스를 자동 저장하지 않는다. 세션 출력 경로는 실행 중 해당 블록 설정에 적용할 수 있으나, 사용자 직접 저장이 없는 조건에서 원본 파일 보존을 실증한다. COM/기존 관측값으로 얻지 못하는 감시는 미지원/확인 불가로 표시하고 프로젝트 복사본 보조안은 별도로 검토한다.

Windows용 배포 폴더와 PC 프로필·번호 DB·실제 로그를 분리한다. 앱 교체로 로컬 상태를 덮어쓰지 않으며 실제 EXE에서 외부 도구의 DLL 검색·작업 프로세스·정상 정지를 확인한다. 대용량 파일 검사와 보관은 진행 상태를 표시하고 원본 취득 정지 시간 제한과 검사 시간 제한을 구분한다.

상세 기준은 [착수 전 종합 검토](development_readiness_review.md), [설치 목록](installation_matrix.md), [개발·검증·배포 순서](development_delivery_plan.md)에 기록한다.
