# 초기 요구사항 구현 검토 — 과거 기록

검토·보완일: 2026-10-17 (Asia/Seoul)
대상: 요구사항 55개, 검증 시나리오 66개, 제어 정책, 설계, 검증 계획.
이 문서의 판정표는 착수 당시 상태를 보존한 기록이다. 개발자로그 기본 OFF·최근 200개·창 숨김 등의 과거 항목을 현재 제품 동작으로 해석하지 않는다. 현재 작업별 구현 현황과 남은 일은 [구현 계획 5절·10절](implementation_plan.md), 최신 빌드 확인 범위는 [0.4.5 기록](hotfix_0_4_5.md)을 따른다.

## 1. 착수 당시 판정

통합 패널의 구현 경로는 있다. 처음 검토한 31개에 15개를 보완했으며, 이번 착수 전 검토에서 원본 구성 보존·운영 환경·오프라인·성능·팀 배포·유지보수 8개를 추가해 54개가 됐다. [제어 정책](control_policy.md)에 구체적인 명령·실패·파일 보관·복구 기준을 기록했다.

이후 사용자의 개발자 진단 파일 요청을 DEV-01로 추가해 현재 55개다. 메인 상단 작은 `개발자로그` 체크박스는 매 실행 OFF이며 켠 동안에만 회전 JSONL 파일을 남긴다. 대응 검증은 T-66이고 구현 작업은 IMP-01/02/07/11/14에 연결한다. Python 3.14.7 x64와 AppData 개발 가상환경·의존성을 준비하고 기본 Qt 앱·대상별 모의 실행부·SQLite·진단을 구현했다. 실제 CANoe/NIC는 열지 않았다.

사용자 직접 답변으로 확정한 세 항목:

1. 기록 도중 한 대상이 중단돼도 다른 대상은 계속 기록한다.
2. 사람이 확인할 화면은 출처·목적지·프로토콜·수신 시각과 최근 패킷 목록이면 충분하다.
3. 통신 이상 감시는 선택 대상의 로깅 중에만 수행한다.

따라서 별도 Wireshark GUI의 실시간 원격 조작은 필수 요구에서 제외하고, 통합 프로그램이 최근 패킷 목록을 제공한다. 파일 기록과 패킷 요약을 함께 얻는 TShark 구성을 우선 실증한다.

**설계 선택으로 보완된 항목과 제품·장비 실증이 필요한 항목을 구분한다.** 문서가 작성됐다는 이유로 복수 CANoe 제어·파일 완결·캡처 성능 검증이 끝났다고 표시하지 않는다.

## 4. 아직 실증해야 하는 핵심 기능

| 순서 | 실증 | 통과 기준 |
| --- | --- | --- |
| P-01 | 실제 .cfg 한 개를 통합 실행부로 열어 제어 참조 확인 | 무관한 기존 창을 인계하지 않고 구성 전체 경로·블록·측정 상태 일치 |
| P-02 | 측정 유지 중 기존 구간 기록을 외부에서 3회 제어 | 매회 지정 이름의 독립 BLF 완결, 다른 블록·측정 유지 |
| P-03 | 두 .cfg를 각각 생성·제어 | A만/B만/양쪽 제어와 한쪽 종료에서 대상 혼동 없음 |
| P-04 | 한 NIC의 TShark 기록+필드 출력 | pcap/pcapng 형식·0패킷 준비·정상 정지·재시작·실제 파일 읽기 확인 |
| P-05 | 실제 부하에서 최근 목록·감시와 기록 병행 | UI 지연·해석 지연·캡처 누락을 측정하고 지원 범위 확정. 화면 닫기/일시 정지/필터는 원본과 감시에 영향 없음 |
| P-06 | 시작 단계 실패와 기록 도중 한쪽 중단 | 시작 실패는 이번 시작만 정리. 도중 실패는 다른 기록 유지. 공통 정지 후 파일별 결과 표시 |
| P-07 | 번호 예약 후 중단·재시작·보관 충돌·부분 파일 작업 실패 | 다음 번호·미완료 경로 회수, 기존 파일 덮어쓰기와 전체 성공 오표시 없음 |

P-01~P-03으로 CANoe 제어 경로를, P-04~P-05로 Ethernet 연동 구성을 확정한다. 실패하면 지원되는 대안을 조사하며 마우스 제어·강제 종료·다른 창 연결로 자동 전환하지 않는다.

CAN 수신 근거와 채널 API는 별도 현장 확인이 필요하다. CAPL 보조가 필요한 경우에 프로젝트 수정 허용 여부를 확인한다. 소스·주기·임계값은 사용자가 추후 제공하기로 한 상태를 유지한다.

## 5. 이번 변경 범위와 확인 한계

요구사항·설계·검증/작업 대응에 DEV-01/T-66을 추가하고 현재 구현 상태를 반영했다. 기본 데스크톱 실행 코드·Qt 화면·모의 세션·SQLite·진단을 구현했으며 기존 HTML 시안은 유지한다. 실제 CANoe/NIC 열기·실제 로그 취득·파일 관리·팀 배포는 수행하지 않았다.

문서 정합성 검사는 현재 55개 요구사항의 검토 표·작업표·66개 검증 시나리오 대응과 로컬 링크를 확인한다. 시나리오 수는 자동 검사 수나 실제 시험 통과 수를 뜻하지 않는다. 로컬 파일·COM 등록·버전 등 환경 진단은 실행했으나 도구 동작·라이선스·장비·프로젝트 취득 실증의 근거로 사용하지 않는다. 최신 검사 결과와 한계는 [1단계 개발 결과](development_stage_1.md)에 기록한다.

초기 논의의 공식 근거와 경로별 상세 검토는 [이전 구현 가능성 검토](implementation_feasibility_review.md)에 남아 있다. 그 문서의 과거 선택지보다 현재 요구사항과 제어 정책을 우선한다.
