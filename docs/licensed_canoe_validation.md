# 라이선스 PC의 실제 CAN/Diag 기록 검증

2026-10-19 · **아직 수행하지 않은 현장 시험 절차**. 구성 열기·COM API 존재 확인·대역 검사만으로 아래 결과를 통과 처리하지 않는다.

## 준비

1. CANoe 빌드·라이선스 활성/측정 가능 여부, VN 모델·드라이버·CAN/Diag의 실제 채널을 기록한다. View Only 상태에서는 기록 시험을 진행할 수 없다.
2. 대표 CAN/Diag cfg와 필요한 데이터베이스/CAPL 등 의존 파일을 준비한다. 원본은 별도 보관하고 시험 전후 해시를 비교한다. 기존 CAPL 자동시험·송신·로깅 버튼의 실행 상태를 확인한다.
3. AutoLog에서 빈 시험 출력 폴더, 구분 가능한 prefix/시작 번호를 지정한다. 기본 선택 CAN·Zipy 중 시험할 대상만 체크한다.
4. CAN·Diag 카드에서 서로 다른 cfg를 지정하고 연결 확인한다. **서로 다른 CANoe PID와 정확한 cfg**가 표시되는지 확인한다. CAN의 `CAN_Logging` BLF, Diag의 `Logging` BLF를 선택한다. CAN의 `ETH_Logging` PCAPNG는 CAN BLF 대상이 아니다.
5. 독립 연결 설정이 처음 필요한 경우 기존 CANoe 작업을 저장하고 창을 닫은 후 다시 연결한다. AutoLog가 원본 can.ini를 백업하고 필요한 모드를 준비한다. 공유 창을 대신 제어하지 않는다.
6. 시험 환경의 절차에 따라 사용자가 각 전용 CANoe 창에서 측정을 시작한다. 다른 로깅 버튼을 누르지 않고 선택 블록의 기록은 정지 상태로 둔다. AutoLog에서 연결 확인 후 기록 준비 상태를 확인한다.

## 기본 구간 기록

| 시험 | 반복 | 확인할 결과 |
| --- | --- | --- |
| CAN 단독 | 3회 | 매회 새 BLF, 번호 한 번 증가, 기대 CAN/CAN FD 채널·ID/시간 구간 확인 |
| Diag 단독 | 3회 | 매회 `_Diag_` 이름의 새 BLF, 기대 진단 통신 확인 |
| CAN+Diag | 3회 | 같은 번호의 BLF 2개, 서로 다른 cfg/PID, 한쪽 제어가 다른 블록에 영향 없음 |
| CAN+Zipy, Diag+Zipy, CAN+Diag+Zipy | 각 1회 이상 | 같은 번호의 선택 파일만 생성, 보관 경로·확장자 일치, 시작 시간차를 기록 |
| Zipy 단독 | 1회 이상 | 차량 NIC로 pcap/pcapng 기록 확인. localhost 결과와 구분 |

각 회차는 `logging` 시작 → 시험 통신 확인 → `logging` 정지 순서로 수행한다. 처음에는 10초 정도의 짧은 구간으로 파일 생성/닫힘부터 확인하고, 성공 후 조건별 장시간 시험으로 확장한다.

정지 후 CANoe **측정이 계속 실행**되는지, 선택 블록의 출력 경로와 자동 증가/분할 옵션이 이전 값으로 복구됐는지 확인한다. 보관된 BLF를 CANoe/검증된 뷰어로 실제 열어 필요한 프레임과 시간 범위를 확인한다. AutoLog의 구조 검사만으로 내용 검증을 대신하지 않는다. 0프레임 파일은 보관 성공일 수 있지만 기대 통신 시험의 성공은 아니다.

## 이상 조건 — 준비된 시험 환경에서만 수행

- 설정의 기록 블록 변경/삭제/순서 변경 후 연결 확인 없이 logging: 시작 차단, 새 번호 예약과 다른 블록 제어 없음. 다시 연결 확인하면 의도한 블록으로 재선택 가능.
- 미리 기록 중인 선택 블록: 시작 차단, 기존 기록 유지.
- 한 대상 시작 실패: 이번 시도에서 시작한 나머지 구간만 정리, 예약한 번호 유지, 부분 파일 보존.
- 기록 중 한 CANoe 측정/창이 외부에서 정지됨: 다른 기록 유지, 실패 대상·시각 표시. 차량과 장비에 영향을 주는 조작은 시험 담당자가 통제한다.
- 한쪽 정지 응답 지연: 다른 쪽은 정지·보관, 미확인 쪽은 미완료. 재시도 후 먼저 보관한 파일의 경로·검사 결과·내용 유지.
- CANoe 외부 파일명/옵션 수정 충돌: 임의 덮어쓰기/다른 기록 정지 없음. 복구 실패를 안내하고 원래 설정의 스냅샷 보존.
- 파일명 충돌·저장 권한/용량 부족·파일 열림: 기존 파일 유지, 실패 경로 확인. 소유권이 불명확한 임시 파일 자동 삭제 없음.
- 메인 X: 활성 구간 정상 정리 후 AutoLog 종료. CANoe 측정/창 유지. 미확인 기록/출력 복구는 종료 보류.

## 결과와 전달 자료

회차마다 AutoLog 버전, 도구/드라이버 버전, 선택 조합·cfg 별칭·PID·블록, 측정 유지 여부, 원래/복구 출력 옵션, 파일명·크기·구조 검사와 실제 프레임 확인 결과, 시작/정지 시각·오류를 기록한다. 업무 원본과 상세 경로는 로컬에 두고 Git에는 익명화한 요약만 남긴다.

문제가 생기면 강제로 정리하기 전에 **버그리포트**를 눌러 바탕화면 ZIP과 발생 시각·조작 순서를 Taegon.Kim에게 전달한다. 자동 이메일 전송은 없다. 실제 BLF/PCAP 추가 전달이 필요한 경우 개발자로그 ZIP과 별도 자료로 취급한다.
