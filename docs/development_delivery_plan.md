# 개발·검증·배포 실행 계획

작성일: 2026-10-17 (Asia/Seoul)
상태: 요구사항 55개·검증 시나리오 66개 기준. 1단계 기본 앱·모의 실행·저장·진단 기반을 구현하고 Python 3.14.7 x64·AppData 가상환경·의존성을 준비했다. 실제 CANoe/Ethernet 연동·시험 PC 취득·팀 배포는 미실행이다. 최신 결과는 [1단계 개발 결과](development_stage_1.md)를 따른다.
기준: [요구사항](requirements.md), [제어 정책](control_policy.md), [착수 전 검토](development_readiness_review.md), [설치 목록](installation_matrix.md).

## 3. 최초 핵심 설계 계약

- Canonical 역할: CAN, DIAG, ETHERNET. 표시 이름 CAN·Diag·Zipy와 실제 도구를 구분한다.
- CapturePlan은 예약 후 불변이다. 이름 생성은 역할·prefix·인덱스·확장자를 자료로 받아 처리하며 기존 파일명을 파싱해 인덱스를 추측하지 않는다.
- Settings 적용은 전체 입력·대상 파일명·현재 폴더 충돌을 검사하고 한 번에 반영한다. 시작 전에는 실제 상태·파일 시스템을 다시 검사한다.
- Prepare/Start/Stop/Query는 역할별 어댑터 계약이며 제품 내장 API 이름이 아니다. 명령·세션·세대로 지연 응답을 구분한다.
- 저장소는 번호 예약/세션/파일 계획을 함께 영구 저장한다. 외부 Start 전 저장 실패는 기록 시작을 차단한다.
- 파일 보관/이름 변경/삭제는 파일별 작업 의도와 결과를 기록한다. 일부 성공·중단 뒤 실제 경로를 회수한다.
- UI와 원본 취득·관측을 분리한다. 화면 필터/일시 정지/버퍼 교체는 데이터 취득을 제한하지 않는다.
- 원본 .cfg/CAPL/시스템 변수 자동 추가·저장은 하지 않는다. 실행 중 출력 설정 적용은 해당 세션 항목에 한정한다.
- DEV-01은 초기 구현부터 적용한다. 메인 상단 작은 `개발자로그`는 매 실행 OFF, 켠 동안만 별도 회전 JSONL에 명령/응답·세션/대상/명령 ID·상태·경과시간·오류 원문/traceback·버전을 남긴다. 해제/종료 시 flush/close하며 진단 오류를 알리되 취득 제어를 막지 않는다. T-66으로 파일 수명·용량/큐 제한·실패 영향을 검사하고 실제 도구 연동 뒤 같은 경로를 검증한다.

## 5. PC별 설치 확인 절차

1. 외부 도구 경로·버전과 VN 장비 인증·CANoe 측정 가능 상태를 확인한다.
2. 캡처 도구가 선택 NIC를 조회할 수 있는지 확인한다. 연결 확인만으로 기록을 시작하지 않는다.
3. CAN/Diag .cfg와 기록 블록·전체 경로가 일치하는지 확인한다.
4. 로컬 폴더를 지정하고 이름 규칙·예상 파일명·번호를 확인한다.
5. 실제 짧은 구간을 선택 대상별/전체로 취득하고 정지한다.
6. CANoe 측정 유지·파일 보관·다음 번호·패킷 목록·오류 이력을 확인한다.
7. 인터넷 연결 없이 같은 동작을 수행한다. 차량용 NIC와 VN 장비 연결은 유지한다.
8. PC 프로필과 통과한 도구 조합을 저장한다. 다른 PC 식별자를 그대로 복사하지 않는다.

설치 확인 도구가 임의 측정 시작·실제 캡처·드라이버 재설정까지 수행하지 않게 한다. 실제 취득 시험은 그 동작을 실행하는 명시적 단계로 구분한다.

## 7. 업데이트와 유지보수

실행 파일 폴더와 PC 프로필/번호 DB/로그를 분리한다. 기록/종료/확인 불가 세션이 남은 상태에서 업데이트하지 않는다.

DB 스키마는 버전으로 관리하고 변경 전 백업·이행·호환성 확인을 한다. 과거 DB 복원으로 이미 사용한 번호를 되살리지 않는다. 앱 파일만 이전 버전으로 바꾸는 경우에도 현재 DB를 읽을 수 있는지 확인한다.

오류 보고에는 앱·도구 버전·세션 ID·대상·시간·이벤트 코드·실제 파일 경로를 포함한다. 로그 원본 전송은 자동화하지 않으며 공유 자료는 사용자가 선택한다.

문제를 재현할 때 `개발자로그`를 켜고 재현 후 해제해 진단 파일을 닫는다. 폴더 열기로 JSONL 및 관련 회전 파일을 확인해 사용자가 전달한다. 진단 파일과 일반 동작 이력·차량 캡처 원본은 저장 목적이 다르며, 개발자 로그 OFF에서도 SQLite 동작 이력은 유지한다. 실제 취득 중 진단 디스크/큐 오류가 정지 명령이나 상태 처리를 방해하지 않는지 T-66과 대표 PC 시험에서 확인한다.

발표용 성과는 버튼 수·취득 준비/종료 시간·파일 이름 실수·파일 대응 오류·문제 발견 시각 등 실측 자료로 남긴다. 아직 측정하지 않은 개선율과 검출 성능은 발표 수치로 만들지 않는다.
