# 0.8.5 화면 정리와 진단 로그 검증

업데이트: 2026-10-19. 실제 CANoe 측정·차량 고부하 취득은 이 변경의 검증 범위에 포함하지 않는다.

## 요청 반영 순서

1. Ethernet의 설치/복구·설치 링크·다시 찾기·버퍼 선택을 제거했다. TShark는 직접 선택하며 경로를 기억한다. 설정창과 네트워크 목록을 열면 네트워크를 갱신한다. 새 도구를 선택해 저장하면 다시 확인한다.
2. 메인의 로그 폴더 버튼은 설정된 캡처 저장 폴더를 연다. 개발자로그 위치와 구분한다.
3. 버그리포트의 실제 파일 내용을 대조하고 ZIP에 파일별 원본 크기·SHA256 목록을 추가했다. ZIP CRC와 압축 해제 내용의 크기·해시를 검증한 뒤 완성본을 공개한다. 파일명은 `AutoLog_BugReport_To_Taegon.Kim_<시각>_<식별자>.zip`이며 팝업에 이메일 주소를 넣지 않는다.
4. 네트워크 드롭다운 오른쪽에 최근 24개 수신량 그래프와 pps를 표시한다. 설정의 Ethernet 탭이 보일 때만 1초 주기로 Windows 카운터를 읽는다. 별도 캡처 프로세스·파일을 생성하지 않는다. 목록을 펼친 중에는 인벤토리 결과로 행을 교체하지 않아 선택을 보호한다.
5. 언어 버튼을 `한 | EN | 中` 하나로 통합했다. 클릭 시 한국어→영어→중국어 순환, 활성 언어 강조, SQLite 저장·재실행 복원을 지원한다. 메인·설정·패킷·파일 관리·감시·복구·품질 및 구조화된 활동을 번역한다. 외부 오류·도구 버전·기술 상세 원문은 보존한다.
6. 시작 시 CAN·Zipy 선택, Diag 해제로 설정했다. 선택 자체는 연결을 시작하지 않는다.
7. 메인의 큰 로그 캡처 제목과 옆 상태 배지를 제거했다. 실제 안내·로깅 버튼 아래의 상태는 유지한다.
8. 설정창의 프로그램 종료 버튼을 제거했다. 설정 닫기는 설정창만 닫고 메인 X는 기존 정상 정지를 거쳐 전체 종료한다.

## 버퍼와 그래프의 의미

캡처 버퍼는 드라이버에 요청하는 순간 수신 메모리이며 64 MiB로 고정한다. 오래된 128/256 MiB 설정도 64로 정규화한다. 실제 적용량이나 무손실을 보장하지 않으며 로그 파일의 최대 크기를 뜻하지 않는다. 로그는 계속 디스크로 기록한다. [TShark 매뉴얼의 -B](https://www.wireshark.org/docs/man-pages/tshark.html)를 따른다.

그래프는 [GetIfTable2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getiftable2)의 [MIB_IF_ROW2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/ns-netioapi-mib_if_row2) 수신 유니캐스트·비유니캐스트 패킷 카운터 차이다. GUID로 캡처 인터페이스와 매칭하며 인덱스 변동·카운터 초기화·장치 교체·관측 중단을 트래픽 급증으로 표시하지 않는다. 처음/확인 불가 구간은 `—`로 표시한다. 장치 제거 뒤 이력도 제한된 시간 후 정리한다. 다른 프로그램의 트래픽도 포함하므로 그래프 움직임만으로 차량 통신 정상이나 실제 캡처 성공을 판정하지 않는다.

## 실제 버그리포트 대조

사용자 바탕화면의 `AutoLog_BugReport_20261018_232035.zip`은 18,508바이트였다. 내부 JSONL은 압축 해제 시 208,566바이트였고 ZIP CRC가 정상이었다. 0.8.4 원본 JSONL의 앞 208,566바이트와 SHA256 `85518595909eda286e8dd4c04674cc1d0a24babbb2153169c1e5210fd46242bb`이 일치했다. 대조 시점의 원본은 이후 기록이 붙어 645,187바이트였다. 압축과 내보내기 이후의 증가로 인한 차이이며 해당 스냅샷의 내용 누락은 없었다.
