1. 처음 사용하는 PC에서 준비하기

  1. 배포 ZIP 전체를 쓰기 가능한 로컬 폴더에 압축 해제하고 AutoLog.exe를 실행합니다. EXE 옆의 _internal 폴더를 함께 유지하세요.
  2. 필요한 외부 도구를 별도 설치 안내에 따라 준비합니다. AutoLog 실행을 위해 Python·Git·개발 도구를 설치할 필요는 없습니다.
  3. 톱니바퀴 설정에서 연결과 저장 위치를 준비합니다. 기본 선택은 CAN·Zipy이며, 사용하지 않는 대상은 메인에서 해제합니다.

2. Windows Defender에 Vector 앱 허용하기

Documents 같은 보호 폴더의 프로젝트에서는 제어된 폴더 액세스가 CANoe 또는 CAPL 컴파일러의 파일 저장을 막을 수 있습니다. 처음 사용하는 PC에서 허용 여부를 확인하고, 차단된 경우 아래 절차로 등록하세요.

  1. 진행 중인 기록과 필요한 작업을 정리하고 CANoe를 닫습니다.
  2. Windows 보안 → 바이러스 및 위협 방지 → 랜섬웨어 방지 관리 → 제어된 폴더 액세스를 통해 앱 허용을 엽니다.
  3. 허용된 앱 추가에서 최근 차단 앱 또는 모든 앱 찾아보기를 이용해 아래 두 실행 파일을 추가합니다.
C:\Program Files\Vector CANoe 19\Exec64\CAPLcompExec.exe
C:\Program Files\Vector CANoe 19\Exec64\CANoe64.exe

CAPLcompExec.exe는 CAPL 컴파일러, CANoe64.exe는 CANoe 본체입니다. 위 경로는 CANoe 19의 기본 설치 예시이므로 실제 설치 위치의 정상 Vector 실행 파일을 선택하세요. 설치 버전이 다르면 그 버전의 경로를 확인합니다.

  1. CANoe를 완전히 다시 실행해 Diag cfg를 열고 CAPL을 재컴파일합니다.
  2. CBF 쓰기 오류가 사라졌는지 확인하고 F9 측정 → Trace 수신 → 수동 기록을 확인한 뒤 AutoLog에서 연결 확인을 다시 누릅니다.
회사 PC에서 설정이 잠겨 있나요?PC 관리자에게 위 두 파일의 제어된 폴더 액세스 허용을 요청하세요. 보호 기능 전체를 끄거나 CAPL 소스를 수정할 필요는 없습니다. AutoLog가 보안 설정을 자동 변경하지는 않습니다.

확인된 사례: Error writing binary file '...cbf': 액세스가 거부되었습니다. Windows Defender 이벤트 1123에서 컴파일러 쓰기 차단을 확인했습니다. 허용 후 다른 컴파일 오류가 나오면 해당 오류는 별도로 확인해야 합니다.

참고: Microsoft 허용 앱 안내. 본 가이드는 오프라인에서도 읽을 수 있으며 참고 링크를 여는 경우에만 인터넷을 사용합니다.

3. CAN·Diag 연결 준비

cfg 선택·연결 확인CANoe에서 F9·Trace 확인AutoLog 연결 재확인
  1. 설정 → CAN·Diag 구성에서 CAN과 Diag 각각 사용할 cfg를 지정합니다. 두 대상은 서로 다른 cfg를 별도 CANoe 창으로 엽니다.
  2. 사용할 카드의 연결 확인을 누릅니다. 표시되는 cfg와 CANoe PID를 확인하세요. 기존 CANoe 창을 모두 닫으라는 안내가 나오면 작업을 정리한 뒤 다시 연결합니다.
  3. 그 cfg의 BLF 기록 블록 하나를 선택합니다. 하나면 자동 선택합니다. 대표 구성에서는 CAN은 CAN_Logging, Diag는 Logging이며 실제 이름은 cfg에 따라 다릅니다. PCAPNG 블록은 CAN/Diag BLF 대상으로 선택할 수 없습니다.
  4. AutoLog가 연 해당 CANoe 창에서 CAPL 컴파일, 실제 장치·포트 채널 매핑, cfg가 요구하는 버스 옵션 라이선스를 확인합니다. F9로 측정을 시작하고 Trace에서 기대한 CAN 메시지 수신을 확인합니다.
  5. AutoLog의 연결 확인을 다시 눌러 구간 기록 준비 상태를 확인합니다. 측정은 유지하고 메인의 logging으로 구간 기록을 제어합니다.

CAN (available) / Ethernet (missing)이면 해당 cfg에 필요한 Ethernet 옵션을 사용할 수 없는 상태입니다. 라이선스 활성 상태 또는 시험 담당자가 준비한 적합한 cfg를 확인하세요. Zipy 체크 해제나 BLF 블록 선택은 cfg의 요구 옵션을 제거하지 않습니다.

프로젝트의 Logging 패널 버튼과 AutoLog는 별도 제어입니다. AutoLog는 선택한 BLF 블록을 직접 제어하므로 패널 배경색만으로 AutoLog 기록을 판단하지 마세요. 기록 중 수동 패널·파일명·분할 옵션을 함께 조작하지 않습니다.

먼저 수동 기록을 시험했다면 해당 기록만 수동으로 정지하고 F9 측정은 유지한 뒤 AutoLog의 logging을 누르세요. 같은 cfg·블록에서 수동 시험이나 자동 번호 증가로 BLF 파일명만 바뀐 경우 연결을 다시 할 필요가 없습니다. AutoLog는 시작 직전 파일명·옵션을 보관하고 구간 정리 후 그 값으로 복구합니다. 블록 선택·구조를 바꿨다면 연결을 다시 확인하세요.

채널 기준을 사용할 때

조회 가능한 로컬 장비의 CAN 번호·시리얼·물리 포트를 확인한 뒤 채널 기준 저장을 누르면 다음 연결/시작 때 비교합니다. 기준과 다르거나 저장한 기준을 확인하지 못하면 시작이 차단됩니다. 장치를 바꾼 경우 실제 매핑 확인 후 새 기준을 저장하거나 해제하세요. 원격/가상 장치·드라이버/API 조회 불가는 확인 불가로 표시하며, 기준 일치는 실제 차량 수신 성공과 구분합니다.

4. Zipy 네트워크 준비

  1. 설정 → Ethernet 연결 → 직접 선택에서 설치된 tshark.exe를 고릅니다. 같은 설치 폴더에 dumpcap·capinfos가 있어야 합니다.
  2. 장비에 연결된 네트워크를 이름으로 선택합니다. 목록 오른쪽 그래프는 해당 어댑터 전체의 수신량이므로 참고용으로 사용하세요.
  3. 저장 형식 pcap(기본) 또는 pcapng를 선택하고 연결 확인을 누릅니다. 실제 취득은 메인의 logging을 눌러 시작합니다.

TShark 경로·네트워크·형식을 기억합니다. 필요한 도구는 별도 설치 안내를 따릅니다. 캡처 버퍼는 고정이며 저장할 수 있는 파일의 최대 크기를 뜻하지 않습니다.

5. 저장 설정과 기록 시작·정지

  1. 설정 → 저장 설정에서 저장 위치를 선택하고 파일 prefix와 다음 저장 인덱스를 입력한 뒤 적용합니다. 파일·네트워크 경로 선택은 자동으로 기억하며 prefix·다음 번호는 적용 후 사용합니다.
  2. 메인의 CAN·Diag·Zipy 중 이번에 사용할 대상을 선택합니다. 준비되지 않은 대상은 해제하거나 먼저 연결을 준비하세요.
  3. logging을 눌러 시작하고 대상별 기록 상태를 확인합니다. 종료할 때 같은 logging 버튼을 다시 누릅니다.
  4. 정지와 파일 검사·보관이 끝날 때까지 기다린 뒤 최종 파일명과 저장 위치를 확인합니다. 일부 실패·미완료 표시는 전체 성공을 뜻하지 않습니다.
prefix = AutoLog, 인덱스 = 7생성 파일
CANAutoLog_7.blf
DiagAutoLog_Diag_7.blf
ZipyAutoLog_7.pcap 또는 AutoLog_7.pcapng

prefix 뒤에 _를 붙여 번호와 구분합니다. 이미 끝에 있으면 중복하지 않습니다. 선택하지 않은 대상의 파일은 만들지 않습니다. 번호 예약 후 부분 실패한 경우 번호를 자동 재사용하지 않으며 이름 변경·삭제도 다음 번호를 되돌리지 않습니다.

기록 중에는 대상·저장 규칙을 바꾸지 마세요. AutoLog의 정지는 이번 기록 블록의 구간만 끝내며 CANoe 측정 자체는 유지합니다. 공통 시작 버튼이 장비 간 정확한 시작 시각 일치나 시간 동기화를 보장하지는 않습니다.

6. 완료 파일 관리와 임시 폴더

  • 로그 폴더는 사용자가 지정한 캡처 저장 폴더를 엽니다.
  • 이름 변경은 입력한 이름을 그대로 사용하며 번호를 붙이지 않습니다. 확장자는 유지하고 Diag에는 _Diag가 붙습니다. 예: 주행 기록.blf, 주행 기록_Diag.blf.
  • 직전 로그 지우기 / 파일 관리에서 대상 경로를 확인한 뒤 삭제합니다. 영구 삭제 확인 후에는 휴지통을 거치지 않습니다.
  • .vil_work는 기록·검사를 위한 임시 작업 폴더입니다. 정상 보관과 소유 작업의 정리가 끝나면 정리하며, 실패·미완료 파일은 보존할 수 있습니다. 기록 또는 복구가 진행 중이면 직접 지우지 마세요.

사용 중·외부 변경·닫힘 미확인 파일은 처리가 보류될 수 있습니다. 파일 관리의 결과와 실제 경로를 확인하세요. 설정·번호·이력은 PC/Windows 사용자별로 기억합니다.

7. 최근 활동·패킷 보기·통신 감시

  • 최근 활동은 500건까지 표시합니다. 전체/경고·오류/오류 필터와 항목 복사로 발생 시각·원문·상세를 확인할 수 있습니다.
  • 패킷 보기의 필터·일시 정지·창 닫기는 원본 저장을 중단하지 않습니다.
  • 통신 감시 → 감시 기준에서 Zipy의 목적지·프로토콜·기대 출처·시간 기준을 저장하면 다음 기록부터 적용합니다. 기본 판정 기준은 비어 있으며 CAN·Diag의 실제 수신 감시는 현재 미지원입니다.
  • 기록 품질에서 파일 증가·해석 지연·표시 누락·디스크 여유를 확인합니다. 화면 표시 누락과 원본 파일 손실은 다릅니다. 원본 누락 통계가 없으면 확인 불가입니다.

통신 경고만으로 기록을 자동 정지하지 않습니다. 한 대상이 실패하면 나머지 기록 상태도 확인하고 logging으로 정상 정리하세요. 상단 한 | EN | 中 버튼으로 언어를 바꿀 수 있습니다.

9. 버그리포트 보내기

  1. 문제 발생 시 상단 버그리포트 버튼을 누릅니다.
  2. 바탕화면의 AutoLog_BugReport_To_Taegon.Kim_날짜_시각_고유번호.zip을 확인합니다.
  3. 발생 시각, 선택한 대상, 누른 버튼 순서, 필요하면 CANoe Write 창 오류를 함께 적어 Taegon.Kim에게 해당 파일을 이메일로 보냅니다. 앱에서 자동 발송하지 않습니다.
