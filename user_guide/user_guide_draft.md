# AutoLog 사용자 가이드 (시험용)

업데이트: 2026-10-19 (Asia/Seoul)
상태: 요구사항 55개·검증 시나리오 66개 기준. 실제 Ethernet 기록·파일 검사/보관·이름 변경/삭제·패킷 보기 구현, CANoe 구간 기록 연동 구현·대표 .cfg 현장 검증 및 차량/부하/장시간·팀 배포 전.

## 1. 현재 제공 상태

현재 소스 버전은 0.8.6이며 [전체 검토·수정 결과](../docs/project_audit_0_8_6.md), [화면·언어·네트워크 그래프 변경](../docs/ui_update_0_8_5.md), [CANoe 자동 독립 연결](../docs/canoe_independent_connection.md), [기록 품질·부하 검사](../docs/development_stage_8.md), [통신 감시 안내](../docs/development_stage_7.md), [미완료 복구 안내](../docs/development_stage_6.md)를 참고한다. 기존 HTML 시안과 실제 앱 화면은 구분한다. Zipy 실제 기록·정지·패킷 보기·파일 검사와 보관, Ethernet 감시·품질, 파일 관리·수동 복구, 설정/번호 보존·환경 확인·상시 개발자로그·버그리포트를 제공한다. 배포 EXE 검증 여부는 해당 릴리스 문서를 따른다.

**CAN·Diag 동시 연결:** 독립 연결이 꺼져 있으면 두 번째 구성을 별도 창으로 열 수 없다. 연결 카드의 **독립 연결 설정…**에서 안내를 확인하고, CANoe 작업 저장·모든 CANoe 창 닫기 → 상태 다시 확인 → 다중 연결 적용 → 닫기를 수행한다. 저장된 CAN·Diag의 연결을 다시 확인한다. 설정 변경은 설치본 전체에 적용되며 원본 백업을 남긴다.

**기록 품질:** 메인에서 버튼을 열면 파일 크기·증가 속도·해석 속도/지연·화면 큐 누락·오류·디스크 여유를 확인한다. 캡처 버퍼는 64 MiB 고정이며 선택란은 없다. 순간 수신 메모리 요청량으로 파일 크기 제한이나 무손실 보장값이 아니다. 종료 파일의 드라이버/OS 누락 통계가 없으면 확인 불가로 표시한다. 화면 누락과 원본 누락은 구분한다. 디스크 여유 1 GiB 이하는 경고하며 다음 기록 전 저장 위치를 확인한다. 상세 부하 시험 방법과 측정의 한계는 8단계 문서를 따른다.

**통신 감시:** 메인에서 **통신 감시 → 감시 기준**을 연다. 목적지·프로토콜·기대 출처와 미수신 시간·유예·허용 해석 지연·복귀 연속 수신 횟수를 시험 기준에 맞게 직접 저장한다. 기본 판정값은 없으며 규칙은 다음 기록부터 적용된다. 실제 기록 중 선택한 대상만 감시하고 경고만으로 기록을 정지하지 않는다. 패킷 표시 필터·화면 일시 정지·표시 큐 누락은 원본 저장과 감시를 제한하지 않는다. CAN·Diag의 수신 이벤트/채널 감시는 현재 미지원이며, 기록 제어와 구분해 표시한다.

**현재 실제 기록 순서:** Ethernet 연결에서 장비의 네트워크와 형식(pcap 기본)을 확인하고, 저장 설정에서 폴더/파일 규칙을 정한다. 메인에서 Zipy만 체크하고 logging으로 시작·정지한다. 정상 정지와 파일 검사가 끝나면 저장 폴더 루트로 보관한다. 실패하면 표시된 작업 파일 경로를 유지한다. CAN·Diag 구간 기록을 0.5.0에 추가했지만 대표 .cfg 현장 시험 전이다. 설정에서 .cfg 선택 → 연결 확인 → 기존 Logging Block 선택 → 전용 CANoe 창에서 측정 시작 → 다시 연결 확인 후 메인 logging으로 시작·정지한다.

0.5.1에서는 CAN+Diag 연결 전 **설정 → CAN·Diag 구성 → CANoe 독립 연결 설정…**을 연다. CANoe의 작업을 보관하고 모든 CANoe 창을 직접 닫은 뒤 **다중 연결 적용**을 누른다. can.ini는 같은 폴더에 백업되고, 다른 COM 도구나 ActiveX/.NET 패널과 충돌하면 같은 화면의 **기본 연결로 복구**를 사용한다. 연결 확인은 전역 설정을 자동 변경하지 않는다. 제공한 두 구성의 독립 연결은 확인했지만 현재 PC의 **View Only** 라이선스로는 측정·기록을 시작할 수 없다.

기록 블록은 실제 이름·파일 형식으로 표시하며, BLF 블록이 하나면 자동 선택한다. PCAPNG 블록은 CAN/Diag용으로 선택할 수 없다. 자동 번호·분할 옵션과 출력 경로는 구간 동안만 적용하고 정지 후 복구한다. 기록 중에는 CANoe의 기존 로깅 버튼이나 파일 설정을 함께 조작하지 않는다. 외부에서 바꾼 설정은 덮어쓰지 않으며, 복구 오류와 마지막 호출은 개발자로그에 남는다. 측정 중 실제 옵션 적용·BLF 기록은 라이선스가 준비된 시험 PC에서 검증해야 한다.

**완료 파일 관리:** 메인 파일명 아래 입력칸에서 직전 파일의 새 이름을 입력하고 **이름 변경**을 누른다. 입력 문자열을 그대로 사용하고 인덱스는 붙이지 않으며 확장자·다음 기록의 prefix 설정은 유지한다. Diag 파일에는 `_Diag`가 붙는다. **직전 로그 지우기** 또는 **파일 관리 → 파일 체크 → 선택 파일 삭제**에서 전체 경로를 확인한다. **영구 삭제**를 누른 경우만 삭제하고 휴지통을 거치지 않는다. 사용 중/누락/외부 변경/닫힘 미확인 파일은 처리하지 않으며, 부분 실패의 실제 경로와 원인은 파일 관리의 작업 이력에서 확인한다. 0.3.x DB는 검증 백업 후 스키마 2로 이행한다.

설치/업데이트 후에는 기존 앱을 메인 **X**로 닫고 새 EXE를 실행한다. X는 진행 중 기록을 정상 정지하고 파일 확인을 마친 뒤 프로그램을 종료한다. 메인과 설정의 버전을 확인한다. Npcap 등 외부 도구는 별도 설치 안내에 따라 준비한 뒤 설정창을 다시 연다. 앱에 설치 링크·설치 실행·다시 찾기 버튼은 없다.

설정은 **저장 설정 / CAN·Diag 구성 / Ethernet 연결** 탭으로 나뉜다. .cfg·TShark·저장 폴더는 선택 직후 자동으로 기억하며, 네트워크는 식별자를 입력하지 않고 이더넷/Wi-Fi 이름으로 선택한다. prefix·다음 인덱스는 **적용**한다. **연결 확인**을 누르면 진행 상태·결과·다음 조치가 같은 카드에 표시된다. **환경 확인**에서도 도구/네트워크별 상태와 설정으로 이동하는 버튼을 사용할 수 있다. CANoe 상세 시험은 [5단계 안내](../docs/development_stage_5.md)를 먼저 따른다. 아래 운용 목표 전체의 현장 검증이 완료된 것은 아니다.

기존 HTML 시안과 모의 앱은 실제 CANoe·Wireshark를 제어하거나 BLF·PCAP를 생성·변경·삭제하지 않는다. 실제 저장용 DB와 모의 DB를 구분한다. 기본 앱의 Zipy 기록은 실제 파일을 만들므로 네트워크와 폴더를 확인한 뒤 시작한다.

아래 전체 취득 환경과 절차는 운용판의 목표 기준이다. 개발 PC에서는 loopback Ethernet 취득과 대표 두 CANoe 구성의 독립 열기·블록 조회를 확인했다. 차량 NIC 취득과 CANoe 측정·실제 BLF 기록은 이번 검증에서 실행하지 않았다. 시험 PC 호환성·차량 통신·장시간 취득 성능은 별도 검증 후 확정한다.

## 2. 시험 PC 실행환경

| 항목 | 준비·확인할 내용 |
| --- | --- |
| 운영체제 | Windows 11 64비트(x64) |
| 통합 프로그램 | 배포받은 실행 파일과 함께 제공된 폴더 전체. EXE만 따로 복사하지 않는다 |
| CANoe | CAN 또는 Diag를 취득할 때 CANoe 19 필요. 실제 에디션·SP·빌드는 배포판의 검증 목록 확인 |
| CAN 장비·드라이버 | 사용하는 Vector VN 장비와 해당 드라이버. 사용자 환경은 VN 장비 연결로 CANoe 라이선스를 인증하므로 장비 연결·인증·측정 가능 상태 확인 |
| Ethernet 캡처 도구 | Zipy를 취득할 때 Wireshark와 TShark·dumpcap·capinfos 필요. 각 실행 파일과 검증된 버전 확인 |
| 캡처 드라이버 | Zipy의 실제 패킷 취득에 Npcap 필요. 설치 후 사용할 NIC를 조회하고 캡처할 수 있는지 확인 |
| Ethernet 연결 | 차량 → 미디어 컨버터 → PC의 취득용 NIC 연결과 해당 NIC 드라이버. 설정에서 실제 취득 대상을 선택 |
| 로그 저장 위치 | 쓰기 가능한 로컬 디스크 폴더. 30분 초과·1GB 초과 로그를 고려해 충분한 여유 공간 확인 |
| CANoe 구성 | 사용할 CAN/Diag의 .cfg 전체 경로와 참조하는 데이터베이스·관련 파일이 읽기 가능한 상태 |

운용판은 Python과 앱 라이브러리를 포함한 폴더로 배포할 예정이다. 시험 PC 사용자가 Python·Git·VS Code·개발 패키지를 별도 설치하는 절차는 없다.

Vector 라이선스 구성 도구와 Microsoft Visual C++ 재배포 패키지는 해당 PC에 필요한 경우에만 준비한다. 이미 정상 동작하는 CANoe·드라이버·Wireshark를 임의로 재설치하거나 업그레이드하지 않는다.

설치 파일·개발 PC용 항목·조건부 설치를 포함한 전체 목록은 [설치 프로그램 안내](../docs/installation_matrix.md)를 참고한다. CPU·메모리·최소 여유 공간의 구체적인 수치와 최대 취득 시간은 실측 후 배포 안내에 명시한다.

## 3. 인터넷 사용 조건

운용판의 준비·캡처·패킷 보기·설정·파일 저장은 인터넷 연결 없이 동작하도록 설계했다. 외부 로그인·자동 전송·자동 업데이트·실행 중 프로그램 다운로드를 사용하지 않는다.

설치 파일을 준비할 때는 인터넷을 사용할 수 있다. 취득할 때는 선택한 차량용 Ethernet 연결과 필요한 VN 장비 연결을 유지한다. 기존 CANoe 라이선스가 해당 PC에서 오프라인으로 동작하는지도 최초 설치 확인에 포함한다.

## 4. 화면의 대상 이름

| 화면 이름 | 실제 대상 | 파일 예시 |
| --- | --- | --- |
| CAN | CANoe 슬롯 1의 기록 | AutoLog_7.blf |
| Diag | CANoe 슬롯 2의 기록 | AutoLog_Diag_7.blf |
| Zipy | Wireshark 계열 도구를 이용한 Ethernet 캡처 | AutoLog_7.pcap 또는 AutoLog_7.pcapng |

메인은 세 대상의 선택·상태와 공통 logging 버튼, 파일명, 알림·로그를 보여준다. 시작 시 CAN·Zipy가 선택되고 Diag는 해제된다. 상단 톱니바퀴의 설정창에서 구성·연결·저장 규칙을 준비한다. `한 | EN | 中` 버튼을 누르면 한국어→영어→중국어로 바뀌고 선택을 기억한다.

**로그 폴더** 버튼은 사용자가 설정한 캡처 저장 폴더를 연다. 개발자로그 체크박스는 없으며 진단 로그는 항상 기록한다.

### 개발자에게 오류 파일 전달하기

개발자로그는 앱 시작부터 항상 EXE 옆 `developer_logs/`에 순환 저장한다. 5MB 파일 하나와 최대 4개 백업을 유지한다. 문제 발생 시 상단 **버그리포트** 버튼을 누르면 바탕화면에 ZIP을 만들고 Taegon.Kim에게 해당 파일을 이메일로 보내 달라는 안내를 표시한다. 발생 시각·선택 대상·조작을 함께 전달한다. 체크박스 조작이나 수동 로그 종료는 필요하지 않다.

앱/도구 버전·확인 범위, 명령/응답·중간 COM 호출 지점·세션/대상/명령 ID·상태·경과시간·오류 원문/traceback을 남긴다. 캡처 payload는 제외하고 자동 전송하지 않는다. 로그 저장 실패는 사용자에게 표시하되 취득 제어를 중단시키지 않는다. 설치·버전·파일 구조 확인을 실제 차량 통신 정상이나 무손실 취득 근거로 해석하지 않는다.

## 5. 최초 실행과 설정 — 운용판 기준

1. 배포 폴더 전체를 로컬에 준비하고 그 안의 앱 실행 파일을 연다.
2. 상단 **톱니바퀴 설정**을 연다.
3. **CAN · Diag 구성**에서 각 카드의 .cfg를 선택하고 해당 **연결 확인**을 누른다. 각각 독립 CANoe 창을 열고 그 구성의 BLF 기록 블록 하나를 선택한다.
4. Zipy는 **Ethernet 연결 → 직접 선택**에서 `tshark.exe`를 지정한다. 네트워크 목록의 수신 그래프와 이름을 보고 NIC를 선택한 뒤 pcap/pcapng 형식과 **연결 확인**을 확인한다. 그래프는 네트워크 전체 수신량이다. 이 조작만으로 캡처가 시작되지는 않는다.
5. **공통 저장 폴더**, **파일 prefix**, **다음 저장 인덱스**를 지정하고 **이름 규칙 저장**을 선택한다.
6. 충돌 파일명·경로 또는 입력 오류가 나타나면 수정한 뒤 적용한다. 충돌한 규칙과 번호는 적용되지 않는다.
7. 열린 CANoe에서 필요한 설정을 확인하고 사용자가 측정을 시작한다. 측정을 유지한 상태에서 패널로 돌아온다.

이미 사용자가 열어 둔 무관한 CANoe 창에는 연결하지 않는다. 통합 프로그램에서 연 창은 직접 조작·설정 수정·저장할 수 있다.

이번 구간의 출력 파일명·저장 위치는 패널이 적용한다. 원본 .cfg에 CAPL·시스템 변수를 자동 추가하거나 원본 파일을 자동 저장하지 않는다. 사용자가 CANoe에서 직접 저장하는 동작은 CANoe의 일반 저장 절차를 따른다.

팀의 다른 PC에서도 같은 배포 폴더를 사용할 수 있지만 .cfg·도구 경로·NIC·저장 폴더는 각 PC에서 확인한다. 번호와 이력은 PC/Windows 사용자별로 보존한다.

## 6. 구간 기록 시작·정지 — 운용판 기준

1. 메인의 CAN·Diag·Zipy 카드에서 이번에 기록할 대상을 체크한다.
2. 파일명·저장 폴더·대상 상태를 확인한다. CANoe 연결과 측정 실행은 각각 확인해야 한다.
3. **logging**을 한 번 누른다. 선택한 대상의 준비를 검사한 뒤 이번 번호를 예약하고 기록을 시작한다.
4. 대상별 실제 로깅 상태와 알림·로그를 확인한다.
5. 종료할 때 **logging**을 다시 누른다. CANoe 측정은 유지하고 이번 구간 기록을 끝낸다.
6. 종료·파일 보관 결과를 확인한다. 종료 중·미완료가 남아 있으면 전체 완료로 해석하지 않는다.

버튼 글자는 시작·정지 모두 logging이며 색·표시와 대상별 상태로 동작을 구분한다. 시작/기록/종료 중에는 대상·형식·번호·폴더를 변경하지 않는다.

파일은 지정 폴더 안의 세션별 임시 위치에 기록하고 종료 확인 후 같은 기본 이름으로 최종 보관한다. 현재 실제 경로와 파일별 상태를 확인할 수 있게 한다. 최종 이름 충돌 시 기존 파일을 덮어쓰지 않고 미완료 경로를 표시한다.

## 7. 파일 이름과 번호

예를 들어 prefix에 VIL, 인덱스가 7이고 세 대상을 선택하면 다음 파일을 만든다.

    AutoLog_7.blf
    AutoLog_Diag_7.blf
    AutoLog_7.pcap

입력 prefix가 이미 `_`로 끝나면 구분자를 중복해 붙이지 않는다.

다음 세션은 인덱스 8을 사용한다. Diag만 선택해도 Diag 구분자는 유지한다. 선택하지 않은 대상의 파일은 만들지 않는다.

다음 저장 인덱스는 기록 종료 후 설정에서 변경할 수 있다. 기존 파일과 겹치면 적용과 시작을 보류한다. 번호 예약 이후 부분 실패한 세션의 번호는 자동 재사용하지 않는다. 파일 이름 변경·삭제는 다음 번호를 자동 되돌리지 않는다.

## 8. 직전 로그 이름 변경·삭제

기록을 종료하고 파일 보관 상태를 확인한 뒤 수행한다.

- **이름 변경:** 메인 파일명 영역의 고정 입력란에 새 기본 이름을 입력하고 **이름 변경**을 선택한다. 입력한 이름 그대로 사용하고 인덱스는 생략하며 확장자는 유지한다. CAN과 Diag를 함께 기록한 세션에서는 이름 충돌을 막기 위해 Diag 파일 끝에 `_Diag`가 붙는다.
- **직전 로그 지우기:** 메인의 해당 버튼으로 대상 전체 파일명·경로를 확인한 뒤 삭제한다. 설정창에서는 개별 파일 선택 삭제를 사용할 수 있다.

예를 들어 직전 세션의 이름을 `주행 기록`으로 변경하면 `주행 기록.blf`, `주행 기록_Diag.blf`, `주행 기록.pcap`이 된다. 다음 저장 번호는 그대로 유지된다.

활성 기록·닫힘 미확인·누락 등 불완전 상태에서는 파일 관리를 보류한다. 일부 작업이 실패하면 파일별 결과와 실제 경로를 확인한다.

## 9. 패킷 보기와 통신 알림 — 운용판 기준

패킷 보기는 별도 상세 창에 최근 1,000건의 수신 시각·출처·목적지·프로토콜·길이를 제공할 예정이다. 표시 필터·화면 일시 정지·창 닫기는 원본 기록과 감시를 중단하지 않는다. 현재 HTML에는 실제 패킷 취득·표시가 구현되지 않았다.

통신 이상 감시는 선택한 대상의 실제 로깅 중에만 동작한다. 로깅 전후와 미선택 대상은 미감시로 표시한다. 소스·주기·미수신 기준은 추후 확정 상태이며 기준이 없으면 설정 필요, 관측하지 못하면 확인 불가로 표시한다.

통신 미수신·출처 불일치 경고 자체로 기록을 자동 정지하지 않는다. 실제 기록 중 한 대상이 중단되면 해당 오류를 알리고 나머지는 계속 기록한다. 공통 logging으로 남은 기록을 종료한다.

## 10. 창 닫기·종료·업데이트 — 운용판 기준

메인 창의 X는 진행 중인 구간을 정지하고 파일 확인을 마친 뒤 프로그램을 종료한다. 설정창에는 별도 프로그램 종료 버튼이 없으며 **닫기**는 설정창만 닫는다. CANoe 측정·창은 자동 종료하지 않는다.

비정상 종료 후에는 이전 세션이 미완료로 표시될 수 있다. **미완료 확인 N건** 또는 **파일 관리 → 미완료 기록 복구**를 연다. 관련 CANoe 기록블록과 TShark 기록이 끝났는지 직접 확인한 뒤 체크한다. CANoe 측정 자체는 유지할 수 있다. 이전 창에 자동 재연결하거나 기록을 자동 재시작하지 않는다.

파일별 전체 경로와 상태를 보고 **검사 후 보관**을 누르면 구조 검사를 통과한 파일을 예약 위치에 보관한다. 사용 중·손상·충돌 파일은 보존한다. **파일 유지하고 미완료 정리**는 세션을 실패 이력으로 남기고 다음 기록을 허용하며 남은 파일과 소비한 번호를 유지한다. 여러 미완료 기록이 있으면 각각 확인해야 한다. 중단된 삭제/이름 변경 결과를 입증할 수 없을 때 **결과 미확인으로 정리**하면 파일을 변경하지 않고 미확인 이력을 남긴다. 현재 앱의 정지가 미확인인 기록은 **현재 기록 정지 재시도**를 먼저 사용한다.

업데이트는 활성/종료/확인 불가 세션이 정리된 뒤 수행한다. 안내된 배포 폴더 전체를 사용하며 기존 설정·번호 DB·로그를 덮어쓰지 않는다.

## 11. 처음 사용하는 PC의 확인 항목

- CANoe 19와 VN 장비가 인증·측정 가능한가.
- 필요한 Wireshark 도구·Npcap이 설치됐고 올바른 NIC를 선택했는가.
- 선택한 .cfg와 실제 열린 구성·기록 대상이 일치하는가.
- 로컬 폴더에 쓰기 가능하고 긴 기록을 위한 공간이 있는가.
- 짧은 실제 구간에서 선택한 모든 파일이 올바른 이름으로 보관되는가.
- 정지 후 CANoe 측정과 다음 번호가 예상대로 유지되는가.
- 인터넷 없이 취득·표시·저장이 되는가.

이 확인은 실제 운용판과 해당 PC 환경으로 수행한다. 현재 시안의 성공 메시지는 설치 확인이나 실제 취득 검증을 대신하지 않는다.

버전·지원 도구 조합·알려진 한계는 운용판 배포 안내에서 확인한다. 상세 설치 목록은 [설치 프로그램 안내](../docs/installation_matrix.md), 현재 확정 범위는 [요구사항](../docs/requirements.md)을 참고한다.
