# 공식 배포용 사용자 가이드

배포 사용자에게 전달하는 문서는 **One Click Log_User_Guide.html**과 **START_HERE.txt**다. `build.cmd`가 현재 소프트웨어 버전·문서 개정일을 반영해 EXE 옆에 만들고 ZIP에도 포함한다. HTML은 별도 프로그램 설치나 인터넷 없이 브라우저에서 읽을 수 있다.

메인 **사용법** 버튼(버그리포트 왼쪽)은 이 HTML을 기본 브라우저로 열며 앱의 현재 언어를 전달한다. 상단 **한국어 / English / 中文**에서 한국어·영어·중국어(간체)로 바꿀 수 있다. 본문·상세 안내·사진·접근성 설명을 함께 전환하며, 직접 열 때는 마지막으로 선택한 언어를 기억한다(브라우저의 로컬 저장을 허용한 경우). 앱에서 열면 앱 언어가 우선이다. 첫 화면은 저장 위치 → CAN·Diag → Zipy → 시작/정지 → 파일 확인의 5단계이며, 설치·오류·검증 상세는 접어 둔다. 사진을 누르면 확대하고 Esc로 닫을 수 있다. 상세 설명 안의 항목으로 링크하면 해당 접힌 영역도 자동으로 열린다. 소스 실행에서는 같은 원본으로 임시 미리보기를 만든다.

번역 원본은 `translations.json`(한국어 원문 대조), `translations.en.json`, `translations.zh.json`이다. HTML의 `data-guide-*` 키와 원문을 함께 관리한다. 원문 변경·미표시 번역·누락·빈 번역·링크/태그/변수 변경·언어별 사진 누락은 빌드를 중단한다. 문장 수정 시 세 언어를 함께 검토하고 개정을 올린다. 저장된 사용자 규칙 이름/팝업 문구는 앱 자체가 자동 번역하지 않으므로 사진에서도 원문을 유지한다.

## 관리 원본

- [사용자 가이드 HTML 원본](AutoLog_User_Guide.template.html)
- [배포 안내문 원본](distribution_notice.template.txt)
- [적용 버전·문서 개정](guide_metadata.json)
- [문서 변경 이력](CHANGELOG.md)
- [화면 사진](images/)과 [재촬영 스크립트](capture_screenshots.py)
- [사진별 안내 문구 번역](annotation_labels.json): Click·입력·선택·확인 옆의 짧은 설명

원본과 사진을 함께 관리한다. UI·연결/설치 조건·보안 허용 앱·기록/파일/복구 절차·알려진 제한이 바뀌면 해당 안내와 이력을 같은 변경에서 갱신한다. 소프트웨어 버전이 바뀌면 실제 적용 여부를 검토한 뒤 `reviewed_app_version`과 문서 개정을 갱신한다. 문서 버전이 맞지 않거나 원본이 누락되면 빌드를 중단한다. 완성 문서를 직접 수정하지 말고 관리 원본을 고친 뒤 다시 빌드한다.

화면이 바뀌면 프로젝트 Python으로 `user_guide/capture_screenshots.py`를 실행한다. 실제 Qt 위젯에 설명용 경로·상태만 넣으며 CANoe·장비·Runtime을 연결하지 않는다. 실제 cfg·캡처·개인 경로를 넣지 않는다. 언어별 14장, 총 PNG 42장과 `images/manifest.json`을 눈으로 확인한 뒤 함께 커밋한다. 스크립트는 실제 위젯 좌표와 사진 크기·해시, 사진 안에서의 조작 순서를 매니페스트에 기록한다. PNG 원본은 그대로 두고 HTML이 빨간 테두리·번호·화살표와 사진 옆의 짧은 안내를 SVG로 표시한다. 번호는 각 사진 안에서 다시 시작하며 Click·입력·선택·확인을 구분한다. 확대 화면에도 같은 표시가 유지된다.

원본 HTML의 `{{IMAGE:파일명.png}}`는 공통 렌더러 `src/vil_logging/documentation.py`가 PNG data URL로 바꾸고 안내 좌표도 HTML에 포함한다. 사용자는 사진 폴더를 따로 복사할 필요가 없다. 사진·안내 누락, 사진 해시·앱 버전 불일치, 범위 밖 좌표·잘못된 순서는 빌드를 중단한다. 렌더 후 세 언어의 데스크톱·작은 화면에서 넘침, 화살표 위치·문구 잘림, 확대/닫기, 접힌 상세 링크를 확인한다. UI가 바뀌면 좌표를 임의로 재사용하지 말고 재촬영한다.

`build_info.json`에는 배포에 포함한 두 문서의 파일명·바이트 수·SHA256과 적용 버전·문서 개정·갱신일을 기록한다. 같은 SW 버전에서 문서만 바뀌면 SW 번호는 유지하고 문서 개정과 빌드 시각으로 구분한다.

기존 `user_guide_draft.md`는 이 안내로 통합했다. `outline.md`와 `performance_notes.md`는 발표/성과 자료이며 배포 사용자 가이드에 포함하지 않는다.

Npcap 설치 파일은 확인된 같은 회사 내부 PC 1대용 빌드(`build.cmd --include-npcap-internal`)에서만 `installers/Npcap`에 포함한다. 일반 빌드는 포함하지 않으며 가이드는 두 경우를 구분한다. 공식 고정 버전·크기/SHA256·서명을 검증하고 설치를 실행하지 않는다. 실제 파일은 Git에 넣지 않는다.
